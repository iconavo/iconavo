# Фаза 3 подробно: пакет для разработчиков

За шесть недель появляется пакет, с которым разработчик пишет одну строку и получает иконку. К концу фазы в npm лежит бета 0.x с веб-компонентом и адаптером React.

Технические решения фазы записаны в ADR-0029…0036, и промпты ниже на них опираются. Продуктовые решения по API ждут вашей отметки там же: [Решения (ADR)](adr/README.md)

## Как устроен пакет

> Схема «устройство пакета · ядро, адаптеры, хосты» — в исходном документе в Claude, сюда она не переносилась.

Пунктир — запасной путь: если основной хост молчит несколько сотен миллисекунд, ядро запрашивает тот же файл со второго.

## Словарь фазы

| Термин | Что это простыми словами |
| --- | --- |
| Пакет | Библиотека, которую разработчик ставит командой npm install |
| API пакета | Набор атрибутов и функций, которыми пользуется разработчик |
| Ядро | Общая часть пакета без привязки к фреймворку: хранит иконки, грузит их, рисует |
| Адаптер | Тонкая обёртка ядра под конкретный фреймворк, например React |
| Веб-компонент | Свой HTML-тег, у Iconavo — `<iconavo-icon>`, который работает в любом фреймворке |
| Shadow DOM | Изолированное содержимое компонента: стили страницы не ломают иконку |
| SSR | Сборка страницы на сервере до отправки в браузер |
| Гидратация | Момент, когда браузер «оживляет» готовую серверную страницу; разметка должна совпасть |
| Пачка запросов | Объединение запросов многих иконок в один |
| Дедупликация | Повторный запрос той же иконки не уходит в сеть |
| Нарастающая задержка | Повторы после сбоя через 1, 2, 4 секунды и так далее |
| Размер в gzip | Вес пакета после сжатия — именно его скачивает пользователь |
| Бета 0.x | Предварительная версия: API ещё может меняться |
| Песочница | Страница для ручных экспериментов с пакетом |

## API как продукт: что решаете вы

Публичное API — это интерфейс для разработчиков, и проектируется он как экран: имена, состояния, ошибки. Здесь ваш опыт дизайнера важнее кода.

Решения, которые принимаете вы:

- Имя тега и компонента. Имя веб-компонента обязано содержать дефис — так требует стандарт; у Iconavo это `<iconavo-icon>` (ADR-0029).
- Как задаётся иконка: `icon="lucide:house"` с разделителем, выбранным в фазе 0. Атрибут `icon`, как у Iconify, — решение владельца 26 октября 2026 (ADR-0031).
- Размер: по умолчанию 1em, то есть иконка растёт вместе с текстом; отдельный атрибут для явного размера.
- Цвет: наследуется от текста; атрибут color — для удобства.
- Повороты и отражения: нужны ли они к запуску или подождут. — К запуску: они есть в превью и коде сайта (ADR-0041), ядро их уже умеет (ADR-0031).
- Подпись для скринридеров: атрибут label; без него иконка считается декоративной.
- Состояние загрузки: скелетон точного размера по умолчанию, спиннер — по выбору разработчика, без сдвигов вёрстки (ADR-0031).
- Состояние ошибки: иконки нет — пустое место и одно понятное предупреждение в консоли разработчика.
- Настройка: `configure` для своих хостов, `addIcons` для офлайна, `setLoader` для своих источников.

Упражнение: напишите пять примеров использования так, как их увидит разработчик в README. Если пример нельзя объяснить одной строкой, API слишком сложное.

## Шаги 1–4: README, ядро, ошибки, рендер

Первые четыре шага дают работающее ядро, которое можно потрогать в песочнице. Песочница — ваш главный инструмент проверки в этой фазе.

### Шаг 1. README до кода, ≈2 дня

Зачем: сначала договор с разработчиками, потом реализация — так меньше переделок.

```
/plan Фаза 3, шаг 1. Помоги написать README пакета до кода: установка, пять примеров (HTML, React, размер и цвет, подпись для скринридеров, свой хост), справка по атрибутам и функциям configure, addIcons, setLoader, loadIcons. Задавай мне вопросы по каждому решению, которого нет в docs/adr/. Код пока не пиши.
```

Как проверить: покажите README одному-двум знакомым разработчикам и спросите, что непонятно.

Готово, когда README одобрен, а решения записаны в ADR.

### Шаг 2. Ядро и песочница, ≈5 дней

Зачем: ядро грузит иконки пачками и не повторяет запросы, а песочница показывает это наглядно.

```
/plan Фаза 3, шаг 2. Сделай ядро пакета по README: реестр иконок в памяти, состояния (загружена, загружается, нет, ошибка), очередь по наборам — все запросы одного тика уходят одним пакетом, дедупликация. Сделай песочницу: страница со 100 иконками и панель журнала сети (сколько запросов, какие адреса, сколько иконок в каждом). Начни с одного хоста.
```

Как проверить в песочнице (`pnpm sandbox`, `http://127.0.0.1:4282`):

- 100 иконок одного набора дают 3–5 сетевых запросов, а не сто: адрес запроса не длиннее 500 символов, как у Iconify (ADR-0030, решение владельца 27 октября 2026). У Lucide — 4 запроса.
- Повторный показ тех же иконок не даёт новых запросов.
- В DevTools на вкладке Network столько же запросов, сколько в журнале песочницы.

Готово, когда цифры в журнале и в DevTools совпадают.

### Шаг 3. Ошибки и запасные хосты, ≈3 дня

Зачем: сбой сети или одного хоста не должен ломать иконки на сайтах ваших пользователей.

```
/plan Фаза 3, шаг 3. Добавь в ядро: отсутствующая иконка запоминается и больше не запрашивается; сетевая ошибка, таймаут и 5xx повторяются с нарастающей задержкой; если основной хост молчит несколько сотен миллисекунд, тот же запрос уходит на второй, побеждает первый ответ. Пачки запрашивай через edge API из ADR-0006, а если он недоступен — бери иконки поштучно со статики. Добавь в песочницу переключатели: «основной хост недоступен», «медленная сеть», «иконки нет».
```

Как проверить самостоятельно:

1. DevTools → Network → правый клик по запросу → Block request domain. Заблокируйте основной хост: иконки должны появиться со второго.
2. Там же включите троттлинг Slow 4G: иконки появляются, страница не прыгает.
3. Укажите несуществующую иконку: пустое место нужного размера и одно предупреждение в консоли. Заблокируйте адреса edge API: иконки должны догрузиться поштучно со статики.

Готово, когда все три сценария отрабатывают без сломанной вёрстки.

### Шаг 4. Рендер, ≈3 дня

Зачем: иконка должна выглядеть одинаково в любом размере, повороте и количестве на странице и быть доступной для скринридеров.

```
/plan Фаза 3, шаг 4. Сделай рендер иконки: viewBox с учётом поворотов (при 90° и 270° стороны меняются местами) и отражений, размер по умолчанию 1em, вторая сторона по пропорции, уникальные ID масок при повторе иконки на странице. По умолчанию aria-hidden="true"; при label — role="img" и aria-label, без title (ADR-0031). Добавь в песочницу сетку вариантов: размеры, повороты, отражения, цвета, одна иконка с маской дважды.
```

Как проверить (`pnpm sandbox`, страница `http://127.0.0.1:4282/render`):

- Сетка вариантов совпадает с ожиданием, повёрнутые иконки не обрезаны.
- Две одинаковые иконки с маской или градиентом выглядят одинаково. Масок в каталоге нет — маска у своей иконки песочницы.
- Экранный диктор Windows (Win+Ctrl+Enter; вместо VoiceOver — решение владельца 27 октября 2026): иконку с подписью он произносит, без подписи — пропускает.

Готово, когда вы как дизайнер приняли сетку вариантов.

## Шаги 5–9: веб-компонент, быстрые пачки, React, размер, тесты

Эти шаги превращают ядро в продукт для разработчиков: готовые обёртки, быстрая загрузка, контроль веса и автоматические проверки.

### Шаг 5. Веб-компонент, ≈3 дня

Зачем: один тег, который работает в любом фреймворке и на обычной HTML-странице.

```
/plan Фаза 3, шаг 5. Сделай веб-компонент на ядре: защита от двойной регистрации (проверка customElements.get), shadow DOM, ленивый рендер через IntersectionObserver, резерв места 1em × 1em до загрузки. Добавь в песочницу страницу с 5000 иконок.
```

Как проверить (`pnpm sandbox`, страницы `http://127.0.0.1:4282/many` и `/tag`):

- Страница с 5000 иконок прокручивается плавно.
- При загрузке текст рядом с иконками не прыгает.
- Иконка перекрашивается, когда меняется цвет текста вокруг.
- На странице «Тег» вы утверждаете вид скелетона и спиннера; подпись проверяется Экранным диктором, как в шаге 4.
- Safari на Windows нет — его заменяет WebKit, движок Safari (решение владельца 27 октября 2026, ADR-0035). Окно браузера для ручной проверки — `pnpm sandbox --browser=webkit` или `--browser=firefox`. Автопроверка в Chrome, Firefox и WebKit — `pnpm sandbox --check`, отчёт со снимками — `.cache/reports/sandbox/check.html`.

Готово, когда всё это работает в Chrome, Safari и Firefox.

### Шаг 6. Быстрые пачки и порог перехода на статику, ≈2 дня

Зачем: пачка, которой ещё нет в кэше edge API, отвечает 0,7–1,2 с — дольше порога ядра 750 мс. Тогда ядро тянет те же иконки по одной со статики: на странице 5000 иконок с живыми хостами первые 216 иконок дали 213 запросов. Сайт фазы 4 показывает тысячи разных иконок — ровно такой случай. Находка шага 5; порядок — решение владельца 27 октября 2026 (ADR-0030).

```
/plan Фаза 3, шаг 6. Ускорь пачки edge API, которых ещё нет в кэше: функция держит прочитанные файлы иконок в кэше дата-центра и собирает новую пачку из знакомых иконок без похода в R2; проверь ограничения бесплатного тарифа Workers. Замерь пачки без кэша до и после — с моего компьютера и из CI. Затем по замеру задай в ядре отдельный порог перехода с API на статику (около 1,5 с вместо 750 мс; ADR-0030). Цифры и варианты — в бэклоге, пункт «Всплеск запросов статики на медленной сети».
```

Как проверить:

- Замер `pnpm api bench --batches` (из CI — ручной запуск «Edge API» с «замер пачек»): пачка из 30 имён, которой нет в кэше, с вашего компьютера укладывается в порог перехода на статику. Протокол и правило выбора порога — в ADR-0030.
- `pnpm sandbox` → `http://127.0.0.1:4282/many` с живыми хостами: «пачек к API» — примерно иконки / 30, а «по одной к статике» почти не растёт.
- `pnpm sandbox --check` по-прежнему зелёный.

Готово, когда страница 5000 иконок с живыми хостами грузится пачками, без всплеска запросов статики.

### Шаг 7. React и Next.js с SSR, ≈3 дня

Зачем: React — самый частый фреймворк у ваших будущих пользователей, а Next.js проверяет работу с серверным рендером.

```
/plan Фаза 3, шаг 7. Сделай адаптер React на ядре и пример приложения на Next.js с серверным рендером. Иконки, известные заранее, должны попадать в серверную разметку без мигания; остальные — догружаться на клиенте. В консоли браузера не должно быть предупреждений о гидратации.
```

После выполнения Claude сам запускает пример и проверяет его в браузерах: `pnpm example --check` — Chrome, Firefox и WebKit, режим разработки и продакшен-сборка, отчёт со снимками `.cache/reports/example/check.html`.

Как проверить самостоятельно (`pnpm example`, `http://127.0.0.1:4283`):

- DevTools → Console — ни одного предупреждения о гидратации. Предупреждения есть только про две иконки, которых нарочно нет, внизу страницы.
- DevTools → Network → Slow 4G, обновить страницу: иконки раздела «From the server» на месте сразу, остальные — сначала пустое место нужного размера, потом иконка.
- То же в продакшен-сборке: `pnpm example --prod`.

Готово, когда пример работает и в режиме разработки, и в продакшен-сборке.

### Шаг 8. Бюджет размера, ≈1 день

Зачем: ядро загружается на каждой странице пользователя, поэтому каждый лишний килобайт бьёт по скорости чужих сайтов.

```
/plan Фаза 3, шаг 8. Подключи size-limit: ядро и каждый адаптер с лимитом в килобайтах после gzip (для ядра — 5 КБ). CI должен падать при превышении. Покажи текущие размеры таблицей.
```

Как проверить: попросите Claude временно добавить в ядро что-то тяжёлое — проверка в CI должна упасть.

Готово, когда CI показывает размеры, а превышение роняет проверку.

### Шаг 9. Тесты, ≈3 дня

Зачем: тесты ловят поломки раньше пользователей и позволяют Claude менять код без страха.

```
/plan Фаза 3, шаг 9. Добавь тесты: модульные на Vitest для ядра (очередь, дедупликация, ошибки, запасные хосты), браузерные на Playwright в Chrome, Firefox и WebKit, визуальное сравнение иконок пакета с исходными SVG из фазы 1, тест SSR для примера Next.js. Итог — отчёт простыми словами: что проверено и что нет.
```

Как проверить: CI зелёный; попросите Claude специально сломать одну функцию — тесты должны упасть.

Готово, когда отчёт покрывает все обещания из README.

## Проверка готовности фазы

Фаза закрыта, когда все пункты — «да», проверенные вами в песочнице и примерах.

- [x] README одобрен, все решения по API записаны в ADR. Одобрен владельцем 26 октября 2026: `packages/icon/README.md`, решения — в ADR-0029…0034, 0036, 0042, 0025.
- [x] 100 иконок одного набора дают 3–5 запросов, повторные показы не уходят в сеть. Принято владельцем 27 октября 2026 (PR #58): в песочнице `pnpm sandbox` 100 иконок Lucide — 4 запроса, повторный показ — ни одного, «все пять» — по запросу на набор; журнал песочницы и Network в DevTools совпадают.
- [x] Отказ основного хоста, медленная сеть и отсутствующая иконка отрабатывают корректно. Принято владельцем 27 октября 2026 (PR #62). В песочнице `pnpm sandbox`:
  - «Основной хост недоступен» — иконки по одной со статики;
  - «Медленная сеть» — серые клетки, побеждает первый ответ;
  - «Ничего не отвечает» — повторы через 1, 2 и 4 с, затем рамка «ошибки»;
  - иконки, которых нет, — пустое место и одно предупреждение в консоли.
- [x] Сетка вариантов рендера принята, Экранный диктор ведёт себя правильно. Принято владельцем 27 октября 2026 (PR #65). В песочнице `pnpm sandbox`, страница `/render`:
  - размеры, повороты, отражения и повороты в данных совпадают с подписями, повёрнутые иконки не обрезаны;
  - одинаковые иконки с маской и градиентами выглядят одинаково, ID у копий разные;
  - Экранный диктор называет кнопку-иконку «Удалить» и пропускает декоративные иконки.
- [x] Веб-компонент работает в Chrome, Safari и Firefox, страница с 5000 иконок не тормозит. Принято владельцем 27 октября 2026 (PR #67). Safari на Windows заменяет WebKit — его движок (решение владельца, ADR-0035):
  - `pnpm sandbox --check` — все проверки «да» в Chrome, Firefox и WebKit: две копии на странице, стили и Trusted Types при строгой CSP, заглушки, рамка, перекраска, место до загрузки, ленивая загрузка;
  - вручную в Chrome, Firefox и WebKit — 5000 иконок прокручиваются плавно, текст рядом не прыгает, иконки перекрашиваются вместе с текстом;
  - вид заглушек утверждён: по умолчанию — скелетон; Экранный диктор называет обе кнопки «Delete».
- [x] Пачка без кэша укладывается в порог перехода на статику, страница 5000 иконок с живыми хостами грузится пачками. Принято владельцем 28 октября 2026 (PR #70, #71):
  - кэш файлов иконок в функции edge API: знакомые иконки в новой пачке — P50 118 мс с компьютера владельца (было 403) и 43 мс из США (было 907);
