# Фаза 4 подробно: сайт MVP и MCP-сервер

За девять недель появляется то, что увидят люди: сайт-каталог со смысловым поиском и MCP-сервер, через который ИИ-ассистенты находят и вставляют иконки. Интерфейс собирается как рабочий прототип на дизайн-токенах, а ваш визуальный дизайн накладывается позже, в фазе 6.

Сайт уже начат в шаге 10 фазы 3 (ADR-0050): `apps/site` на Next.js, адрес `iconavo.dev`, главная и документация `/docs`. Там уже есть:

- токены и Tailwind CSS 4, светлая и тёмная темы по настройке системы;
- строгая CSP и метка noindex до запуска;
- выкладка — workflow «Сайт» при каждом слиянии в `main`;
- проверки — `pnpm site --check` в трёх браузерах на каждом PR и `pnpm site --live` после выкладки.

Фаза 4 достраивает этот сайт, а не начинает новый.

## Что будет в конце и ваша роль

В конце фазы:

- Сайт на `iconavo.dev`: главная с поиском, каталог наборов, страницы наборов и иконок, генератор кода, экспорт и «сумка». До запуска он по-прежнему скрыт от поисковиков (ADR-0050).
- Поиск понимает смысл и два языка, а его качество подтверждено замером на эталоне.
- MCP-сервер на `mcp.iconavo.dev`: Claude, ChatGPT, Cursor и Claude Code находят иконки и вставляют код. В клиентах с поддержкой MCP Apps иконку можно выбрать из сетки прямо в чате.

Ваша роль:

- Продуктовые решения фазы уже приняты — они в [Решениях (ADR)](adr/README.md), раздел «Продуктовые решения фазы 4». Не хватает одного: назвать одну-две фичи-отличия до шага 9.
- После каждого шага — короткая приёмка: пройти сценарий руками и сказать, что неудобно. Вы проверяете поведение, а не внешний вид: визуал будет в фазе 6.
- Где смотреть: до слияния — у себя, `pnpm site` → `http://127.0.0.1:4284`; после слияния — `iconavo.dev`. Превью PR у Vercel нет: сайт выкладывается только из `main` (ADR-0050).
- Новые зависимости — только с вашего согласия. В этой фазе их будет несколько, например shadcn/ui с Radix, Storybook, SDK MCP и MCP Apps; Claude спрашивает о каждой в плане шага.

## Словарь фазы

| Термин | Что это простыми словами |
| --- | --- |
| Прототип на токенах | Рабочий интерфейс без вашего визуального дизайна: цвета, шрифты и отступы заданы токенами, их значения заменят в фазе 6 |
| Дизайн-токен | Именованное значение дизайна — цвет, шрифт, отступ, радиус; в коде называется так же, как переменная в Figma |
| shadcn/ui и Radix | Готовые элементы интерфейса — меню, диалоги, переключатели, — доступные с клавиатуры и для скринридеров; вид берут от токенов |
| Storybook | Витрина компонентов: каждый элемент интерфейса во всех состояниях, без запуска всего сайта |
| Кэш страниц | Готовая страница, которую сервер собрал при первом открытии и дальше отдаёт без пересборки |
| noindex | Метка «не показывать в поисковиках»; стоит на сайте до запуска |
| Карта сайта | Список всех адресов сайта для поисковиков |
| Канонический адрес | Главный адрес страницы, если она открывается по нескольким |
| hreflang | Пометка для поисковиков: у страницы есть версия на другом языке |
| Картинка для соцсетей (OG) | Картинка карточки, которая появляется, когда ссылку присылают в мессенджер или соцсеть |
| Lighthouse и LCP | Проверка скорости и качества страницы от Google, оценки до 100; LCP — время, за которое появляется главное на экране |
| Эталон | 200 запросов с подходящими иконками для замера поиска: по рабочей части поиск настраивают, по контрольной только меряют |
| Строгий Hit@5 | Доля всех запросов эталона, у которых подходящая иконка есть в первой пятёрке; запрос без подходящей иконки — промах |
| Лимит частоты | Сколько запросов в минуту принимается с одного адреса; сверх лимита — ответ 429 «слишком много запросов» |
| Успех поиска | Поиск, который закончился копированием кода или скачиванием, — главная метрика продукта |
| Сумка | Список выбранных иконок, которые скачиваются одним архивом или спрайтом |
| SVG-спрайт | Один файл со многими иконками, из которого страница берёт нужную по имени |
| MCP | Протокол, по которому ИИ-ассистент вызывает внешние инструменты, например поиск иконок |
| MCP Apps | Расширение MCP: инструмент показывает свой интерфейс прямо в чате, например сетку иконок |
| MCP Inspector | Программа для проверки MCP-сервера без ассистента: вызвать инструмент и посмотреть ответ |

## Шаги 1–3: каркас, каталог, поиск

### Шаг 1. Каркас сайта, ≈4 дня

Зачем: основа для всех страниц — языки, темы, дизайн-токены и компоненты.

```
/plan Фаза 4, шаг 1. Сайт уже есть — apps/site (ADR-0050): главная, /docs, токены в app/globals.css, Tailwind CSS 4, темы по системе, выкладка из CI. Сделай из него каркас каталога по ADR-0037 и ADR-0038: общая шапка с полем поиска и навигацией; языки — английский на /, русский на /ru; переключатели языка и темы, тема по умолчанию — как в системе. Компоненты — shadcn/ui на Radix, витрина — Storybook; сначала спроси моего согласия на эти зависимости. Никаких цветов и отступов прямо в страницах, только токены: тест lib/tokens.test.ts остаётся зелёным. Иконки самого сайта — через @iconavo-ui/react. Предложи, как быть с двумя пунктами бэклога: файл стилей React для серверного HTML и /ru/docs. Расширь pnpm site --check на новые страницы.
```

Как проверить:

- `pnpm site` → `http://127.0.0.1:4284`: переключение языка и темы работает, `/ru` открывает русскую версию.
- В Storybook видны базовые компоненты в обеих темах.
- Попросите Claude поменять один токен цвета: если меняется весь сайт, редизайн в фазе 6 будет простым.
- `pnpm site --check` — «да» в Chrome, Firefox и WebKit; в CI это обязательная проверка.

Готово, когда каркас открывается на `iconavo.dev` на обоих языках и в обеих темах.

### Шаг 2. Каталог и страницы наборов, ≈3 дня

Зачем: человек видит, какие наборы есть, и открывает любой из них.

```
/plan Фаза 4, шаг 2. По ADR-0037 сделай главную, каталог /sets, страницу набора /{префикс}, ленту «Что нового» /changelog (ADR-0018) и страницу /licenses. На странице набора — сетка иконок с пагинацией, категории автора, лицензия и автор набора, шесть образцов для витрины (ADR-0017); скрытых иконок в каталоге нет. Данных о наборах на раздаче нет: info.json, metadata.json, search.json и changelog.json лежат только в data/ (ADR-0022). Сделай в edge API адреса /collections, /collection и /last-modified (ADR-0004, ADR-0024) — они же нужны MCP — или предложи другой путь и объясни. Страницы создаются при первом запросе и кэшируются (ADR-0039); предложи, как сайт узнаёт о новом выпуске набора. Из бэклога: спроси меня, нужна ли в ленте запись о смене лицензии; у пакетов данных в npm — homepage на страницу набора и ссылка на ленту в README.
```

Как проверить:

- Откройте каждый из пяти наборов: иконки видны, лицензия и автор указаны.
- Категории фильтруют сетку, пагинация работает. У Material Symbols категорий автора нет (ADR-0017) — только сетка.
- В «Что нового» видны последние выпуски наборов, например Lucide 1.65.0.

Готово, когда все наборы открываются и листаются без ошибок.

### Шаг 3. Поиск, ≈5 дней

Зачем: это главная фича продукта.

```
/plan Фаза 4, шаг 3. Сделай поиск по ADR-0040 и ADR-0049: поле на главной и страница /search, запрос по мере ввода с паузой 150 мс к api.iconavo.dev/search, точное совпадение имени первым, группировка вариантов с переключателем стиля; порядок вариантов — свой, не по ключам suffixes (бэклог). Ответ с semantic: "pending" — это выдача по словам: покажи её сразу, а полную выдачу, которая досчитывается в фоне, — повтором запроса, без прыжков вёрстки. Фильтры: набор, цветность, лицензия, заметный фильтр «можно в коммерческих проектах» и стиль. Общей шкалы стилей у наборов нет (ADR-0049): предложи её, запиши ADR и добавь в индекс. Фильтры попадают в адрес страницы. Пагинация — до 96 иконок на странице, API отдаёт первые 1000 результатов. Лимит — 60 поисков в минуту с адреса (ADR-0049): если сайт ищет и со своего сервера, нужен ключ или обход (бэклог); на ответ 429 — понятное сообщение. Если ничего не найдено — ближайшие по смыслу иконки и подсказка. При загрузке — скелетон (ADR-0031).
```

Сейчас все пять наборов разрешают коммерческое использование: конвейер принимает только MIT, ISC и Apache-2.0 (ADR-0017). Фильтр «можно в коммерческих проектах» на нынешнем каталоге ничего не отсеет — как его показать, обсудим в плане шага.

Как проверить:

- Задайте 20 своих запросов на русском и английском, включая разговорные: «мусорка», «домик». Известные слабые места — «корзинка» и абстракции вроде «успеха» (бэклог); их доводит шаг 8.
- Ссылка с фильтрами открывает тот же результат в другом браузере.
- Запрос с опечаткой всё равно находит нужное.

Готово, когда выдача появляется не позже 0,3 с после паузы в наборе для 95% поисков (ADR-0040), а на ваших запросах выглядит разумной.

## Шаги 4–5: страница иконки, код и экспорт

### Шаг 4. Страница иконки, ≈4 дня

Зачем: здесь человек принимает решение и забирает результат, поэтому всё нужное должно быть на одном экране.

```
/plan Фаза 4, шаг 4. Сделай страницу иконки /{префикс}/{иконка} по ADR-0041: большое превью на светлом и тёмном фоне, переключатель вариантов стиля, настройки — размер, цвет (только для монохромных), толщина линии, поворот и отражение. Превью — компонент Icon пакета, настройки — его пропсы (ADR-0042). Пометки «линии сохранены как линии» в данных пока нет: линии есть только у Lucide и Tabler, и то не у залитых вариантов Tabler — предложи, как её получить. Блок автора и лицензии с готовым текстом указания авторства; у иконок Lucide, пришедших из Feather, — ещё и Feather (бэклог). Описание, теги и синонимы — из search.json, тем же путём данных, что в шаге 2. «Похожие иконки» — по векторам поискового сервиса (ADR-0049): локальные векторы .cache/embeddings сайту недоступны (ADR-0047). Алиасы перенаправляют на основной адрес, скрытые иконки показываются с пометкой «устарела» (ADR-0037).
```

Как проверить:

- Меняйте размер, цвет и поворот: превью обновляется сразу.
- Толщина линии есть у Lucide и Tabler и отсутствует у Material Symbols, Phosphor, Fluent Emoji и залитых иконок Tabler.
- «Похожие иконки» действительно похожи по смыслу.
- Старое имя `lucide:home` открывает страницу `lucide:house`.

Готово, когда со страницы иконки понятно всё нужное без лишних переходов.

Зачем: человек забирает иконку в том виде, который нужен его проекту, за один клик.

```
/plan Фаза 4, шаг 5. По ADR-0042 добавь на страницу иконки генератор кода: веб-компонент <iconavo-icon>, React из @iconavo-ui/react, SVG с выбранными настройками, CSS и ссылка на SVG через api.iconavo.dev. Команды установки — для npm, pnpm и yarn, выбор запоминается; тег @next в них не нужен: latest идёт за каждой бетой (ADR-0051). Строки подключения бери из README пакета, как документация (ADR-0050): у скрипта без сборщика — хэш integrity, его обновляет pnpm release bump (ADR-0051). Толщины линии среди параметров SVG в edge API нет — добавь её функцией ядра setStrokeWidth (бэклог). Экспорт: SVG и PNG от 16 до 512 px, PNG рисуется в браузере. Мультивыбор: иконки собираются в «сумку», из неё — ZIP или SVG-спрайт, в архив кладутся тексты лицензий. Места событий аналитики — копирование и скачивание — отметь, подключение в шаге 7 (ADR-0043).
```

Готово, когда любой вариант кода работает с первого раза.

## Шаги 6–8: SEO, аналитика, качество поиска

### Шаг 6. SEO и скорость, ≈3 дня

Зачем: страницы иконок приводят людей из поисковиков, а скорость — часть качества. До запуска сайт скрыт от поисковиков (ADR-0050), поэтому здесь готовится всё, кроме самого открытия: снять метку noindex, сделать карту сайта и канонические адреса — работа фазы 7 (ADR-0039).

```
/plan Фаза 4, шаг 6. По ADR-0039: заголовки и описания страниц из обогащения, картинки для соцсетей, hreflang для русской и английской версий; страницы поиска не индексируются. Метку noindex, карты сайта и канонические адреса не трогай — это фаза 7, вместе с открытием сайта. Замерь Lighthouse на главной, на странице набора и на странице иконки и доведи до 90+, LCP — не больше 2,5 с.
```

Как проверить:

- Вставьте ссылку на иконку в Telegram или Slack: появляется карточка с картинкой.
- Отчёт Lighthouse показывает 90+ на трёх страницах.
- `pnpm site --live`: метка noindex по-прежнему на месте.

Готово, когда Lighthouse 90+ на трёх страницах, а ссылка на иконку показывает карточку с картинкой.

### Шаг 7. Аналитика, ≈1 день

Зачем: главную метрику продукта — успех поиска — нужно видеть с первого дня.

```
/plan Фаза 4, шаг 7. Подключи аналитику без cookie по ADR-0043, мой сервис — [Plausible или Umami]. События: поиск (текст запроса обезличенно, число результатов, фильтры), копирование кода, скачивание, переключение стиля, переход к похожим иконкам. Адрес сервиса добавь в CSP сайта (lib/headers.ts). Посчитай метрику «успех поиска» и собери еженедельный отчёт о запросах без результатов и без кликов.
```

Как проверить: сделайте три поиска и одно копирование — события появились в панели аналитики. До беты в панели почти только ваши визиты: сайт скрыт от поисковиков.

Готово, когда «успех поиска» виден в панели аналитики.

### Шаг 8. Качество поиска, ≈3 дня

Зачем: довести поиск до цели — строгий Hit@5 не ниже 90% отдельно на русских и на английских запросах (ADR-0021). Строгий — значит по всем 200 запросам эталона, и запрос, для которого подходящей иконки нет, считается промахом. Сейчас у сервиса 83% и 88% (ADR-0049).

```
/plan Фаза 4, шаг 8. Замерь сервис по эталону (ADR-0021): pnpm eval --service, неразмеченные пары — pnpm judge --service, сумма разметки — с моего согласия. Покажи строгий Hit@5 и MRR@10 отдельно для русского и английского и «потолок» — запросы, для которых подходящей иконки нет ни в одном варианте. Настраивай только по рабочей части эталона — долю смысла SEMANTIC_RATIO, веса полей, обогащение, — а контрольную часть только мерь (ADR-0021, ADR-0048). Покажи 20 худших запросов рабочей части с выдачей и предложи, как их исправить. Из бэклога: разговорные слова и абстракции, Material Symbols лишний раз в пятёрке, типы задачи Gemini «запрос» и «документ» с ключом Google напрямую, замер с фильтром по каждому набору (около 1 885 новых пар, ≈80 ₽). Новый промпт обогащения или смена эмбеддера — сначала оценка стоимости.
```

Как проверить:

- Строгий Hit@5 — не ниже 90% и на русских, и на английских запросах; на контрольной части — не хуже, чем было.
- Разбор худших запросов понятен, а правки не ухудшают остальные.

Готово, когда цель достигнута на обоих языках.

## Шаги 10–12: MCP-сервер и выбор иконки в чате

### Шаг 10. MCP-сервер, ≈4 дня

Зачем: ИИ-ассистенты получают иконки так же надёжно, как сайт, но в удобном для себя виде.

```
/plan Фаза 4, шаг 10. Сделай MCP-сервер по ADR-0011 и ADR-0044: официальный TypeScript SDK, Streamable HTTP на mcp.iconavo.dev, Cloudflare Workers рядом с edge API. Код — в apps/mcp, выкладка только из CI, как у edge API (ADR-0024); разовую настройку панели Cloudflare для меня запиши дословно. Инструменты: search_icons (поиск по смыслу с фильтрами; в ответе имена, лицензии и одна картинка-сетка с превью), get_icon (по умолчанию — код с @iconavo-ui, веб-компонент или React; чистый SVG — по запросу ассистента; размер, цвет, толщина линии, поворот), get_matching_set, get_usage (установка и подключение пакета), list_sets (данные наборов — адреса edge API из шага 2). Vue нет: адаптер Vue — после запуска; поправь ADR-0011 (бэклог). Точные описания и схемы ответов, лицензия и автор в каждом ответе. Лимиты для людей — по ADR-0044. К поиску сервер ходит с одного адреса, а там лимит 60 запросов в минуту (ADR-0049): нужен ключ или обход (бэклог). Бесплатный тариф Workers — 10 мс процессора на запрос и 100 000 запросов в сутки (ADR-0024): первым делом проверь, успевает ли функция нарисовать картинку-сетку. Проверь сервер в MCP Inspector и покажи мне результат каждого инструмента.
```

Как проверить:

- В MCP Inspector все пять инструментов отвечают без ошибок.
- Ответ search\_icons содержит картинку-превью и лицензии.

Готово, когда все инструменты отвечают в Inspector.

### Шаг 11. Выбор иконки в чате, ≈3 дня

Клик возвращает выбор ассистенту. Где MCP Apps не поддерживаются — обычный ответ с картинкой-превью. Стили — из дизайн-токенов сайта. Используй навыки create-mcp-app и add-app-to-server.

Как проверить:

Готово, когда выбор в чате работает хотя бы в Claude и ChatGPT.

## Если что-то пошло не так

| Что видите | Почему так бывает | Что делать |
| --- | --- | --- |
| Поиск находит не то на русском | Мало синонимов или низкая доля смысловой части | Шаг 8: разбор худших запросов рабочей части, доработка обогащения или весов |
| Поиск отвечает медленно | Вектора запроса ещё нет — первый ответ только по словам (`pending`), или запрос из дальнего региона | Замер `/search` по частям — `pnpm api bench` (ADR-0049); полная выдача досчитывается в фоне и приходит на повтор |
| Поиск отвечает ошибкой 429 | Лимит 60 поисков в минуту с адреса (ADR-0049) | Понятное сообщение на сайте; серверу сайта и MCP — ключ или обход (шаги 3 и 10) |
| Иконки на сайте мигают | Иконки нет в серверном HTML или нет резерва места | Иконки первого экрана — через `loadIcons` и `IconavoProvider` (ADR-0033); резерв 1em и скелетон (ADR-0031) |
| Ошибка гидратации в консоли | Сервер и браузер рисуют разное | Одинаковая заглушка на сервере и в браузере (ADR-0033) |
| После выпуска набора на сайте старые данные | Кэш страниц набора не сбросился | Проверить, как сайт узнаёт о новом выпуске (шаг 2, ADR-0039) |
| `pnpm site --check` красный после новой страницы | Проверка ждёт прежние страницы, ссылки или заголовки | Открыть отчёт `.cache/reports/site/check.html` и поправить страницу или ожидания проверки |
| Lighthouse ниже 90 | Тяжёлые картинки или лишний JavaScript | Попросить Claude показать главные причины в отчёте и исправлять по одной |
| Ассистент выбирает не те иконки | Нечёткие описания инструментов | Шаг 12: переписать описания и добавить примеры в схему |
| Сетка не появляется в чате | Клиент не поддерживает MCP Apps или ошибка в ресурсе | Проверить в MCP Inspector и в другом клиенте; без поддержки остаётся ответ с превью |
| Claude «наломал», и сайт сломан | Слишком большой шаг | Откатить через `/rewind` или вернуть ветку, затем разбить шаг на части; на живом сайте — откат PR, «Сайт» выложит прежнюю версию |
| Заканчивается контекст | Длинная сессия | `/compact` или новая сессия: CLAUDE.md и `docs/` вернут контекст |
