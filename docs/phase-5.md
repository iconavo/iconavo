## Шаг 1. Ревизии кода

Зачем: перед тем как звать людей, весь код проверен на ошибки и уязвимости. Перенесено из шага 13 фазы 4 решением владельца 23 ноября 2026.

### Как устроено

- **Команды проверяют только изменения ветки.** `/security-review` берёт `git diff origin/HEAD...` и прямо велит не трогать существующие проблемы; `/code-review` по умолчанию — `git diff origin/HEAD...HEAD`. Чтобы проверить готовый код, часть делается «добавленной заново».
- **Скрипт `tools/review.mjs`** (без зависимостей):
  - `node tools/review.mjs list` — части, файлы, строки;
  - `node tools/review.mjs prepare <часть>` — временная ветка `review/<часть>`: основа — `main` без исходников части, поверх — коммит с деревом `main`. Тесты остаются в основе: в проверку не попадают, но читаются. Рабочая папка не меняется, `origin/HEAD` временно указывает на основу. Ветку не отправлять;
  - `node tools/review.mjs done` — вернуть `main` и `origin/HEAD`, удалить временное;
  - файлы, которые git считает двоичными, скрипт называет: ревизии читают их целиком.
- **Порядок на часть:** `prepare` → `/code-review high --max-findings all` (у частей 15–19 — `medium`) → для частей с безопасностью — `/security-review` → проверка каждой находки по коду → `done`.
- **`--max-findings all` запоминается** до `--max-findings default`. После серии ревизий вернуть `default`.
- **Уровень рассуждений решает цену.** Агенты ревизии наследуют уровень сессии. В общих настройках владельца `CLAUDE_CODE_EFFORT_LEVEL: max` — он главнее `/model` и `/effort`. Для проекта уровень ограничен файлом `.claude/settings.local.json` с `"maxEffortLevel": "high"` (в git не попадает, действует без перезапуска). Замер 24 ноября 2026:
  - Fable 5.2 на `max` — 35 минут на часть 1 и 1,28 млн токенов ответа, не закончил;
  - Opus 5.5 на `high` — все 19 частей за ≈2,5 часа, 627 тыс. токенов ответа;
  - любой агент сначала загружает весь контекст проекта — около 133 тыс. токенов, больше всего весит `CLAUDE.md` (247 КБ).

### Исправления — порядок

Один PR на группу, с тестами; мелочи — в том же PR, если они рядом с важным; остальное — отдельным PR или в бэклог, по решению владельца. Группы и номера — в `docs/phase-5-review.md`.

1. **Сайт** (С) — то, что видят люди; владелец проверяет глазами на `pnpm site`.
2. **Робот обновления и CI** (Р) — от них зависит, доходят ли обновления.
3. **Данные и поиск** (Д) — очистка, кэш источников, модель векторов.
4. **Пакеты** (П) — затем выпуск 0.1.2 (`pnpm release bump 0.1.2`).
5. **API, MCP, раздача, npm** (А).
6. **Обогащение и проверки** (И) — до переноса обогащения в CI.
7. **Укрепление безопасности** (Б) — часть делает владелец в настройках GitHub.

Перед исправлениями нужны решения владельца — раздел «Ждут решения» в `docs/phase-5-review.md`.

Промпт для новой сессии:

```
Фаза 5, шаг 1: исправления по ревизии. Прочитай docs/phase-5.md и docs/phase-5-review.md. Начни с группы «Сайт» (С): сначала план PR, затем исправления с тестами, pnpm check и pnpm site --check. Каждую находку перед исправлением ещё раз проверь по коду: строки могли сдвинуться.
```

Готово, когда каждая находка исправлена или владелец отложил её в бэклог, а в `docs/phase-5-review.md` у неё стоит отметка.
