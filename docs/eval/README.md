# Эталон поиска

`queries.csv` — набор запросов для замера качества поиска (ADR-0021). Главная метрика — Hit@5, вспомогательные — MRR@10 и P@5. Как размечен эталон и как идёт замер — ADR-0048.

## Как получен

- Сгенерирован моделью `google/gemini-3.8-flash` через Polza AI, не Claude: так эталон не подыгрывает обогащению (ADR-0021).
- 200 запросов: по 100 на русском и английском, по 20 на каждый из пяти типов в каждом языке (предметы, действия, абстракции, интерфейсные термины, разговорные).
- Модель писала запросы по сценариям реальных задач, а не по списку существующих иконок.
- Дата генерации: 17 октября 2026. Скрипт: `tools/eval/generate-queries.mjs`.

## Колонки

| Колонка | Что это |
| --- | --- |
| `id` | Номер запроса внутри языка, например `ru-006` |
| `query` | Поисковый запрос |
| `lang` | `ru` или `en` |
| `type` | `object`, `action`, `abstract`, `ui`, `casual` |
| `expected_description` | Какую иконку ожидает человек, словами (по-русски) |
| `split` | `work` — по ней настраивают поиск; `holdout` — контрольная, только для замера |

Разделение стратифицированное: в каждой ячейке «язык × тип» по 10 запросов в `work` и в `holdout` (100 и 100). Контрольную часть не используют для настройки поиска.

## Первый замер

21 октября 2026, итоги и решения — в ADR-0048:

- гибрид Gemini — 96% Hit@5 на контрольной части и 88% строго на всех 200 запросах;
- выбрана модель `google/gemini-embedding-001` с длиной вектора 1024;
- цель к запуску — 90% строго, отдельно для русских и английских запросов (ADR-0021).

Цифры по каждому запросу — в `baseline.json`.

## Разметка: подходящие иконки

Подходящие иконки проставляет ИИ-судья командой `pnpm judge` (ADR-0048). Колонки `expected_icons` в CSV больше нет: разметка лежит в отдельных файлах.

- `judgments.json` — вердикты судьи `google/gemini-3.8-flash`: по каждой паре «запрос × иконка» — «подходит» (`fits`), «частично» (`partial`) или «нет» (`no`). Пара помнит текст запроса, описание и отпечаток иконки: если что-то из этого поменялось, пара размечается заново. Тут же — сколько стоила разметка. Руками не правится.
- `overrides.json` — правки владельца в виде `{"ru-008": {"lucide:shopping-basket": "no"}}`. Судья этот файл не трогает, а правки главнее его вердиктов.
- `baseline.json` — первый замер для фазы 2: цифры главных вариантов и первая десятка по каждому запросу. Пишет `pnpm eval --baseline`.

Судья видит запрос, описание и картинки кандидатов — всё, что попадает в первые десятки вариантов замера. Посмотреть разметку и проверить 20 случайных запросов можно на странице `.cache/reports/eval/judge.html`.

## Команды

```
pnpm judge --limit=10 --max-rub=30   # пилот: по запросу на ячейку «язык × тип»
pnpm judge                           # весь эталон; повторный запуск отправляет только новые пары
pnpm judge --dry-run                 # только посчитать пары и оценить стоимость
pnpm eval                            # замер: .cache/reports/eval/index.html
pnpm search-page                     # страница поиска для ручной проверки: http://127.0.0.1:4280
```

Нужен ключ `POLZA_API_KEY` в `.env` и векторы иконок (`pnpm embed`). Если векторы запросов уже в кэше, замер идёт без сети.

## Пересоздание

Перегенерация меняет запросы и разбиение, поэтому запускать её нужно осознанно: результаты замеров до и после нельзя сравнивать. Разметка новых запросов пойдёт заново: у пар поменяется текст запроса.

```
node --env-file=.env tools/eval/generate-queries.mjs
```
