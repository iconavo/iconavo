Шаг 12 фазы 4 (ADR-0044): 20 сценариев на русском и английском в Claude, ChatGPT и Claude Code. Группы сценариев — найти иконку, вставить код, собрать набор в одном стиле, лицензии.

- **Сценарии и признаки** — `packages/pipeline/src/mcp/clients-scenarios.ts`.
- **Claude Code** прогоняется командой `pnpm mcp clients`.
- **Claude и ChatGPT** владелец прошёл по общей таблице 20 ноября 2026.
- **Cursor** не проверялся: у владельца его нет.

## Что показала проверка

- **12 — CSS-класс — не прошёл во всех трёх клиентах.** Ни один ассистент не обратился к Iconavo: в запросе нет его имени, и ассистенты нарисовали иконку по памяти.
  - Исправление (PR #175): инструкция сервера требует брать иконку в любом виде — веб-компонент, React, SVG или CSS-класс — из Iconavo; описание `get_icon` — так же.
  - Против превью Claude Code на Sonnet оба раза вызвал `get_icon` с форматом `css` и назвал лицензию.
- **5 — эмодзи в ChatGPT.** ChatGPT не показал ни одной иконки Fluent Emoji. Исправление (PR #175): в описании стиля сказано, что эмодзи — это `"color"`, набор Fluent Emoji Flat.
- **15 — набор для меню в Claude.** Claude нашёл иконки, но не дал ни кода, ни установки. Исправление (PR #175): `get_matching_set` и инструкция сервера требуют отвечать кодом каждой иконки, строками установки и лицензией.
- **Claude Code показывает модели не текст ответа инструмента, а его данные** (`structuredContent`) строкой JSON. Подсказки из текста — «покажи список и спроси номер», блок лицензий — до модели не доходят. Ассистент и так строит список с номерами и лицензиями из данных, поэтому пока ничего не меняли; вынести подсказки в данные — в бэклоге.
- **Первый прогон Claude Code дал 10 из 20, но половина провалов была ошибками самой проверки** (исправлены в PR #174):
  - номер иконки для второго сообщения искался в тексте, а не в данных JSON;
  - код в ячейках таблицы не распознавался;
  - в проекте поиск вместе с `get_usage` не засчитывался.

  Повтор этих сценариев — 9 из 10, итог — 19 из 20.
- **Код из чатов в браузере не проверялся:** в таблицу его не вставляли, засчитан по оценке владельца. У Claude Code проекты сценариев 8, 9 и 14 собраны и открыты в Chrome — иконки нарисованы.
- **Живая проверка лимитов** (`pnpm mcp clients --limits`) не прогонялась: шаг принят раньше итогового прогона. Ошибку `rate_limited` с подсказкой «Wait about a minute and try again» проверяют тесты. Во время проверки в чатах лимит ни разу не сработал.
- **Ловушка «profile → бланк анализов»** (бэклог) в сценарии 15 не сработала: ChatGPT и Claude Code взяли иконку человека. У Claude этот сценарий не прошёл по другой причине — без кода.

## Как повторить

- `pnpm mcp clients [--only=…] [--model=…] [--limits] [--keep]` — нужен вход в Claude Code по подписке, около минуты на сценарий:
  - каждый сценарий — свежий `claude -p` в чистой папке вне репозитория, только с нашим сервером;
  - без настроек, плагинов, памяти и коннекторов владельца;
  - отчёт — `.cache/reports/mcp/clients.md`, журналы разговоров — `.cache/reports/mcp/clients/sNN.jsonl`.
- Claude и ChatGPT — те же запросы, по новому чату на сценарий. После каждой выкладки в ChatGPT нужно обновить список инструментов коннектора.
