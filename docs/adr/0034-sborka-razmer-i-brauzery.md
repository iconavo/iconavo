# ADR-0034. Сборка, размер и браузеры

Статус: принято 16 октября 2026 по рекомендации.

Вопрос: в каком виде выходят пакеты, сколько они весят и где работают?

Решение:

- Пакеты выходят только в современном формате модулей ESM с типами TypeScript; старый формат CommonJS не поддерживается.
- Бюджеты размера после gzip: ядро — 5 КБ, веб-компонент сверх ядра — 2 КБ, адаптер React сверх ядра — 2 КБ. CI падает при превышении (size-limit, ADR-0007).
- Пакеты устроены так, чтобы в сборку сайта попадало только то, что действительно используется.
- Поддерживаются последние две версии Chrome, Edge, Firefox и Safari.

Почему: ядро загружается на каждой странице пользователей, и каждый лишний килобайт замедляет чужие сайты.

Последствия: бюджеты можно пересмотреть после первой реализации, но только осознанно, через изменение этого ADR.

Уточнение от 26 октября 2026 (шаг 1 фазы 3, README пакета):

- Для страницы без сборщика в `@iconavo-ui/icon` лежит ещё и самостоятельный ES-модуль с ядром внутри (ADR-0032); его размер меряется отдельно.
- Режим разработки включается условием экспорта `development` (ADR-0031): длинные сообщения и пунктирная рамка живут только в сборке для разработки и не занимают бюджет рабочей.
- Цифр размера в README нет, пока их не измерит шаг 8.

Уточнение от 27 октября 2026 (шаг 5 фазы 3, тег):

- **Размеры в gzip** (`pnpm size`):
  - ядро — 4,48 КБ из 5;
  - тег сверх ядра — 1,98 КБ из 2, впритык. Больше всего весят тексты предупреждений с допустимыми значениями (их обещает README) и CSS заглушек; каждое новое свойство тега придётся окупать или пересматривать бюджет;
  - скрипт для страниц без сборщика `dist/iconavo-icon.js` — 5,88 КБ. Новый бюджет — 7 КБ, сумма бюджетов ядра и тега.
- **Как меряется.** Тег — `packages/icon/dist/index.js` без ядра (`ignore`): цифра с запасом, в ней и строки импорта из ядра. Скрипт — сам выпускаемый файл (`"rolldown": false`), поэтому CI собирает его перед `pnpm size` (`pnpm icon build`).
- **Поправка про режим разработки.** Рамка нужна и в рабочей сборке — для `configure({ dev: true })`. Поэтому её CSS есть во всех сборках, а входы отличаются только режимом по умолчанию (ADR-0032). Условие `development` webpack 5 и Vite выбирают сами, esbuild и Rollup — только с настройкой; Next.js и Turbopack проверяет шаг 7.

Уточнение от 28 октября 2026 (шаг 7 фазы 3, React; решение владельца — бюджет React 2,5 КБ):

- **Бюджет React сверх ядра — 2,5 КБ** вместо 2 (решение владельца). Адаптер весит 2,19 КБ. В нём то, что обещает README: разбор пропсов с текстами предупреждений, стили заглушек, Trusted Types и поиск в обёртке.
  - Уложиться в 2 КБ можно было только ценой этих обещаний.
  - Общий с тегом код в ядре вывел бы ядро за его 5 КБ.
  - Пользователь React скачивает ядро и адаптер — около 6,7 КБ в gzip.
- **Размеры в gzip** (`pnpm size`): ядро — 4,50 КБ из 5, тег — 1,98 из 2, React — 2,19 из 2,5, скрипт без сборщика — 5,89 из 7.
- **Как меряется React** — `{ Icon, IconavoProvider }` из `packages/react/dist/index.js` без ядра и react; в цифре и строки импорта.
- **Условие `development` в Next.js 16.4** (замер `pnpm example --check` 28 октября 2026):
  - Turbopack выбирает `development.js` тега в `next dev` и обычный вход в `next build`;
  - webpack (`--webpack`) — так же.

  По исходникам Next.js оба сборщика добавляют условие `development` или `production` по режиму сборки — и для браузера, и для сервера. Исключение — серверные пакеты, которые Next.js не собирает, а отдаёт Node (`serverExternalPackages`): Node условие `development` без флага не выбирает. Пакет React условие не использует: его режим — по `NODE_ENV` (ADR-0031).

Уточнение от 28 октября 2026 (шаг 8 фазы 3, бюджет в CI; решение владельца — потолок по бюджетам в README):

- **Таблица в сводке CI.** Шаг «Размер пакетов» задачи `check` (`.github/workflows/ci.yml`) запускает size-limit один раз, с `--json`. Таблицу «пакет, размер, бюджет, запас, итог» он пишет в журнал и в сводку запуска: её видно на странице запуска, без журнала, и при превышении тоже.
  - КБ — 1000 байт, как у size-limit; бюджет включает границу.
  - Превышение — код 1 и красная проверка `check`, а без неё PR в `main` не слить. Сломанная таблица тоже роняет шаг.
  - Локальные `pnpm size` и `pnpm check` не менялись.
- **Проверка превышения** — черновой PR #78, закрыт без слияния.
  - В ядро добавили 4 000 знаков случайного base64: gzip их почти не сжимает. Ядро стало 8,03 КБ при бюджете 5.
  - Проверка `check` покраснела на шаге «Размер пакетов», в таблице сводки — «превышен на 3,03 КБ» ([запуск](https://github.com/iconavo/iconavo/actions/runs/40690185419)).
  - Остальные шаги зелёные: функция edge API и скрипт тега тяжёлый код не взяли.
- **README** — потолок по бюджетам, а не точные цифры (решение владельца): тег с ядром — не больше 7 КБ, React с ядром — не больше 7,5 КБ, без самого React. Цифра не устареет: превышение роняет CI. На деле — около 5,9 КБ (скрипт без сборщика) и 6,7 КБ (ядро и адаптер по отдельности).
- **Размеры в gzip** (`pnpm size`): ядро — 4,50 КБ из 5, тег — 1,98 из 2 (запас — 20 байт), React — 2,19 из 2,5, скрипт без сборщика — 5,89 из 7.
