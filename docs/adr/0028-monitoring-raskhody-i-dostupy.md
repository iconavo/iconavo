# ADR-0028. Мониторинг, расходы и доступы

Статус: технические части приняты 16 октября 2026 по рекомендации; продуктовые — потолок расходов, публичная страница статуса, обезличенные логи — подтверждены владельцем 17 октября 2026 (отметки в [сводке решений](README.md)).

Вопрос: как вовремя узнавать о сбоях и расходах и кто имеет доступ к сервисам?

Решение:

- Проверка доступности каждые 5 минут: манифесты обоих хостов, пачка иконок и поиск. Оповещения приходят в Telegram или на почту.
- Еженедельная сводка: трафик, популярные наборы и запросы, расходы по провайдерам.
- Оповещение о расходах — при достижении 80% месячного потолка.
- Доступы: личные аккаунты с двухфакторной аутентификацией у всех провайдеров, токены с минимальными правами, секреты только в GitHub. Действия при сбоях описаны в `docs/ops.md`.

Продуктовые решения — владельца, подтверждены 17 октября 2026:

- Месячный потолок расходов на инфраструктуру до запуска. Рекомендация — около $100 с уточнением после первого месяца.
- Публичная страница статуса сервисов. Рекомендация — да: пользователи сами видят, всё ли работает.
- Что хранится в логах. Рекомендация — только обезличенная статистика без IP-адресов, а сырые логи — не дольше 30 дней.

Уточнение от 23 октября 2026: всё устройство выше делается после запуска, в фазе 8 — решение владельца. Это проверки каждые 5 минут, сводки, оповещение о расходах при 80% потолка, страница статуса и `docs/ops.md`; шаг 6 фазы 2 перенесён туда же.

До запуска пользователей нет, поэтому хватает страховки:
- **Сбои.** «Сверка хостов» (`verify.yml`) и «Публикация в npm» (`publish.yml`) раз в сутки проверяют оба хоста и пакеты. При неудаче запуска по расписанию GitHub присылает письмо.
- **Расходы.**
  - R2 за трафик не берёт.
  - У зоны CDN Bunny — лимит трафика в месяц, автопополнение баланса — на малую сумму (ADR-0025).
  - У команд ИИ — свои лимиты стоимости прогона: `--max-cost` у `pnpm enrich`, `--max-rub` у `pnpm embed` и `pnpm judge`.
- **Доступы** — как в решении: двухфакторная защита, токены с минимальными правами, секреты только в GitHub. Что делать, если ключ утёк, — в разделе «Ключи и секреты» `docs/phase-2.md`.

Уточнение от 23 октября 2026 (шаг 7 фазы 2, edge API, ADR-0024):

- **Ключ выкладки функции** — `CLOUDFLARE_API_TOKEN`, право Account · Workers Scripts · Edit.
  - Это секрет окружения GitHub `api`: выкладывать из него можно только из `main`, а задача «Выкладка» идёт без checkout и `pnpm install`.
  - Функция привязана к бакету раздачи, а ключ может выложить любую функцию с любой привязкой. Поэтому по силе он равен ключу записи R2.
  - Подмену файлов в бакете поймает ежедневная «Сверка хостов» (`pnpm cdn verify`).
- **Новый путь к расходам.** Запрос с непопулярным набором имён идёт в обход кэша и читает R2. Это операции класса B: $0,36 за миллион сверх 10 млн в месяц.
  - На бесплатном тарифе Workers потолок — 100 000 запросов в сутки по 100 имён, то есть не больше 10 млн чтений в сутки даже при злонамеренных запросах.
  - Страховка до запуска — бюджетное оповещение Cloudflare (Notifications → Add → Budget Alert), его ставит владелец.
  - Перед платным тарифом нужно ограничение частоты для `api.iconavo.dev` (бэклог).
- **Журналы Workers** — только сообщения об ошибках из кода функции, без журнала запросов и IP. Хранятся 3 дня, с декабря 2026 — 7: это в пределах «сырые логи — не дольше 30 дней».

Уточнение от 26 октября 2026 (шаг 8 фазы 2, поиск, ADR-0049):

- **Ключи поиска и их сила:**
  - `MEILISEARCH_ADMIN_KEY` — переписать или стереть индекс. Хранится только в окружении GitHub `search`, у робота индекса.
  - `MEILISEARCH_SEARCH_KEY` — только поиск, у функции edge API, окружение `api`.
  - `POLZA_API_KEY` — тратит баланс Polza; есть у робота (`search`) и у функции (`api`). Расход функции ограничивают длина запроса до 100 символов и 60 поисков в минуту с адреса.
  - `SEARCH_R2_ACCESS_KEY_ID` и `SEARCH_R2_SECRET_ACCESS_KEY` — токен только на закрытый бакет `iconavo-search`.
  - Адрес Meilisearch — тоже секрет: логи CI открыты.
- **Расходы:**
  - Meilisearch — после 14 дней пробы тариф XS, ≈ $23 в месяц;
  - Polza — ≈ 53 ₽ по оценке на первую загрузку индекса, дальше — копейки на новые тексты и запросы;
  - бакет поиска — ≈ 0,3 ГБ, в бесплатных пределах R2.
- **Журналы** — ни текста запросов, ни IP: IP служит только ключом лимита частоты.
- **Проверка безопасности шага 8:**
  - закрыта уязвимость «Поискового индекса» — запуск чужого коммита с ключами после поддельной «Выкладки» из форка (PR #53, ADR-0049);
  - workflow из форков теперь всегда ждут подтверждения владельца;
  - история git чистая.

Уточнение от 29 октября 2026 (шаг 10 фазы 3, [ADR-0050](0050-sayt-dokumentatsii-i-zhivye-primery.md)) — сайт на Vercel:

- **Ключ.** `VERCEL_TOKEN` лежит только в окружении GitHub `site` (только `main`) и действует год. Он выкладывает и меняет любые проекты команды Vercel, поэтому сайт выкладывает только задача «Выкладка»: без checkout и без установки наших зависимостей.
- **Защита аккаунта.** На аккаунте Vercel включена двухфакторная защита. Вход — по почте, Vercel не получает доступа к репозиторию.
- **Расходы.** Тариф Hobby бесплатный, но только для некоммерческого использования. Появится коммерция — переход на Pro за $20 в месяц (фаза 7).
  - С 19 ноября 2026 — Pro, раньше плана: квоты Hobby не хватило ещё до запуска (ADR-0039). Сверх включённых $20 расход оплачивается по факту. Уведомление о расходах (Spend Management) Vercel по умолчанию присылает при $200; порог — решение владельца.

Уточнение от 19 ноября 2026 (шаг 10 фазы 4, MCP-сервер, ADR-0044) — платный Workers и MCP:

- **Расходы.** Cloudflare Workers — на платном тарифе с 19 ноября 2026 (решение владельца): $5 в месяц, в них 10 млн запросов и 30 млн мс процессора в месяц, сверх — $0,30 за миллион запросов и $0,02 за миллион мс (ADR-0024). Суточного потолка нет: обход ботами идёт в счёт. Страховка — оповещение о расходах (Notifications → Add → Budget Alert, ставит владелец), предел процессора на вызов у MCP (300 мс) и ограничение частоты для зоны (бэклог).
- **Ключи MCP** — те же, что у edge API: выкладка MCP идёт из окружения GitHub `api` (только `main`) с `CLOUDFLARE_API_TOKEN`, `R2_ACCOUNT_ID` и ключами поиска. Новых секретов нет; `CLOUDFLARE_API_TOKEN` по-прежнему выкладывает любую функцию аккаунта.
- **Журналы MCP** — как у API: только наши сообщения об ошибках, без журнала запросов и IP; адрес человека — только ключ лимита частоты.

Уточнение от 26 ноября 2026 (ревизия фазы 5, «Укрепление», Б-1…Б-3) — доступы CI:

- **Ключи записи раздачи** — `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` и `BUNNY_STORAGE_PASSWORD` — секреты окружения GitHub `cdn`, оно пускает только `main`. Их берут две задачи: выгрузка «Выкладки» (`deploy.yml`) и «Сверка хостов» (`verify.yml`). С другой ветки «Выкладка» не идёт вовсе, и показ тоже. `R2_ACCOUNT_ID` — секрет репозитория: его берут и «Edge API», «MCP-сервер», «Поисковый индекс». Правило проверяет тест `workflows.test.ts`.
- **Сторонние действия GitHub** закреплены по хэшу коммита, тег выпуска — в комментарии; сейчас такое одно — `pnpm/action-setup` (v6.1.1). Действия самого GitHub (`actions/*`) — по тегу. Закреплённое обновляется вручную; правило проверяет тот же тест.
- **Сканирование секретов и защита при отправке** (Secret scanning, Push protection) — включены в настройках репозитория (их включает владелец).

Почему: о проблеме лучше узнать от монитора, чем от пользователя, а потолок расходов защищает от неприятных счетов.
