# ADR-0035. Тесты и проверки

Статус: принято 16 октября 2026 по рекомендации.

Вопрос: как убедиться, что пакет работает у пользователей так же, как в песочнице?

Решение:

- Модульные тесты на Vitest для ядра: очередь, повторы, отсутствующие иконки, запасные хосты. Покрытие ядра тестами — не ниже 90%.
- Браузерные тесты на Playwright в Chromium, Firefox и WebKit.
- Визуальное сравнение иконок из пакета с SVG из фазы 1 через pixelmatch: расхождений быть не должно.
- Сбои сети: тесты блокируют основной хост и edge API, замедляют сеть и проверяют, что иконки всё равно появляются.
- Доступность: автоматическая проверка axe-core для иконок с подписью и без.
- Серверный рендер: пример на Next.js собирается и открывается без предупреждений о гидратации.
- Всё это запускается в CI на каждый pull request.

Почему: вы не читаете код, поэтому тесты — ваша гарантия, что изменение ничего не сломало.

Уточнение от 27 октября 2026 (шаг 5 фазы 3; решение владельца — Playwright сейчас, а не в шаге 9):

- **Playwright 1.64.1** — точная версия, в зависимостях конвейера. Браузеры ставятся один раз: `pnpm exec playwright install webkit firefox` (около 190 МБ, в `%LOCALAPPDATA%\ms-playwright`). Chrome — установленный, через `channel: "chrome"`.
- **WebKit вместо Safari.** Safari на Windows нет, и на шаге 5 его заменяет WebKit Playwright — движок Safari. По документации Playwright у WebKit на Windows отличаются видео, графика и сеть; ближе всего к Safari — WebKit на Mac.
- **`pnpm sandbox --check`** — проверка тега без интернета. Песочница и превью API поднимаются на свободных портах, браузеры идут по очереди. Что проверяется:
  - регистрация двух копий;
  - стили и Trusted Types при строгой CSP;
  - ошибки и нарушения политики;
  - предупреждения;
  - задержка и вид заглушек, в том числе без анимации;
  - рамка, перекраска, подпись, место до загрузки и ленивая загрузка.

  Отчёт — `.cache/reports/sandbox/check.html`, таблица и снимки каждого браузера.
- **Подпись** проверяется только в Chrome — по дереву доступности браузера. В Firefox её проверяют Экранным диктором вручную, в WebKit на Windows скринридера нет.
- **Плавность прокрутки** проверяет владелец глазами: `pnpm sandbox --browser=webkit|firefox|chrome` открывает песочницу в окне браузера.
- **В CI** браузерной проверки пока нет — это шаг 9. Тесты тега в Vitest идут в Node на маленькой подделке DOM, без новых зависимостей.

Уточнение от 28 октября 2026 (шаг 7 фазы 3, React и Next.js):

- **Тесты React в Vitest** — серверная разметка через `react-dom/server` в Node: обёртка, заглушки, ID, подпись, неверные значения, правило «ядро сервера не читается». Эффекты и гидратацию проверяет браузер: библиотеки DOM для Node (happy-dom) не добавляли.
- **`pnpm example --check`** — пример `examples/next` в режиме разработки (`next dev`) и в продакшен-сборке (`next build`, `next start`), в Chrome, Firefox и WebKit по очереди.
  - Сеть не нужна: хосты иконок — превью API на свободном порту.
  - Что проверяется:
    - серверный HTML (контекст без JavaScript);
    - «без мигания»: сторож DOM и одинаковые снимки раздела до и после гидратации;
    - консоль и строгая CSP продакшена;
    - заглушки: сразу после гидратации скрыты, через 0,25 с видны — скелетон мерцает, спиннер крутится. Снимок этого момента — в отчёте: на снимке «сразу после загрузки» заглушек ещё не видно, и он сбивал с толку (замечание владельца 28 октября 2026);
    - запросы к хостам;
    - клиентский компонент и переход по ссылке;
    - подпись (Chrome), Trusted Types, рамка, тег в React.
  - Сведения для ADR: какой вход тега выбрал Next.js и работает ли `var()` в атрибуте `color`.
  - **Контрольный запуск** портит заголовок страницы сразу после разбора HTML и ждёт сообщения о гидратации. Другое сообщение не в счёт: проверка не должна быть слепой.
  - **Почему оба режима.** Расхождение текста React 19 сообщает и в продакшене (ошибка #418), а расхождение атрибутов — только в сборке для разработки. Поэтому без `next dev` проверка не увидела бы, например, лишний класс у `<svg>`.
  - Отчёт — `.cache/reports/example/check.html` со снимками, код 1 — есть проблемы. `--webpack` — то же со сборщиком webpack.
  - Снимки — через помощника песочницы: стиль, который Playwright вставляет для снимка, строгая CSP WebKit отклоняет, и эти нарушения не в счёт.
- **React 18** в браузере проверит шаг 9: App Router рисует своей сборкой React 19, а React 18 под другим именем не ставили (решение владельца).
