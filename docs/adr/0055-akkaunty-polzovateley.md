# ADR-0055. Аккаунты пользователей

Статус: принято 23 ноября 2026. Решения владельца:
- продавец — его ИП в Эстонии;
- тарифы и оплата — после запуска, в фазе 8;
- свой сервис аккаунтов, а не готовый; библиотека Better Auth — новая зависимость;
- без «коммерческой лицензии» и обещания «без указания авторства»;
- аккаунты делаются в фазе 5, закрытой беты нет (`docs/roadmap.md`);
- блок «Your Plan» до тарифов, обратная связь — владельцу, подписки на наборы и рюкзак в аккаунте — до запуска.

Остальное — по рекомендации; подробности уточняются в PR сервиса.

Вопрос: как сделать аккаунты пользователей по макетам Figma «Авторизация / Регистрация / Забыли пароль» и «Личный кабинет», не нарушив устройство сайта (статические страницы, строгая CSP — ADR-0039, ADR-0050), приватность (ADR-0028, ADR-0043) и лицензии наборов (ADR-0017)?

## Решение

### Что делаем и когда

**Фаза 5, до запуска — аккаунты без денег:**
- **Вход** — окном поверх текущей страницы: по почте и паролю или через Google.
  - Регистрация: почта → код из 6 цифр → пароль.
  - Восстановление пароля: почта → код → новый пароль.
  - Кадры — раздел макета «Авторизация, регистрация».
- **Меню аккаунта** по аватару и выход — сценарии A1 и L раздела «Личный кабинет».
- **Страница Account → My account** (сценарии B–F):
  - фото с обрезкой по кругу и имя;
  - почта: смена — кодом на новый адрес;
  - пароль;
  - способы входа: Google подключается и отключается, но без пароля отключить его нельзя — сначала задать пароль;
  - письма;
  - удаление аккаунта — вводом своей почты.
- **Обратная связь** из меню аккаунта (сценарий K): ошибка со скриншотом, запрос иконок, запрос функции, отзыв со звёздами. Help center открывает документацию в новой вкладке.
- **Подписки на наборы:**
  - кнопка «Subscribe to updates» на странице набора и страница Subscribed;
  - еженедельное письмо о новых, изменённых и переименованных иконках подписанных наборов — по журналу выпусков (ADR-0018).
- **Рюкзак в аккаунте** — один на все устройства. При входе рюкзак браузера сливается с рюкзаком аккаунта, предел прежний — 500 иконок (ADR-0042).
- **Страница «Приватность»** — до включения аккаунтов (сейчас в подвале «Soon»).

**Фаза 8, после запуска:**
- вкладка Plan & licenses, тарифы Free / Pro / Ultimate, оплата и счета — сценарии A3, A4 и G–J; цены и состав тарифов в макете — заглушки, они решаются тогда же;
- платный доступ для ИИ-агентов: вход в MCP-сервер через аккаунт Iconavo по OAuth — так авторизацию устраивает протокол MCP.

**Лицензия.** Iconavo не правообладатель иконок. Строк макета «Commercial license with a certificate» и «No attribution needed» не будет ни сейчас, ни с тарифами (решение владельца). Тарифы продают удобство и сервисы, а у каждой иконки остаётся лицензия её набора с указанием авторства (ADR-0017).

**Пока тарифов нет,** блок «Your Plan» внизу левой панели у гостя ведёт на вход («Log In to Your Account»), а у вошедшего показывает аватар и имя, без «Manage». Кнопка аккаунта в верхней полосе и подписки на наборы перестают быть «Soon» (ADR-0038).

### Продавец и законы

- **Продавец и оператор персональных данных — ИП владельца в Эстонии** (решение владельца). Главный закон — GDPR:
  - данные аккаунтов хранятся в ЕС;
  - удалить аккаунт можно самому (сценарий F);
  - выгрузка своих данных — по письму, пока нет кнопки;
  - «Приватность» перечисляет, что хранится, зачем и у кого: Cloudflare, почтовый сервис, Google — только при входе через Google.
- **Оплата в фазе 8 — через сервис-продавца** (Merchant of Record): Paddle или Stripe Managed Payments, выбор — тогда же.
  - Покупателю продаёт сам сервис, а ИП — сервису. Поэтому налоги стран покупателей, чеки и неудачные продления — на нём.
  - Поля карты в окне оплаты — его форма, оформленная под макет: номера карт через нас не проходят.
  - С продавцами из ЕС оба сервиса работают. Покупателей из России Paddle не принимает, и тарифы россиянам, скорее всего, будут недоступны.
- **152-ФЗ** требует записывать данные россиян сначала в базу в России и формально касается и зарубежных сайтов с русской версией. Для небольшого зарубежного сайта главный риск — блокировка в России. Спросить юриста один раз перед запуском, вместе с текстом «Приватности».

### Устройство

- **Свой сервис аккаунтов** — функция Cloudflare Workers `iconavo-account` на `account.iconavo.dev`, рядом с edge API и MCP. Выкладка — из CI тем же путём, что у них (ADR-0024, ADR-0044), с проверкой живого адреса после выкладки.
- **Better Auth** — библиотека входа: пароли, коды на почту, вход через Google, сеансы, смена почты, удаление. Версия закрепляется точно. Свой код — интерфейс по макетам и связка с сайтом. Любой следующий пакет, например драйвер базы, — с отдельного согласия владельца.
- **Данные:**
  - база Cloudflare D1 в Европе — люди, способы входа, сеансы, коды, подписки, рюкзаки, обратная связь;
  - фото и скриншоты — в закрытом бакете R2, отдаёт их сервис;
  - персональных данных нет ни в git, ни в журналах, ни в аналитике.
- **Cookie сеанса — только у `account.iconavo.dev`:** без атрибута Domain, HttpOnly, Secure, SameSite=Lax.
  - Она не уходит ни на сайт, ни на раздачу иконок (`cdn` и Bunny), ни в edge API и MCP.
  - Для браузера сайт и сервис — один сайт `iconavo.dev`, поэтому cookie не считается сторонней.
- **Сайт остаётся статическим** (ADR-0039):
  - о входе узнаёт браузер — запросом к сервису после загрузки страницы; Vercel не собирает страницы на каждый запрос, proxy нет;
  - в CSP сайта адрес сервиса добавляется в `connect-src`;
  - окно входа и шторки на телефоне — `<dialog>`, как рюкзак и настройки: модальные компоненты Radix вставляют `<style>` (ADR-0038).
- **Защита:**
  - лимиты частоты по адресу и по почте — привязки ratelimit Workers, как у поиска и MCP (ADR-0049, ADR-0044);
  - Cloudflare Turnstile — на регистрации, восстановлении и входе после неудачных попыток;
  - код из 6 цифр живёт недолго, число попыток ограничено, повторная отправка — через минуту, как в макете;
  - смена пароля и почты завершает остальные сеансы;
  - восстановление не говорит, есть ли аккаунт с такой почтой. Регистрация говорит «почта занята», как в макете, и закрыта лимитами и Turnstile.
- **Письма:**
  - что: коды, смена почты, еженедельная сводка подписок; новости продукта — только по согласию, переключатели — в My account;
  - язык — язык страницы, с которой человек зарегистрировался: английский или русский;
  - почтовый сервис выбирается в PR сервиса по ценам и надёжности: Cloudflare Email Service (бета с апреля 2026) или зрелый сервис;
  - домен отправки — с SPF, DKIM и DMARC, в сводках — отписка в один щелчок.
- **Обратная связь** — запись в базе и письмо владельцу, скриншоты — в закрытом R2. Не в GitHub Issues: репозиторий открытый (ADR-0036).
- **Аналитика аккаунтов не видит:** события по-прежнему обезличенные, без идентификатора аккаунта (ADR-0043).
- **Проверки:**
  - сборка, превью и проверка живого сервиса — командами, как у edge API и MCP;
  - на сайте — все сценарии макета в Chrome, Firefox и WebKit, на компьютере и телефоне, с подставной почтой: в `pnpm site --check`, с контрольными поломками;
  - перед включением для людей — `/security-review` всего входа.

### Порядок работ

1. Этот ADR и план фазы 5 (`docs/roadmap.md`).
2. Сервис без интерфейса: база, вход, письма, лимиты, проверки, выкладка.
3. Окно входа на сайте: вход, регистрация, восстановление, меню аккаунта, выход.
4. Страница My account (сценарии B–F) с телефонными кадрами.
5. Подписки на наборы, сводки и рюкзак в аккаунте.
6. Обратная связь, страница «Приватность», `/security-review` — и только потом аккаунты включаются для людей.

### Что делает владелец

Пошаговые инструкции — в PR сервиса.

- **Google Cloud:** клиент OAuth и экран согласия — название, логотип, ссылка на «Приватность».
- **DNS в Cloudflare:** записи почтового сервиса — SPF, DKIM, DMARC.
- **Cloudflare:**
  - база D1 и виджет Turnstile;
  - право ключа выкладки на D1. Ключ становится сильнее: доступ к базе с почтами людей (ADR-0028).
- **Текст страницы «Приватность»** — с юристом.

Уточнение от 27 ноября 2026 — план шага 3 фазы 5 и решения владельца, все — по рекомендации. Подробный план — шаг 3 `docs/phase-5.md`.

- **Почта — Cloudflare Email Service**, хотя он пока помечен «бета». Привязка `send_email`, без ключа; 3 000 писем в месяц входят в тариф Workers, дальше — $0,35 за 1 000; записи SPF, DKIM и DMARC Cloudflare ставит сам. Письма — от `support@iconavo.dev`, ответы приходят владельцу пересылкой Email Routing. Модуль отправки один — на случай смены сервиса.
- **Закрытый режим** до `/security-review`: зарегистрироваться могут только адреса из списка владельца, остальные видят кнопку аккаунта «Soon».
- **База — со строгой привязкой к ЕС** (Jurisdiction EU), а не с подсказкой расположения, как у аналитики. По документации Cloudflare её можно задать в окне создания базы, изменить потом нельзя. Бакет для фото и скриншотов — тоже в ЕС.
- **Better Auth 1.7 работает с D1 сам** — драйвер базы не нужен, других новых пакетов нет. Его телеметрия выключена. На сайте клиента Better Auth нет — свой маленький.
- **Права D1 ключу выкладки не нужно:** привязке базы хватает права на функции, а таблицы сервис создаёт сам. По силе ключ всё равно равен доступу к данным людей. У сервиса — своё окружение GitHub `account` (только `main`), чтобы выкладка API и MCP его секретов не видела.
- **Отчёт аналитики — через edge API по отдельному секрету,** `ANALYTICS_READ_TOKEN` удаляется: право D1 у ключей Cloudflare нельзя сузить до одной базы (ADR-0028).
- **Встроенные скрипты в CSP сайта остаются** (бэклог, Б-7): nonce и хэши у статических страниц Next.js невозможны без сборки страниц на каждый запрос (ADR-0039). Взамен:
  - тест не пускает в код сайта вставку HTML строкой;
  - опасные действия — только с паролем или кодом;
  - cookie сеанса — только у сервиса;
  - единственный сторонний скрипт — Turnstile от Cloudflare.
- **Вход помнится 30 дней с последнего визита.** Смена почты и пароля, отключение Google и удаление — с паролем или кодом на почту.
- **Сроки хранения:**
  - код — 10 минут;
  - регистрация без подтверждения — сутки;
  - удалённый аккаунт — сразу всё, вместе с фото, подписками, рюкзаком и отзывами;
  - отзывы и скриншоты — год.
- **По рекомендации и остальное:**
  - Turnstile — на регистрации, восстановлении и на входе после трёх неудачных попыток;
  - код — 3 попытки, повтор через минуту;
  - фото из Google копируется к себе один раз;
  - сводка — по понедельникам утром по Европе, пустых писем нет.
- **Тесты видят пределы D1** (урок PR #207, ADR-0043): подделка D1 отклоняет всё, что отклонит настоящая база.

Дословные шаги владельца — после PR сервиса.

Почему: интерфейс аккаунтов полностью свой, по макетам, поэтому готовые экраны сервисов вроде Clerk не нужны. А их цена — данные людей у сторонней компании в США, плата за каждого пользователя и чужие скрипты в строгой CSP.

Свой сервис на Workers хранит данные в ЕС, живёт рядом с API и MCP и выкладывается тем же путём. Better Auth избавляет от самописных паролей и кодов — самой рискованной части. Отдельный адрес, у которого одного есть cookie, оставляет сайт статическим, а раздачу — без cookie.

Деньги — после запуска: сначала продукт должен быть законченным, а платить будет за что, когда появятся плагины и платный MCP.
