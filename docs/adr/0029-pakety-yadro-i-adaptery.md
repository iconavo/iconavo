# ADR-0029. Пакеты: ядро и адаптеры

Статус: технические части приняты 16 октября 2026 по рекомендации, с опорой на Iconify; продуктовая ждёт вашего подтверждения.

Вопрос: из каких пакетов состоит библиотека для разработчиков?

| Пакет | Что делает |
| --- | --- |
| `@iconavo-ui/core` | Ядро без привязки к фреймворку: хранилище, загрузка, рендер SVG |
| `@iconavo-ui/icon` | Веб-компонент `<iconavo-icon>` для любого фреймворка и обычного HTML |
| `@iconavo-ui/react` | Компонент React, который рисует SVG напрямую через ядро |

- Ядро общее для всех адаптеров — так устроен и Iconify, где все компоненты работают на одном ядре ([источник](https://github.com/iconify/iconify)).
- Адаптер React не оборачивает веб-компонент, а рисует SVG сам: так проще серверный рендер, и так же устроен React-компонент Iconify.
- Адаптеры Vue и Svelte делаются после запуска по той же схеме.
- Во время работы у пакетов нет внешних зависимостей.

Продуктовое решение — за вами: имена. Рекомендация — по образцу тега `iconify-icon` у Iconify: тег `<iconavo-icon>` и пакеты `@iconavo-ui/core`, `@iconavo-ui/icon`, `@iconavo-ui/react`. Scope в npm — `@iconavo-ui`, потому что `@iconavo` занято; имя тега от npm не зависит. Дефис в имени тега обязателен: этого требует стандарт веб-компонентов.

Почему: логика живёт в одном месте, а каждый адаптер остаётся тонким и простым.
