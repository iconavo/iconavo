# ADR-0009. Поиск: гибридный, смысловой и многоязычный

Статус: направление принято 15 октября 2026; движок — Meilisearch (ADR-0027), модель эмбеддингов выбрана по эталону 21 октября 2026 (ADR-0010, ADR-0048).

Вопрос: как находить иконки по смыслу и на любом языке, а не только по словам из имени?

Варианты:

1. Текстовый поиск по именам и тегам. Просто и быстро, но запрос «домик» не найдёт иконку house.
2. Текстовый поиск по словам, которые заранее сгенерировала нейросеть. Так в августе 2026 сделал Iconify ([источник](https://iconify.design/news/2026.html)): помогает, но поиск ограничен списком слов.
3. Гибрид: текстовый поиск плюс векторный по эмбеддингам, результаты сливаются.

Решение: вариант 3.

- Текстовая часть ловит точные имена, начала слов и опечатки, векторная — смысл и другие языки.
- Точное совпадение имени всегда стоит выше остальных результатов.
- Фильтры: стиль, цветность, набор, лицензия; варианты одной иконки группируются.
- Популярные запросы кэшируются на edge, вектор запроса считается на лету.

Кандидаты на движок:

| Кандидат | Сильные стороны | Чем платим |
| --- | --- | --- |
| Meilisearch | Гибридный поиск, опечатки и фильтры из коробки | Отдельный сервис |
| Typesense | То же, векторный поиск встроен | Отдельный сервис |
| Postgres + pgvector | Одна база для поиска и данных сайта | Опечатки и ранжирование настраиваются вручную |

Как меряем: эталон из 200 запросов на русском и английском с ожидаемыми иконками. Метрика — доля запросов, где нужная иконка в первой пятёрке; цель к запуску — 90% строго, отдельно для русских и английских запросов (ADR-0021).

Последствия: поиск — единственная часть системы с постоянно работающим сервером. Прототип поиска появляется в фазе 1 на данных конвейера, развёрнутый сервис — в фазе 2.
