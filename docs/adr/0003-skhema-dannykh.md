# ADR-0003. Схема данных

Статус: принято 15 октября 2026 по рекомендации, с опорой на Iconify.

Вопрос: из каких файлов состоит набор и что в каждом лежит?

Решение: структура файлов совместима с открытым форматом IconifyJSON, а данные для поиска лежат в отдельном файле.

| Файл | Что внутри | Кто использует |
| --- | --- | --- |
| `icons.json` | Префикс, тела иконок, размеры, алиасы с поворотами и отражениями, пометка hidden, время изменения | Пакет, edge API, MCP |
| `info.json` | Название, автор, лицензия, число иконок, примеры, высота сетки, признак цветного набора | Сайт, MCP |
| `metadata.json` | Категории и карта суффиксов вариантов | Сайт, поиск |
| `search.json` | Теги, описания и синонимы на русском и английском, отпечатки иконок | Поиск, конвейер |

Векторы эмбеддингов в файлы набора не попадают: они живут в поисковом индексе.

Уточнение от 20 октября 2026 (шаг 8 фазы 1, ADR-0018):

- К файлам набора добавился журнал выпусков: `changelog.json` для сайта и CI, со своей схемой, и `CHANGELOG.md` для людей.
- В `icons.json` теперь есть скрытые иконки (`hidden`), алиасы переименований и прежних имён от автора, а также `lastModified`.
- В `info.json` появилась версия набора.

Почему: формат проверен годами работы Iconify. Его понимают популярные инструменты — Unplugin Icons, UnoCSS, плагины Tailwind, — поэтому разработчики смогут подключать ваши наборы привычными способами. Это совместимость формата, а не зависимость: код, данные и серверы остаются вашими.

Последствия: валидатор в фазе 1 строится по этой таблице, а поля сверх IconifyJSON добавляются только в `search.json`.
