# ADR-0042. Генератор кода и экспорт

Статус: технические части приняты 16 октября 2026 по рекомендации; продуктовые — все форматы экспорта и мультивыбор к запуску — подтверждены владельцем 17 октября 2026 (отметка в [сводке решений](README.md)).

Вопрос: в каком виде человек забирает иконку в свой проект?

| Вариант | Что получает человек |
| --- | --- |
| Веб-компонент | `<iconavo-icon icon="lucide:heart"></iconavo-icon>` и команду установки |
| React | `<Icon icon="lucide:heart" />` с импортом из `@iconavo-ui/react` |
| SVG | Готовый код с выбранными настройками |
| CSS | Класс с маской или фоном через `api.домен` |
| Ссылка | Адрес SVG с параметрами для `<img>` |
| Файлы | SVG, PNG от 16 до 512 px, ZIP выбранных иконок, SVG-спрайт |

- Команды установки — для npm, pnpm и yarn; выбранный вариант запоминается.
- PNG рисуется прямо в браузере, без нагрузки на сервер.
- Мультивыбор: иконки собираются в «сумку», из неё — ZIP или спрайт, и в архив всегда кладутся тексты лицензий. На новом сайте Iconify тоже есть мультивыбор с бандлами и спрайтами ([источник](https://iconify.design/news/2026.html)).
- Каждое копирование и скачивание считается успехом поиска в аналитике (ADR-0043).

Продуктовые решения — владельца, подтверждены 17 октября 2026:

- Форматы экспорта к запуску. Рекомендация — все варианты из таблицы.
- Мультивыбор к запуску. Рекомендация — да: у Iconify он уже есть, и пользователи будут его ждать.

Уточнение от 26 октября 2026 (шаг 1 фазы 3): иконка в коде задаётся атрибутом и пропом `icon`, как у Iconify, а не `name` (ADR-0031, решение владельца). Настройки превью переходят в код атрибутами пакета: `width`, `height`, `color`, `stroke-width` (`strokeWidth` в React), `rotate`, `flip` — их описывает `packages/icon/README.md`.

Уточнение от 3 ноября 2026 (шаг 5 фазы 4) — решения владельца:

- **Сумка — меню из кнопки в шапке**, а не отдельная страница: кнопка с числом иконок, по щелчку — немодальное меню поверх страницы (ADR-0038: модальные окна Radix ломают строгую CSP).
- **Класть в сумку** — кнопкой «В сумку» в панели и на странице иконки и режимом «Выбрать несколько» в сетке набора и в выдаче поиска: пока он включён, щелчок по иконке кладёт её в сумку или убирает, панель не открывается.
- **Из сумки** — исходный вид иконок (цвет текста и родная толщина) плюс один общий цвет и одна толщина линии на все иконки, где это применимо.
- **Лицензии в файлах:**
  - в ZIP — папка `LICENSES` с полными текстами и `README.txt` с указанием авторства;
  - одиночный SVG и спрайт начинаются с короткого комментария: набор, автор, лицензия и ссылка на её текст;
  - в PNG ничего: это картинка.

Уточнение от 3 ноября 2026 (шаг 5 фазы 4) — как устроены код и скачивание одной иконки:

- **Где.** Разделы «Код» и «Скачать» — в `IconDetails`, общем у панели и страницы иконки (ADR-0041), после «Настроек». Настройки сразу применяются к коду и файлам.
- **Варианты кода** — кнопки с `aria-pressed`, как у поворота. Вкладки Radix не подходят: они ставят атрибут `style` в серверный HTML, а CSP сайта его не пускает (ADR-0038). Выбранный вариант запоминается в localStorage (`iconavo-code`), как тема.
  - **Тег** — команда установки, строка подключения, код `<iconavo-icon …>` и «Без сборщика» — строки `<script>` с хэшем `integrity` и `<style>`.
  - **React** — команда установки, импорт и `<Icon … />`.
  - **SVG** — SVG с настройками, побайтно тот же, что отдаёт адрес из «Ссылки»: его собирают те же функции ядра в том же порядке, что `svgBody` edge API (тест `apps/site/lib/code.test.ts` сверяет иконки пяти наборов на сетке настроек).
  - **CSS** — ссылка на CSS edge API и элемент с классами. Размера, поворота и отражения у CSS API нет, их задаёт стиль элемента: размер — `font-size`, поворот и отражение — `transform`.
  - **Ссылка** — адрес SVG edge API с параметрами.
- **В код попадают только изменённые настройки.** Размер превью по умолчанию (48 px) не пишется: тогда у тега, React и SVG `1em`, как у Iconify. Цвет — только у монохромных, толщина — где она меняет рисунок (`hasStrokeWidth`, ADR-0041). Параметры — как в README тега: `width`, `color`, `stroke-width` (`strokeWidth` в React), `rotate` градусами, `flip`.
- **Установка** — кнопки npm · pnpm · yarn, выбор запоминается (`iconavo-pm`): `npm install`, `pnpm add`, `yarn add`, без тега `@next` — `latest` идёт за каждой бетой (ADR-0051).
  - Имена пакетов, строки подключения и «без сборщика» — **из `packages/icon/README.md`**, как документация (ADR-0050). Их читает `next.config.ts` при сборке (`lib/install-readme.ts`) и вшивает в код переменной `ICONAVO_INSTALL`: страницы иконок собираются по первому запросу на Vercel, а README в функции нет. Нужной строки нет или она не одна — «СТОП» сборки.
  - Хэш `integrity` в README обновляет `pnpm release bump` (ADR-0051), сайт берёт его со следующей выкладкой.
- **SVG-файл** (`lucide-house.svg`) — тот же SVG, но размер — родной у сетки набора (24 или 32 px), если размер не меняли. Первой строкой — комментарий на английском: имя, текст указания авторства (тот же, что в панели), «Based on Feather…» у иконок из Feather и ссылка на `https://iconavo.dev/licenses#{набор}`. Внутри комментария XML нет «--».
- **PNG** (`lucide-house-256.png`) — 16, 24, 32, 48, 64, 128, 256 или 512 px, по умолчанию 256. Размеры — кнопки, а не ползунок. Рисует браузер (`lib/png.ts`): SVG — картинкой по адресу `data:`, его пускает `img-src` CSP сайта, затем canvas и `toBlob`. Свой цвет — как выбран, иначе чёрный: у картинки нет цвета текста вокруг.
- **Метки аналитики** (ADR-0043) — `lib/analytics.ts`, `track()`: у всех «Копировать» (код, установка, подключение, «без сборщика», имя, указание авторства) и у каждого скачивания. До шага 7 метка только посылает событие страницы `iconavo:track`.

Уточнение от 3 ноября 2026 (шаг 5 фазы 4) — как устроена сумка:

- **Хранение** — `apps/site/lib/bag.ts`: имена в localStorage браузера (`iconavo-bag`) в порядке добавления, не больше 500. Сумка переживает перезагрузку и видна во всех вкладках, на сервер не уходит. Чужое или неверное имя из хранилища отбрасывается.
- **Кнопка в шапке** (`components/BagMenu.tsx`) — `lucide:shopping-bag`, число иконок — значком поверх кнопки, после гидратации: шапка не сдвигается. Меню — Popover из `radix-ui`, всегда немодальный (`components/ui/popover.tsx`, ADR-0038). Внутри:
  - список с «Убрать» и «Очистить»;
  - «Свой цвет» и «Толщина линии» — только если в сумке есть монохромные иконки и линии;
  - «Скачать ZIP» и «Скачать спрайт»;
  - строка о текстах лицензий наборов.

  Esc и щелчок вне меню закрывают его, фокус возвращается на кнопку. На телефоне меню — во всю ширину, список прокручивается внутри.
- **«В сумку»** — кнопка-переключатель (`aria-pressed`) в разделе «Скачать» панели и страницы иконки.
- **«Выбрать несколько»** — переключатель над сеткой набора и выдачей поиска (`components/catalog/SelectToggle.tsx`):
  - пока он включён, карточки — кнопки с `aria-pressed`: щелчок кладёт иконку в сумку или убирает, панель не открывается;
  - строка состояния объявляет число иконок в сумке;
  - режим в адрес не попадает.
- **Вид** — исходный: цвет текста и родная толщина. Плюс один общий цвет и одна толщина на все иконки: толщина меняет только линии с `currentColor`, цвет встаёт вместо `currentColor`, цветные иконки не меняются. Размер файлов — родной у сетки набора.
- **ZIP** `iconavo-icons.zip` — свой модуль `lib/zip.ts`: без сжатия (store), CRC-32, имена в UTF-8. Внутри:
  - `{набор}/{иконка}.svg`;
  - `LICENSES/{набор}.txt` — полный текст лицензии и NOTICE, если он есть, из `/collection?info=true`;
  - `README.txt` — по набору: указание авторства тем же текстом, что в панели (с Feather у Lucide — из `/icon`), ссылка на текст лицензии и список файлов.
- **Спрайт** `iconavo-sprite.svg` — `<symbol id="{набор}-{иконка}" viewBox>` на иконку, ID внутри рисунков — свои у каждого символа (`replaceIds` ядра). Первым — многострочный комментарий: наборы, авторы, лицензии, ссылка на тексты и как подключить, `<svg><use href="iconavo-sprite.svg#lucide-house"/></svg>`. Что ID `набор-иконка` не совпадают ни у одной пары имён каталога, сверяет тест.
- **Сборка файлов** — в браузере, `lib/bag-export.ts`, грузится по щелчку (`import()`): рисунки — пачками edge API через ядро, тексты лицензий — `/collection?info=true`, указание авторства — `/icon` одной иконки набора. Чистые части — `lib/bag-files.ts`.
- **Проверка** — строка «Сумка» `pnpm site --check`:
  - режим выбора в сетке и поиске, «В сумку» в панели;
  - число в шапке после перезагрузки;
  - меню с клавиатуры, «Убрать», Esc и фокус;
  - ZIP — своим разбором с CRC из `node:zlib`: файлы, полные тексты лицензий как у `/collection?info=true`, README;
  - спрайт — символы, ID и каждая `<use>` рисует;
  - axe с открытым меню в обеих темах, телефон.

  Контрольный запуск добавляет две поломки: сумка не сохраняется в хранилище и ZIP без текстов лицензий.

Уточнение от 3 ноября 2026 (шаг 5 фазы 4) — решения владельца после первого просмотра: сайт прежде всего для дизайнеров, сценарий «нашёл — скопировал — вставил» должен быть самым быстрым и понятным, как у Iconify.

- **«Скопировать иконку»** — главная кнопка сразу под превью, рядом «Скачать SVG» (`components/icon/IconActions.tsx`).
  - Копируется код SVG с настройками: размер в пикселях — родной у сетки набора (24 или 32 px), если его не меняли, цвет, толщина, поворот и отражение (`fileSvg` в `lib/code.ts`).
  - В Figma, Sketch и Illustrator код вставляется вектором.
  - Комментария об авторе в буфере нет: при вставке он мешает. В скачанном файле он остаётся.
- **«Копировать PNG»** — рядом со «Скачать PNG», того же выбранного размера: картинка в буфер, как у Iconify.
- **Имя копируется отдельно** — строка имени под превью (`components/icon/IconName.tsx`):
  - список форматов как у Iconify — меню Radix, немодальное, как меню темы;
  - кнопка «Копировать имя»;
  - формат по умолчанию — набор/иконка, `lucide/house`: так дизайнеры называют компоненты в Figma;
  - выбор запоминается в localStorage (`iconavo-name`).

  | Формат | Пример | Для чего |
  | --- | --- | --- |
  | Набор/иконка (по умолчанию) | `lucide/house` | имя компонента в Figma |
  | Iconavo и Iconify | `lucide:house` | атрибут `icon` тега и React, Iconify |
  | Имя компонента | `LucideHouse` | компоненты по имени (unplugin-icons) |
  | Tailwind CSS | `icon-[lucide--house]` | плагин Iconify для Tailwind |
  | UnoCSS | `i-lucide:house`, `i-lucide-house` | пресет иконок UnoCSS |
  | Только имя | `house` | |
  | Класс CSS | `lucide--house` | классы Iconify |

  Имена наборов и иконок у нас те же, что у Iconify (ADR-0001), поэтому его инструменты понимают все форматы.
- **Буфер обмена** — `lib/clipboard.ts`: запись — `ClipboardItem` прямо в щелчке, данные — обещанием. Иначе Safari отклонил бы запись после ожидания рисунка или canvas.
- **Метки аналитики** (ADR-0043): копирование имени (с форматом), иконки и PNG (с размером).
- **Проверка сайта:**
  - имя по умолчанию `lucide/house`, смена формата и он же после перезагрузки;
  - в Chrome — что лежит в буфере: имя, SVG — побайтно ответ edge API с теми же настройками, PNG последнего размера.

Почему: человек должен забрать иконку в том виде, в котором она нужна его проекту, за один клик.
