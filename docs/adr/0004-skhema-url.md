# ADR-0004. Схема URL

Статус: принято 15 октября 2026 по рекомендации, с опорой на Iconify.

Вопрос: по каким адресам доступны иконки, поиск и MCP?

Решение: API повторяет устройство адресов Iconify API, а статика остаётся версионированной, как в ADR-0006.

| Адрес | Что отдаёт |
| --- | --- |
| `api.домен/{набор}.json?icons=a,b` | Пачку иконок одним ответом |
| `api.домен/{набор}/{иконка}.svg` | Готовый SVG; параметры color, width, height, rotate, flip, box, download |
| `api.домен/{набор}.css?icons=a,b` | CSS-иконки |
| `api.домен/collections` и `/collection?prefix=` | Список наборов и иконки набора |
| `api.домен/search?query=…` | Смысловой многоязычный поиск — ваше отличие |
| `api.домен/last-modified` | Когда наборы менялись в последний раз |
| `cdn.домен/v/{версия}/{набор}/{иконка}.json` и `.svg`, `/manifest.json` | Версионированная статика |
| `cdn2.домен/…` | Копия статики у второго провайдера |
| `mcp.домен` | MCP-сервер |

Параметры SVG повторяют документацию Iconify ([источник](https://iconify.design/docs/api/svg.html)): поворот задаётся как `90deg` или `1`, отражение — `horizontal`, `vertical` или оба через запятую.

Почему: разработчики и ИИ-ассистенты знают адреса Iconify, а совместимые адреса позволяют подключать ваш API привычными инструментами. Версионированная статика остаётся запасным путём, если edge API недоступен.

Последствия: адреса edge API в ADR-0006 приведены к этой таблице.
