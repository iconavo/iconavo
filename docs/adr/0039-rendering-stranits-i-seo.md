# ADR-0039. Рендеринг страниц и SEO

Статус: принято 16 октября 2026 по рекомендации.

Вопрос: как сайт с десятками тысяч страниц остаётся быстрым и находится в поисковиках?

Решение:

- Next.js на Vercel (ADR-0007). Страницы наборов и иконок создаются при первом запросе и кэшируются; после выпуска данных кэш сбрасывается только по изменившимся наборам.
- У каждой страницы иконки свой заголовок, описание из обогащения, канонический адрес и автоматически созданная картинка для соцсетей.
- Карта сайта разбита на файлы по наборам — не больше 50 000 адресов в файле — плюс общий индекс карт.
- Русская и английская версии связаны пометками hreflang, чтобы поисковики показывали нужный язык.
- Страницы результатов поиска не индексируются: у них нет постоянного содержания.
- Бюджет скорости из плана: LCP не больше 2,5 секунды для 75% визитов, Lighthouse не ниже 90.

Уточнение от 29 октября 2026 (шаг 10 фазы 3, [ADR-0050](0050-sayt-dokumentatsii-i-zhivye-primery.md)):

- До запуска 1 июня 2027 сайт скрыт от поисковиков — решение владельца. Метка `noindex, nofollow` стоит и в HTML, и в заголовке `X-Robots-Tag`.
- `robots.txt` обход не запрещает: иначе поисковик не увидел бы саму метку.
- Страницы документации собираются при сборке и статические.
- В фазе 7 нужно сделать вместе: снять метку, сделать карту сайта и канонические адреса.

Уточнение от 30 октября 2026 (шаг 2 фазы 4; решение владельца — пересборка после выкладки):

- **Страницы каталога собираются при сборке и статические**: главная, `/sets`, страницы наборов, `/changelog` и `/licenses` на двух языках. Данные — из edge API (`/collections`, `/collection`, `/changelog`, ADR-0024), поэтому сайт показывает ровно то, что уже выложено на раздачу. Страницы наборов — `generateStaticParams` по `/collections` и `dynamicParams = false`: неизвестный адрес — 404 без запуска функции.
- **О выпуске сайт узнаёт пересборкой.** После каждой успешной «Выкладки» на `main` workflow «Сайт» собирает и выкладывает сайт заново (`workflow_run`, та же защита от запусков из форков, что у поискового индекса, ADR-0049). Пять наборов — минуты сборки, лимит Vercel Hobby — 100 выкладок в сутки.
- **Сброс кэша только по изменившимся наборам** — в шаге 4, когда появятся десятки тысяч страниц иконок: их собирать при каждой выкладке уже долго.
- **Свежесть видна снаружи.** У страницы набора — метка `<meta name="iconavo-version">` с версией данных набора; `pnpm site --live` сверяет её с живым манифестом раздачи (строка «Свежесть данных», ADR-0050).

Уточнение от 2 ноября 2026 (шаг 4 фазы 4) — кэш страниц и сброс по наборам. Решение от 30 октября о пересборке после каждой «Выкладки» заменено: каждая выкладка Vercel начинает с пустого кэша, и выпуск любого набора сбрасывал бы десятки тысяч страниц иконок.

- **Страницы иконок** создаются при первом открытии и хранятся в кэше Vercel (`generateStaticParams() → []`, `revalidate = false`). Страницы каталога по-прежнему собираются при сборке.
- **Метки кэша.** Метку получает каждый запрос сайта к edge API (`fetch` с `next: { tags }`, без `cache`): ответ не ложится в кэш запросов Next.js, который пережил бы выкладки, а метка достаётся странице. Метку выбирает страница, а не адрес:
  - страница набора и страницы его иконок — только `set-{набор}`: выпуск другого набора их не трогает;
  - общие страницы (главная, `/sets`, `/licenses`, `/changelog`, поиск) — только `catalog`, даже когда спрашивают про отдельный набор: иначе у главной было бы по метке на набор, а Vercel и Next.js хранят не больше 128 меток на ответ.

  Метки сверяет строка «Метки кэша» проверки сайта (ADR-0050).
- **Без памяти процесса.** На сервере каждый адрес API — один запрос на сборку страницы (React `cache`), иконки — своим запросом пачки edge API, а не хранилищем ядра. Память процесса тёплой функции Vercel держала бы старые данные после выпуска.
- **`dynamic = "error"` снят** со всех страниц с данными, включая поиск: он кладёт все запросы страницы в кэш запросов навсегда. Статичность страниц проверяет строка «Статичность» проверки сайта.
- **Метки страницы.** У страницы набора и страниц его иконок, кроме версии (`iconavo-version`), есть ещё две метки:
  - `iconavo-content` — отпечаток содержимого набора (`X-Iconavo-Content`, ADR-0022): меняется с любым файлом набора, включая описания в `search.json`;
  - `iconavo-rendered` — время сборки страницы.
- **Как сайт узнаёт о выпуске** — workflow «Сайт» после «Поискового индекса» (ADR-0050):
  - `pnpm site --refresh` сравнивает отпечатки живых страниц наборов с оглавлением каталога раздачи;
  - `vercel cache invalidate --tag catalog,set-{набор}…` сбрасывает устаревшие: посетители получают прежнюю страницу, пока новая собирается (stale-while-revalidate);
  - затем «Свежесть» ждёт свежих страниц до 5 минут.

  Индекс после правки кода поиска или ручного запуска сбрасывает все наборы: описания и похожие могли измениться без выпуска. Новый набор (страницы нет) — обычная выкладка сайта.
- **Выкладка кода** — как раньше: новая выкладка начинает с пустого кэша, страницы иконок соберутся при первом открытии.
- **Квота.** Записи в кэш страниц на тарифе Hobby — 200 тысяч единиц по 8 КБ в месяц. До запуска хватает с запасом; к запуску нужен Pro (фаза 7).
- **Проба пройдена 2 ноября 2026.** Документация Vercel прямо говорит о `cacheTag`, а о метках `fetch` — нет; в сборке метки были (заголовок `x-next-cache-tags` в файлах кэша Next.js). Проверка на живом сайте — ручной запуск «Сайт» со «сбросить все наборы» (запуск 41502484622):
  - Vercel CLI 65.7.0: «Successfully invalidated all cached content associated with tags catalog, set-fluent-emoji-flat, set-lucide, set-material-symbols, set-ph, set-tabler»;
  - через 7 секунд прежними были 11 страниц из 15, через 18 — все: страницы наборов на двух языках, собранные заранее, и страницы первой иконки витрины, собранные по запросу;
  - затем `pnpm site --live` — все строки «да».

  Первый настоящий запуск пути — «Сайт» после «Поискового индекса» 2 ноября 2026: все пять наборов свежие, сбрасывать нечего.

Уточнение от 2 ноября 2026 (шаг 3 фазы 4): страницы поиска не индексируются никогда, и после запуска тоже. У них всегда метка `noindex, nofollow` (`searchMetadata`), а когда сайт откроют поисковикам (`INDEXING`), заголовок `X-Robots-Tag` у `/search` и `/ru/search` останется (`searchRobotsHeaders` в `apps/site/lib/headers.ts`).

Уточнение от 6 ноября 2026 — ИИ-обходчики закрыты до запуска (решение владельца):

- **Что случилось.** Ночью 6 ноября, примерно с 22:00 до 05:00 UTC, GPTBot открыл 33,6 тысячи страниц сайта, почти все — страницы иконок. GPTBot — обходчик OpenAI, который собирает тексты для обучения моделей, он шёл с одного адреса Microsoft Azure. Метку `noindex, nofollow` он не соблюдает, а `robots.txt` пускал всех.
  - Страница иконки собирается при первом открытии, и каждая сборка делает около пяти запросов к edge API: `/icon`, `/collections`, пачки иконок нескольких наборов. По журналу Cloudflare это функции Vercel: адреса Amazon в США, программа `node`.
  - За сутки — около 194 тысяч запросов при лимите бесплатного Workers в 100 тысяч. Примерно с 05:00 UTC Cloudflare отвечал на все адреса `api.iconavo.dev` ошибкой 1027 (ответ 429) — до сброса лимита в 00:00 UTC.
  - Последствия: поиск и панель иконки на сайте не работали, несобранные страницы иконок отвечали 500, проверки двух выкладок наборов покраснели. Ядро пакета, как и задумано, брало иконки со статики.
  - Заодно ушла половина квоты Vercel Hobby на записи в кэш страниц: 113 тысяч из 200 тысяч за 30 дней. Кончится квота — Vercel может остановить сайт до следующего периода.
- **Что сделано.**
  - Правило AI Bots в Firewall Vercel: проект `iconavo-site` → Firewall → Rules → Bot Management. Включено 6 ноября 2026 по решению владельца, работает без выкладки. «Bot Protection» не включали: она мешала бы проверкам сайта из CI.
  - `robots.txt` закрывает сайт известным ИИ-обходчикам: список `AI_CRAWLER_AGENTS` и константа `AI_CRAWLERS = false` в `apps/site/lib/headers.ts`. Поисковикам обход открыт, как раньше: решение от 29 октября о метке noindex не меняется.
  - `pnpm site --live`, строка «robots.txt»: поисковикам обход открыт, ИИ-обходчикам — как велит `AI_CRAWLERS_OPEN` в конфиге проверки.
- **После запуска ИИ-обходчики нужны** — решение владельца: так сайт и иконки попадают в ответы ИИ-ассистентов. Открыть их — пункт чек-листа запуска фазы 7 (`docs/roadmap.md`), вместе со снятием noindex. До этого нужны платный тариф Workers (суточного потолка у него нет) и меньше запросов к edge API со страницы иконки (бэклог). Иначе обход снова упрётся в лимит или в счёт.

Почему: страницы иконок приводят людей из поисковиков, а скорость — часть качества продукта.
