# ADR-0044. MCP-сервер: реализация

Статус: технические части приняты 16 октября 2026 по рекомендации; продуктовая — по умолчанию код с вашим пакетом, чистый SVG по запросу — подтверждена владельцем 17 октября 2026 (отметка в [сводке решений](README.md)).

Вопрос: как устроен MCP-сервер из ADR-0011?

Решение:

- Официальный TypeScript SDK протокола MCP, удалённый доступ по Streamable HTTP на `mcp.домен`.
- Сервер работает на Cloudflare Workers рядом с edge API и обращается к нему напрямую.
- Пять инструментов из ADR-0011 с точными описаниями и схемами ответов — так ассистенты реже ошибаются при вызове.
- `search_icons` возвращает имена, лицензии и одну картинку-сетку с превью найденных иконок: модели со зрением видят результат целиком.
- Без входа и ключей, с лимитами из ADR-0024; ключ — для активного использования.
- Инструменты меняются только с добавлением возможностей, чтобы ничего не ломать у подключённых клиентов.
- Проверка — в MCP Inspector и в реальных клиентах: Claude, ChatGPT, Cursor, Claude Code.

Продуктовое решение — владельца, подтверждено 17 октября 2026: что MCP отдаёт по умолчанию. Рекомендация — код с вашим пакетом, а чистый SVG — по запросу ассистента: так MCP приводит разработчиков к пакету.

Почему: ассистенты должны получать иконки так же надёжно, как сайт, но в удобном для себя виде.

## Уточнение от 19 ноября 2026 — шаг 10 фазы 4, часть 1: сервер и search_icons

Решения владельца 19 ноября 2026:

- новые зависимости: SDK-сервер `@modelcontextprotocol/server` 2.4.0 (с `@modelcontextprotocol/core`) и SDK-клиент `@modelcontextprotocol/client` 2.4.0 — только для проверок;
- `get_icon` по умолчанию отдаёт веб-компонент, React и SVG — по просьбе ассистента;
- Cloudflare Workers — на платном тарифе с 19 ноября 2026 (ADR-0024).

### Как устроено

- **Отдельная функция `iconavo-mcp`** на `mcp.iconavo.dev`, рядом с `iconavo-api`. У каждой своя выкладка: сбой MCP не задевает иконки на сайтах.
- **«Обращается к edge API напрямую»** — внутри MCP работает тот же код, что отвечает на `api.iconavo.dev`, с теми же хранилищами R2 и тем же Meilisearch. MCP не ходит к edge API ни через интернет, ни через привязку функции к функции. Почему:
  - один вызов инструмента — ровно один запрос к Workers: у бесплатного тарифа суточный потолок общий на весь аккаунт, у платного каждый запрос — в счёте;
  - ответы совпадают с сайтом и API;
  - лимит 60 поисков в минуту с адреса API не мешает: у MCP свой лимит, по адресу человека. Пункт бэклога «ключ или обход» закрыт обходом — ключ не нужен (ADR-0049).
- **Код API для MCP** — `createRoutes()` в `apps/api/src/handler.ts`: маршруты и загрузчики без HTTP-обёртки; `createHandler` — маршрутизатор поверх них. Перевод ошибок — `toApiError()`, общий: у MCP те же 400, 404, 429 и 503, только ошибкой инструмента. Поведение API не изменилось.
- **Поиск ждёт смысл.** У поиска API флажок `SearchOptions.waitForModel`: фразы нет в бакете — функция ждёт вектор запроса от Polza (1–2 с) и сразу отдаёт полную выдачу по смыслу, а не слова с пометкой `pending`. Модель не ответила — выдача по словам (`ranking: "words"` в ответе). Ассистенту смысл важнее первых 0,25 с, а ожидание не тратит процессор. Сайт и API флажок не ставят.
- **SDK версии 2**, `createMcpHandler(…, { legacy: "stateless" })`:
  - протокол MCP 2026-07-28 — без рукопожатия и сессий, версия и возможности клиента — в каждом запросе;
  - клиенты 2025 года — запасным путём без состояния; GET и DELETE на `/mcp` — 405;
  - сервер и обработчик SDK собираются заново на каждый запрос: между запросами у функции нет общих обещаний (ADR-0024, 18 ноября 2026); общие у копии только загрузчики API с готовыми значениями;
  - сборка SDK под Workers (условие экспорта `workerd`): проверка схем `@cfworker/json-schema` внутри пакета, без `eval` и модулей Node — это проверяет тест сборки;
  - подписки на изменения списка инструментов не объявлены (`listChanged: false`): список меняется только выкладкой; клиенты протокола 2026 года могут хранить его час (`cacheHints`).
- **Адреса.** `https://mcp.iconavo.dev/mcp` — протокол; `/` — короткая страница для людей (что это и как подключить, метка сборки `X-Iconavo-Build`); `robots.txt` закрывает всё. CORS — для клиентов в браузере. Тело запроса — не больше 64 КБ, пачки сообщений JSON-RPC — 400: один запрос — одно сообщение, иначе один запрос съел бы процессор и обращения к хранилищам за многих.
- **Код** — `apps/mcp/src/`: `index.ts` (точка входа), `http.ts` (адреса, CORS, пачки), `context.ts` (код API с привязками MCP), `server.ts` (сервер и инструкция ассистенту), `tools/search.ts`, `schemas.ts`, `grid.ts`, `digits.ts`, `png.ts`, `wasm.ts`.

### search_icons

- **Вход:** `query` (до 100 знаков, любой язык или точное имя `lucide:house`), `sets`, `style` (шкала ADR-0052), `license`, `limit` — 12 по умолчанию, до 24, `offset`, `preview` — картинка, по умолчанию да.
- **Ответ** — текст для ассистента и данные по схеме (`outputSchema`):
  - каждая иконка: номер в картинке, имя, набор, стиль, тот же рисунок в других стилях, точное ли имя, лицензия (SPDX) и автор;
  - наборы выдачи: автор, лицензия со ссылками, части других авторов (Feather у Lucide) — то же правило, что у `/icon` (`setSummary`);
  - `ranking` — по смыслу или только по словам, `matched` — нашлось ли по словам, `nextOffset` — следующая страница;
  - текст — нумерованный список и блок «Licenses» с указанием авторства: клиенты без данных по схеме видят то же.
- **Картинка-сетка** — одна PNG: клетки 96 px, иконка 48 px по центру, номер — в углу клетки. До 12 иконок — 4 колонки (384 × 288), больше — 6 (до 576 × 384). Цифры — контурами (`digits.ts`): шрифтов resvg в Workers нет, а свой шрифт пришлось бы разбирать при каждой отрисовке. ID каждой клетки — свои (`replaceIds` ядра). Готовая картинка — в кэше дата-центра неделю по именам и версиям наборов: тот же поиск второй раз не рисует.
- **Рисовальщик** — resvg (`@resvg/resvg-wasm` 2.6.2, как у контроля качества, ADR-0016). Модуль wasm (2,4 МБ) уходит в Cloudflare отдельной частью загрузки (`application/wasm`), Workers компилирует его при выкладке, а функция готовит рисовальщик при запуске копии, а не в вызове.

### Успевает ли функция нарисовать сетку

Замер 19 ноября 2026 на компьютере владельца, медиана по 60 повторам (resvg + PNG):

| Сетка | Lucide, Tabler, Material Symbols, Phosphor | Fluent Emoji Flat |
| --- | --- | --- |
| 12 иконок по 48 px (384 × 288) | 4,3–5,0 мс | 6,0 мс |
| 24 иконки по 48 px (528 × 352) | 7,8–9,1 мс | 11,9 мс |

PNG — 12–44 КБ; подготовка рисовальщика — 14 мс, один раз на копию функции. На бесплатном тарифе (10 мс процессора на вызов) 12 иконок помещались, 24 — нет. На платном тарифе предел — 30 с, у MCP свой — 300 мс на вызов (`limits.cpu_ms` в metadata, с запасом на холодный старт копии): страховка счёта от сбоев и перебора. Замер на серверах Cloudflare — `pnpm mcp bench` после первой выкладки (окна времени — для графика CPU Time в панели).

### Лимиты для людей

- Без входа и ключей, как в ADR-0024: `search_icons` — 60 вызовов в минуту с адреса (`MCP_SEARCH_LIMIT`, своё пространство счёта 1003 — поиски на сайте и в ассистенте не делят один счёт); ответы из кэша не считаются. Превышение — ошибка инструмента с текстом «at most 60 per minute… Wait about a minute and try again».
- Claude.ai и ChatGPT обращаются к серверу со своих машин, и все их пользователи делят один адрес (у Anthropic — 160.79.104.0/21). В бете это не мешает; пересмотреть на реальных данных — шаг 12 (бэклог).

### Разовая настройка в панели Cloudflare

Её делает владелец до первой выкладки. Загрузка новых версий домен и выключенный workers.dev не трогает.

1. Workers & Pages → Create → Worker «Hello World», имя `iconavo-mcp` → Deploy.
2. Settings → Domains & Routes → Add → Custom Domain → `mcp.iconavo.dev`. Запись DNS Cloudflare создаёт сам.
3. Там же: workers.dev — Disable, Preview URLs — Disable.

### Сборка, превью, проверка, выкладка

- `pnpm mcp build` — тем же сборщиком, что edge API (`bundleWorker` с целью `MCP_TARGET`, `packages/pipeline/src/mcp/`): `dist-mcp/worker.js`, `resvg.wasm`, `metadata.json` (бакеты `CDN` и `SEARCH`, лимит, предел процессора, журналы без запросов), `build.json`. Метка сборки — SHA-256 бандла, модуля wasm и metadata. Бандл — 842 КБ, в gzip 204 КБ.
- `pnpm mcp preview` — `127.0.0.1:4285/mcp`: бандл в отдельном процессе Node, где, как в Workers, запрещены `eval` и компиляция wasm из байтов; данные — `dist-cdn/`, поиск — Meilisearch и Polza из `.env`.
- `pnpm mcp check [--expect-build=…] [--base=…]` — клиент SDK на обоих протоколах: страница `/`, `robots.txt`, 405, CORS, отказ пачке, переход с http; список инструментов; вызовы `search_icons` — по схеме, по смыслу, лицензия и автор у каждой иконки, картинка нужного размера. Отчёт `.cache/reports/mcp/check.html` — запрос, текст, картинка и данные каждого вызова.
- `pnpm mcp bench` — поиски контрольной части эталона с картинкой и без; окна времени UTC для процессора в панели.
- Workflow «MCP-сервер» (`.github/workflows/mcp.yml`) — как «Edge API»: «Сборка» → «Выкладка» одним `curl -X PUT …/workers/scripts/iconavo-mcp` с тремя частями (`metadata`, `worker.js`, `resvg.wasm`) из окружения `api` (только `main`, те же ключи) → «Проверка» `pnpm mcp check --expect-build`. Запускается push в `main` при правке `apps/mcp`, `apps/api/src`, ядра, общего модуля поиска, кода MCP в конвейере, lock-файла или самого workflow; вручную — «только показ», «выложить заново», «замер». Что функция собирается, на каждом PR проверяет CI (`pnpm mcp build`).
- Журналы — только наши сообщения об ошибках, без журнала запросов и IP (ADR-0028).

## Уточнение от 19 ноября 2026 — шаг 10 фазы 4, часть 3: ещё четыре инструмента

Код для вставки — общий с генератором сайта: модуль `packages/snippets` (часть 2, ADR-0042). Справка для разработчиков — `apps/mcp/README.md`: подключение в Claude, Claude Code, Cursor, VS Code и ChatGPT, инструменты, лимиты, лицензии, приватность.

### get_icon

- **Вход:** `icon` (старые имена тоже), `format` — `html` по умолчанию (веб-компонент, решение владельца), `react` или `svg`; `size` (по умолчанию 24), `color` (только hex: в код не попадёт ничего лишнего), `strokeWidth`, `rotate` (0, 90, 180, 270).
- **Код** — функции генератора сайта: `tagCode`, `reactCode`, для SVG — `svgFile` с комментарием об авторстве первой строкой (`fileComment`) и ссылка на тот же SVG edge API (`svgLink`). Без SVG — строки установки и подключения из README (`setup`).
- **Сведения** — маршрут `/icon` edge API внутри MCP (лимит `MCP_ICON_LIMIT` — 300 в минуту с адреса, пространство 1004): основное имя и пометка старого, «удалена», набор с автором и лицензией, текст указания авторства (`attributionText`), стиль и тот же рисунок в других стилях, оттенки, описание, похожие в том же стиле.
- **Неприменимое отмечается**, а не скрывается: цвет у цветного набора, толщина у иконки без линий.
- **Meilisearch не ответил** — сведения попроще из файла имени и оглавления каталога: код ассистент получит всё равно, без описания и похожих (`details.ts`).

### get_matching_set

- **Вход:** `concepts` — от 2 до 10 понятий на любом языке; `like` — образец, иконка из проекта; `set`, `style`; вид кода — как у `get_icon`.
- **Образец** задаёт набор, стиль и вариант через сведения `/icon`: суффикс образца относительно его карточки (`ph:house-bold` у `ph:house` — `-bold`) ставится каждой иконке, у которой такой вариант или оттенок есть; иначе — главное имя стиля.
- **Без образца** набор — тот, где нашлось больше понятий (при равенстве — где они выше, затем порядок каталога), стиль — у лучших иконок большинства понятий (при равенстве — порядок шкалы ADR-0052).
- **Один вызов — одно обращение к поиску:** векторы понятий — кэш дата-центра и фразы каталога в бакете, недостающие — одним вызовом Polza (`modelVectors` в `apps/api/src/search/vectors.ts`); все понятия — одним multi-search с телами общего модуля и той же долей смысла, что у `/search`; на выбор набора — ещё один. Лимит — один счёт `MCP_SEARCH_LIMIT` на вызов.
- **Ответ** — по понятию иконка, код и две запасные; ненайденные понятия; строки установки; текст указания авторства.

### get_usage

- **Вход:** `framework` — `html` (по умолчанию), `script` (без сборщика), `react`, `next`; `packageManager` — npm, pnpm или yarn.
- **Текст — из README тега дословно** (`usageFromReadme` общего модуля): строки установки, версия пакетов из адреса скрипта, разделы Install, HTML, React, Size and color, A label for screen readers, Next.js and server rendering, License. `pnpm mcp build` вшивает их в функцию модулем без файла (`virtual:iconavo/readme`); нужного раздела нет — «СТОП» сборки. Поэтому `mcp.yml` выкладывает MCP и при правке README.

### list_sets

Наборы из оглавления каталога раздачи (те же данные, что у `/collections` и `/collection?info=true`): название, префикс, число иконок, автор, лицензия со ссылкой, части других авторов, стили в порядке шкалы, цветной ли, сетка, образцы, версия у автора, пометка «можно в коммерческих проектах» и страница набора. Полные тексты лицензий — `licenseText: true`.

### Общее

- Инструкция сервера: обычный путь — `search_icons` → `get_icon` → `get_usage` один раз на проект; несколько иконок в одном виде — `get_matching_set`; лицензию и автора — сказать человеку.
- Все пять инструментов — «только чтение»; лицензия и автор — в каждом ответе.
- `pnpm mcp check` проверяет все пять на обоих протоколах: код — как у генератора сайта, SVG — побайтно как у адреса SVG edge API, `like: ph:house-bold` — только `ph:*-bold`, `list_sets` — пять наборов, лицензия и автор — везде. Проверка идёт и в ежедневной «Сверке хостов» (`verify.yml`): сбой придёт письмом.

### Процессор на Workers

Данные — из панели Cloudflare: Workers & Pages → iconavo-mcp → Metrics. Нагрузку дал замер `pnpm mcp bench` с компьютера владельца, все вызовы шли через Амстердам. Взята минута каждого вида:

| Поиск | Вызовов | Процессор: медиана / 90% / 99% | Память, медиана |
| --- | --- | --- | --- |
| с картинкой-сеткой, 12 иконок | 23 | 55 / 69 / 73 мс | 13 МБ |
| без картинки | 29 | 11,1 / 12,5 / 13,2 мс | 12 МБ |

За первые сутки — 250 вызовов всех инструментов:
- процессор — медиана 9 мс, 90% — 46 мс, 99% — 117 мс, самый тяжёлый — 163 мс;
- память — до 34 МБ из 128;
- ошибок и превышений предела нет.

Выводы:

- **Картинка-сетка на Workers — около 44 мс процессора**, в 8–10 раз дольше, чем в Node на компьютере владельца (4–6 мс). При нынешних объёмах это неважно: в тариф входит 30 млн мс в месяц — около полумиллиона поисков с картинкой, сверх — около цента за 10 000. Ускорение — в бэклоге, если вырастет нагрузка.
- **На бесплатном тарифе (10 мс на вызов) не поместился бы даже поиск без картинки**, так что переход на платный был нужен.
- **Предел MCP 300 мс на вызов** — с запасом почти вдвое.

### Наблюдения

- `get_matching_set` для «profile» в Material Symbols первым взял `lab-profile-outline` (бланк анализов), а `account-box-outline` — только третьей запасной. Как и у «search» в Phosphor, слово в имени перевешивает смысл. Это задача шага 12 — в бэклоге.
- Повтор запроса к edge API не всегда попадает в тот же дата-центр: с компьютера владельца соседние соединения уходили в AMS, LHR и CDG, а кэш у каждого свой. Проверки поиска и сведений об иконке теперь повторяют запрос до трёх раз и называют дата-центры (PR #167).

- **Ресурс** — первый у сервера: шаблон `ui://picker/{version}` со страницей сетки. Возможность `resources` объявлена без `listChanged`, списки ресурсов кэшируются так же, как список инструментов, — час.
- **Общее с `search_icons`**: поиск (`findIcons`), чтение рисунков по каноническим именам (`readIcons`) и картинка-сетка с кэшем на неделю (`gridPreview`) — из `tools/search.ts`; лимит — тот же счёт `MCP_SEARCH_LIMIT`, 60 поисков в минуту. Поведение `search_icons` не изменилось.
- **Код для вставки** — чистая часть `code.ts` переехала в `packages/snippets/src/look.ts`: её берёт и сетка в браузере, и `get_icon`, поэтому код из сетки побайтно совпадает с `get_icon`. В `apps/mcp/src/code.ts` осталась схема полей zod и адрес edge API.
- **Инструкция сервера**: когда человек хочет выбрать сам или посмотреть варианты — `pick_icon`.
- **Сборка**: страница сетки вшита в функцию модулем без файла `virtual:iconavo/picker`; функция — 1,2 МБ, в gzip 293 КБ, из них страница — 72 КБ. В `build.json` — версия и размер страницы.
- **`pnpm mcp check`** — шесть инструментов, `pick_icon` на обоих протоколах и строка «сетка выбора»: ресурс, его версия и код выбора как у `get_icon`.

## Уточнение от 20 ноября 2026 (второе) — формат css и сетка по умолчанию

По проверке сетки владельцем в Claude и ChatGPT (ADR-0045, второе уточнение того же дня):

- **Формат `css`** у `get_icon`, `get_matching_set` и `pick_icon` — новое значение, изменение только добавлением.
  - Это CSS-класс с иконкой-маской (у цветных наборов — картинкой фона) и элемент `<span>` с ним, как вид «CSS» панели сайта.
  - Рисунок нужен, как у `svg`; установки нет.
  - Код класса — в общем модуле `packages/snippets/src/code.ts`, вывод панели сайта прежний.
- **Инструкция сервера и описания:** человек просит найти, показать или выбрать иконку — сразу `pick_icon`. `search_icons` и `get_icon` — когда ассистент выбирает сам, например в коде интерфейса. Причина: Claude сначала отвечал текстом через `search_icons` и только потом предлагал сетку.
- **`pnpm mcp check`** — ещё `get_icon` с форматом `css` и толщиной линии.

## Уточнение от 20 ноября 2026 (третье) — шаг 12 фазы 4: проверка в клиентах

Шаг принят владельцем 20 ноября 2026 (PR #174, #175). Отчёт со всеми сценариями — [docs/eval/mcp-clients.md](../eval/mcp-clients.md).

- **Клиенты** — Claude (claude.ai и Desktop), ChatGPT и Claude Code. Cursor не проверялся: у владельца его нет (решение владельца).
- **Итог.** 20 сценариев на русском и английском, порог — не меньше 18 из 20:
  - Claude — 18;
  - ChatGPT — 18;
  - Claude Code — 19, автопрогон на Sonnet 5.5.
- **Автопрогон Claude Code** — `pnpm mcp clients` (`packages/pipeline/src/mcp/clients*.ts`), только локально, по подписке владельца:
  - каждый сценарий — свежий `claude -p` в чистой папке вне репозитория (иначе он прочитал бы наш CLAUDE.md), только с нашим сервером;
  - без настроек, плагинов, памяти и коннекторов владельца; из окружения убраны переменные Claude Code этой сессии, в том числе максимальные усилия;
  - первое событие запуска сверяется: вход по подписке, один сервер, только встроенные плагины;
  - в «найти» прогон отвечает номером подходящей иконки, как человек;
  - проекты на HTML и React собираются и открываются в Chrome.
- **Описания по ошибкам ассистентов (PR #175):**
  - иконка в любом виде — веб-компонент, React, SVG или CSS-класс — берётся из этих инструментов, а не рисуется самому: на CSS-класс без слова «Iconavo» все три клиента рисовали иконку по памяти;
  - эмодзи — стиль `"color"`, набор Fluent Emoji Flat: ChatGPT не находил эмодзи;
  - `get_matching_set` — отвечать кодом каждой иконки, установкой и лицензией: Claude отдал одни иконки.
- **Claude Code показывает модели не текст ответа инструмента, а `structuredContent` строкой JSON.** Текстовые подсказки до модели не доходят. Пока ассистент справляется по данным; подсказки в данных — бэклог.
- **Лимиты:**
  - общий адрес Claude.ai и ChatGPT остаётся до беты: за проверку лимит не сработал ни разу;
  - живая проверка `pnpm mcp clients --limits` готова, но не прогонялась — ошибку с подсказкой проверяют тесты.
