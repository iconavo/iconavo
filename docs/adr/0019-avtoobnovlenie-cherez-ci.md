# ADR-0019. Автообновление через CI

Статус: технические части приняты 15 октября 2026 по рекомендации, продуктовая часть подтверждена владельцем: лично одобряются скрытия, переименования и смена лицензии.

Вопрос: как наборы обновляются без ручной работы и без риска сломать опубликованные данные?

Решение:

- GitHub Actions раз в сутки, в 03:00 UTC, проверяет версии источников. Iconify обновляет наборы несколько раз в неделю ([источник](https://github.com/iconify/icon-sets)), ежедневная проверка не хуже.
- Изменения приходят только через pull request с журналом и ссылкой на отчёт контроля качества; напрямую в основную ветку ничего не попадает.
- Автоматически сливается PR, в котором иконки только добавлены или изменены, а все проверки зелёные.
- PR со скрытием или переименованием иконок, сменой лицензии или ошибками контроля ждёт вашего одобрения.
- Ключи для обогащения и публикации хранятся в секретах GitHub, у задач — минимальные права.

Продуктовое решение — за вами: что вы одобряете лично. Рекомендация — скрытия, переименования и смену лицензии; всё остальное идёт автоматически.

Уточнение от 20 октября 2026 (шаг 8 фазы 1): скрытия и переименования видны по последнему выпуску в `data/{набор}/changelog.json` (функция `needsApproval`), а в `CHANGELOG.md` они идут отдельным блоком «Требуют вашего одобрения» (ADR-0018). Смену лицензии и так останавливает сборка, пока владелец её не подтвердит (ADR-0017).

Уточнение от 20 октября 2026 (шаг 9 фазы 1): как устроен робот обновления.

- **Расписание и запуск.**
  - Робот — `.github/workflows/update.yml`, запускается в 03:17 UTC: в начале часа очередь расписаний GitHub перегружена.
  - Его можно запустить и вручную: Actions → «Обновление наборов» → Run workflow.
  - Для каждого набора: `pnpm sources pin`. Если версия не та, что в main, — `pnpm sources fetch` и `pnpm data`, затем `pnpm pr` решает и пишет текст PR, и робот открывает PR из ветки `auto/{набор}`.
- **Отдельный PR на каждый набор** (решение владельца): безопасные сливаются сами, а PR, который ждёт одобрения или остановлен, не задерживает другие наборы.
- **Кто открывает PR.**
  - Приложение GitHub организации iconavo, секреты `UPDATE_APP_CLIENT_ID` и `UPDATE_APP_PRIVATE_KEY` (решение владельца).
  - С июня 2026 PR от стандартного токена GitHub Actions ждут ручного разрешения на запуск проверок, а проверки из ручного запуска защита main не засчитывает.
  - Токен приложения выпускается только для записи, уже после обработки чужих SVG.
  - Без приложения, вне main и на PR, которые меняют робота, работает только показ.
- **Решение и метки.**
  - «сольётся сам» (метка «автообновление»): иконки только добавлены или изменены, или изменилась только версия источника.
  - «нужно одобрение» — любое из:
    - скрытия или переименования;
    - новые находки контроля качества (почти пустые, обрезанные, отличаются от оригинала) у добавленных, изменённых, вернувшихся и переименованных иконок;
    - иконки, исключённые при очистке;
    - версия пакета npm стала меньше;
    - новая лицензия — если это единственная причина «СТОП».
  - «проблема»: сборка остановилась по другой причине, например из-за пустых иконок. В PR только `sources.lock.json`, проверка «Данные» красная, слить нельзя.
  - PR, которые ждут человека, приходят владельцу запросом на ревью.
- **Новая лицензия подтверждается в ветке PR робота.** Владелец читает текст, а Claude вписывает отпечаток в `sources/{набор}.ts` прямо в эту ветку и пересобирает `data/`. Ветку с коммитом человека робот больше не трогает.
- **Закрытый без слияния PR — отклонённая версия.** Робот её больше не предлагает, а следующую предложит. Метка версии — скрытый комментарий в начале описания PR.
- **Пока PR открыт, робот раз в сутки пересобирает его от свежего main.**
  - Дата ожидающего выпуска берётся из журнала в ветке PR. Если результат тот же, ветка не меняется.
  - Если в main уже последняя версия, робот закрывает свой PR.
  - Если у PR красные проверки, робот ставит метку «проблема» и зовёт владельца.
- **Сводка и отчёты.**
  - Сводку сборки для машины — `.cache/reports/data/summary.json` — пишет каждый `pnpm data`.
  - Отчёты «что изменилось», «контроль качества» и «лицензия и теги» — артефакты запуска. Они открываются в браузере и хранятся 90 дней; ссылки на них — в описании PR.
- **Где смотреть результаты:**
  - Actions → «Обновление наборов» → запуск, внизу по строке на набор;
  - список PR с меткой «автообновление»;
  - письма о новых PR, запросах на ревью и упавших запусках.
- **Ограничение GitHub:** расписание в открытом репозитории выключается после 60 дней без активности.

Почему: рутина уходит машине, а решения, которые меняют то, что видят пользователи, остаются за человеком.
