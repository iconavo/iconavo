# ADR-0017. Метаданные и лицензии

Статус: технические части приняты 15 октября 2026 по рекомендации, продуктовые ждут вашего подтверждения.

Вопрос: откуда берутся сведения об авторах, лицензиях, тегах и категориях и как они проверяются?

Решение:

- Лицензия набора хранится полностью: SPDX-идентификатор из пакета автора, текст LICENSE, файл NOTICE (если есть), ссылка на источник и коммит.
- При первом добавлении набора лицензию подтверждает человек. Дальше конвейер останавливается, если она изменилась у автора.
- Автор, ссылка и признак цветного набора записываются в `info.json`, как у Iconify.
- Теги и категории авторов импортируются как есть — до очистки SVG, если лежат прямо в файлах. Они приводятся к строчным буквам, дубли удаляются.
- Если тегов нет, базовые берутся из частей имени, остальное добавляет обогащение (ADR-0020).

Продуктовые решения — за вами:

- Категории на сайте. Рекомендация: на старте показываем авторские категории каждого набора, а единые категории для всех наборов — кандидат в фичи фазы 4.
- Образцы для витрины набора. Рекомендация: шесть иконок выбираются автоматически, вы можете заменить их вручную.

Уточнение от 20 октября 2026 (шаг 7 фазы 1):

- **Файлы.** `pnpm data` пишет рядом с `icons.json` ещё `info.json`, `metadata.json`, `search.json` и `LICENSE`, а `NOTICE` — только если он есть у автора. Набор со «СТОП» не записывает ни одного файла.
- **Откуда теги и категории.** В самих SVG тегов нет ни у одного из пяти наборов, поэтому правило «до очистки SVG» не понадобилось. Формат метаданных автора называет поле `metadata` в конфиге набора.

  | Набор | Теги | Категории |
  | --- | --- | --- |
  | Lucide | `icons/{имя}.json` рядом с иконкой | слаги оттуда же, названия — в `categories/{слаг}.json` |
  | Tabler | `icons.json`, запись по базовому имени | `category` там же |
  | Phosphor | массив иконок в модуле `dist/index.mjs`: модуль не запускается, его текст переводится в JSON | `categories`, от одной до четырёх на иконку |
  | Fluent Emoji Flat | `keywords` в `assets/{эмодзи}/metadata.json`, общие для всех оттенков кожи | `group` |
  | Material Symbols | в пакете нет: теги из частей имени | нет |

  - У Material Symbols полные теги и категории есть только по живому адресу Google. Его нельзя закрепить по версии, поэтому по ADR-0012 он не подходит. Вернуться к вопросу после первого замера поиска на шаге 12.
- **Теги.** Строчными буквами, без пробелов по краям и без повторов, в порядке автора.
  - Числа становятся строками. Служебные пометки Phosphor `*new*` и `*updated*` отбрасываются.
  - У Tabler `null` в тегах становится словом «null»: это синоним нуля, который YAML превратил в пустое значение.
  - Теги из частей имени — имя без суффикса варианта, разделённое по дефисам: `arrow-back-ios-new-outline-rounded` даёт arrow, back, ios, new.
  - У вариантов теги базовой иконки: `ph:house-bold` и `tabler:heart-filled` берут записи `house` и `heart`.
- **Категории — как у автора** (решение владельца): «Animals & Nature», «arrows». Единый вид на сайте задаст вёрстка. Строчными становятся только теги.
- **Лицензия.**
  - Разрешены MIT, ISC и Apache-2.0. Другая лицензия в конфиге — ошибка, новую добавляют только отдельным решением.
  - У пакета npm SPDX сверяется с `package.json` автора, при расхождении — «СТОП».
  - Подтверждение — поле `license.confirmed` в конфиге набора: SHA-256 от SPDX, текста LICENSE и текста NOTICE с переводами строк LF. Нет поля — «СТОП, лицензия не подтверждена»; не совпадает — «СТОП, лицензия изменилась у автора».
  - Отпечаток вписывается только после явного «подтверждаю» владельца, который прочитал полный текст на странице `metadata.html`.
  - В `info.json` — SPDX, название как у Iconify (MIT, ISC, Apache 2.0), ссылка на spdx.org, полный текст, NOTICE, источник (репозиторий или страница пакета npm) и версия или полный хэш коммита.
  - NOTICE ищется в корне источника: `NOTICE`, `NOTICE.txt`, `NOTICE.md`.
  - LICENSE у Lucide — это ISC и раздел MIT (Cole Bemis, Feather) для иконок, пришедших из Feather. SPDX у автора — ISC, текст хранится целиком.
- **Автор** — как у Iconify: Lucide Contributors, Paweł Kuna, Google, Phosphor Icons, Microsoft Corporation.
- **Витрина** (решение владельца) — одни и те же понятия во всех наборах: дом, поиск, настройки, пользователь, сердце, звезда.
  - Для каждого понятия берётся первое имя из списка, которое есть в наборе.
  - Если понятий не хватило, недостающие иконки добираются в постоянном порядке по хэшу имени.
  - Поле `samples` в конфиге набора заменяет витрину вручную.
- **Карта вариантов** — поле `suffixes` в конфиге, оно попадает в `metadata.json` (ADR-0002).
- **Правило 1%.** «СТОП», если в наборе с метаданными автора больше 1% иконок остались без тегов автора: значит, сломался разбор формата.
- **Первый прогон.**
  - Лицензии пяти наборов подтверждены владельцем 20 октября 2026. NOTICE нет ни у одного набора.
  - Теги автора есть у всех иконок четырёх наборов: Lucide — 1 891 иконка и 42 категории, Tabler — 6 238 и 41, Phosphor — 9 072 и 18, Fluent Emoji Flat — 3 145 и 9.
  - У Material Symbols у всех 15 756 иконок теги из частей имени, категорий нет.
  - `icons.json` не изменились.
  - `data/` выросла примерно с 24 до 32 МБ, почти всё — `search.json` (6,6 МБ).
  - Проверено на поломках: изменённый текст LICENSE Lucide и пустой `icons.json` Tabler остановили наборы.

Почему: лицензия — юридическая основа каждого пакета, а теги — сырьё для поиска.
