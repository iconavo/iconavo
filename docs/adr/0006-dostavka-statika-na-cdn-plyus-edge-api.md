# ADR-0006. Доставка: статика на CDN плюс edge API

Статус: принято 15 октября 2026.

Вопрос: как данные иконок попадают на сайты пользователей так же быстро и гибко, как у Iconify, но без сервера, падение которого гасит иконки у всех?

Варианты:

1. Динамический API-сервер. Гибко, но сервер работает круглосуточно, его нужно мониторить, и он — единая точка отказа.
2. Только статика на CDN. Быстро и надёжно, но нет пачек, SVG с параметрами и CSS.
3. Статика плюс edge-функции на серверах CDN. Гибкость API при надёжности статики.

Решение: вариант 3, адреса — по ADR-0004.

| Адрес | Что отдаёт | Где работает |
| --- | --- | --- |
| `cdn.домен/v/{версия}/{набор}/{иконка}.json` и `.svg` | Данные иконки и готовый SVG | Статика |
| `cdn.домен/manifest.json` | Текущие версии наборов | Статика, короткий кэш |
| `api.домен/{набор}.json?icons=…` | Пачку иконок одним ответом | Edge |
| `api.домен/{набор}/{иконка}.svg?color=…&width=…&rotate=…&flip=…` | SVG с параметрами | Edge |
| `api.домен/{набор}.css?icons=…` | CSS-иконки | Edge |
| `api.домен/search?query=…` | Результаты поиска | Edge, дальше сервис поиска |

Почему: edge даёт ту же гибкость, что динамический API, а при сбое функции ядро пакета берёт файлы со статики напрямую.

Последствия:

- Edge-слой делается в фазе 2, а не после запуска.
- Имена в пачке сортируются, ответы edge кэшируются на CDN.
- Ядро пакета в фазе 3 запрашивает пачки через edge, а при его недоступности — поштучно со статики.
- Основной CDN должен поддерживать edge-функции; второй хост может отдавать только статику.
