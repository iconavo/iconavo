# ADR-0031. Рендер и доступность

Статус: технические части приняты 16 октября 2026 по рекомендации, с опорой на Iconify; продуктовые ждут вашего подтверждения.

Вопрос: как ядро рисует иконку и как с ней работают скринридеры?

Решение:

- Высота по умолчанию 1em — иконка растёт вместе с текстом, ширина считается по пропорции. Явные размеры задаются атрибутами width и height.
- Цвет наследуется от текста через currentColor, атрибут color — для удобства.
- Повороты (`90deg` или 1–3) и отражения (horizontal, vertical) делаются внутри SVG с изменением viewBox, а не CSS-трансформацией. Сначала отражение, потом поворот — как у Iconify ([источник](https://iconify.design/docs/iconify-icon/)).
- ID масок и градиентов уникализируются при каждой отрисовке, поэтому одна иконка может стоять на странице сколько угодно раз.
- По умолчанию иконка декоративная и скрыта от скринридеров (`aria-hidden`). С атрибутом label она получает роль изображения и подпись.
- Атрибут inline выравнивает иконку по строке текста.

Продуктовые решения — за вами:

- Состояние загрузки — ваше решение: есть и скелетон, и спиннер. По умолчанию показывается скелетон точного размера, спиннер включается атрибутом или общей настройкой. Индикатор появляется, только если загрузка длится дольше 150 мс, и без анимации у тех, кто отключил её в системе.
- Состояние ошибки. Рекомендация — в рабочей версии пустое место и одно предупреждение в консоли, в режиме разработки — пунктирная рамка, чтобы разработчик сразу заметил опечатку в имени.

Почему: поведение привычно разработчикам, знакомым с Iconify, а доступность включена по умолчанию.
