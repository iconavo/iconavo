# ADR-0027. Поисковый сервис

Статус: принято 16 октября 2026 по рекомендации; детали подтверждаются замером прототипа.

Вопрос: как прототип поиска из фазы 1 становится сервисом для сайта, пакета и MCP?

Решение:

- Meilisearch Cloud (ADR-0007), один индекс: документ — базовая иконка со списком своих вариантов (ADR-0002).
- Поля: части имени, теги, описания и синонимы на русском и английском, набор, стиль, цветность, лицензия. Фильтры — по набору, стилю, цветности и лицензии.
- Векторы иконок приходят из конвейера (ADR-0010). Вектор запроса считается той же моделью — средствами Meilisearch или в edge-функции, смотря что окажется проще после прототипа.
- Доля смысловой части в гибридном поиске подбирается по эталону (ADR-0021).
- Индекс обновляется после каждого выпуска данных, только изменившимися документами по отпечаткам. Полная переиндексация — только при смене модели эмбеддингов.
- Браузеры не обращаются к Meilisearch напрямую: запросы идут через `api.домен/search`, где работают кэш и лимиты. Ключ администратора хранится только в секретах CI.
- Если сервис эмбеддингов недоступен, поиск откатывается на текстовую часть, а не возвращает ошибку.

Почему: поиск — главная фича, поэтому он должен оставаться быстрым и предсказуемым даже при сбоях отдельных частей.
