# ADR-0045. MCP Apps: выбор иконки в чате

Статус: технические части приняты 16 октября 2026 по рекомендации; продуктовая — сетка выбора из 12 вариантов со стилем, цветом и кнопкой «Выбрать» — подтверждена владельцем 17 октября 2026, визуал — по его макетам после прототипа (ADR-0038; отметки в [сводке решений](README.md)). Как сделано — уточнение от 20 ноября 2026 ниже (шаг 11 фазы 4); сетка после проверки владельцем в Claude и ChatGPT — второе уточнение того же дня: без стиля, с толщиной линии и форматом кода. Шаг 11 принят владельцем 20 ноября 2026: сетка работает в Claude и ChatGPT (PR #169, #171).

Вопрос: как человек выбирает иконку прямо в разговоре с ассистентом?

Решение:

- Шестой инструмент `pick_icon` объявляет интерфейс — ресурс `ui://picker` по спецификации MCP Apps ([источник](https://github.com/modelcontextprotocol/ext-apps)).
- Клиент показывает сетку прямо в чате, в защищённой рамке. Клик по иконке возвращает выбор ассистенту, и он вставляет код.
- Интерфейс собирается на SDK `@modelcontextprotocol/ext-apps`. Для Claude Code в том же репозитории есть готовые навыки `create-mcp-app` и `add-app-to-server`.
- Такие интерфейсы показывают Claude, ChatGPT, VS Code и другие совместимые клиенты. Где поддержки нет, ассистент получает обычный ответ с картинкой-превью.
- Стили сетки берутся из дизайн-токенов сайта (ADR-0038).

Продуктовое решение — владельца, подтверждено 17 октября 2026: сетка выбора. Рекомендация — 12 вариантов, переключатель стиля, предпросмотр в выбранном цвете и кнопка «Выбрать»; визуал — по вашим макетам.

Почему: ИИ часто берёт не ту иконку, а выбор человеком прямо в чате решает эту проблему за один клик.

## Уточнение от 20 ноября 2026 — шаг 11 фазы 4: как сделано

### Решения владельца 20 ноября 2026

- **После «Выбрать»** — короткое сообщение в чат от имени человека («Выбрана иконка lucide:share-2 · Контур · #E11D48») и тихая передача кода, автора и лицензии в контекст ассистента. В Claude сообщение подтверждают одним щелчком: так устроен Claude.
- **Карточки без выбранного стиля** приглушены и недоступны, но стоят на своих местах: сетка не прыгает. Заново не ищем.
- **Шрифт — шрифт чата.** Рамка клиента по умолчанию не пускает внешние шрифты; цвета, радиусы и размеры — токены сайта.
- **Вид сетки** утверждён по странице просмотра `pnpm mcp picker` до подключения к серверу: номера на карточках остаются, готовых образцов цвета нет.

### Как устроено

- **Инструмент `pick_icon`** (`apps/mcp/src/tools/pick.ts`) ищет тем же поиском, что `search_icons` (`findIcons`), всегда 12 вариантов, и тот же лимит 60 поисков в минуту. Вход — как у поиска (`query`, `sets`, `style`, `license`) плюс вид кода `format` и `size`, как у `get_icon`, и начальный `color`. Толщины линии в первой версии нет.
- **В ответе три части:**
  - текст и одна PNG-картинка-сетка — модели и клиентам без MCP Apps: там ассистент просит назвать номер и вызывает `get_icon`;
  - `structuredContent` — карточки с лицензией и автором, как у `search_icons`;
  - `_meta["iconavo.dev/picker"]` — данные сетки. По спецификации `_meta` не для модели: её не засоряют рисунки.
- **Данные сетки** (`packages/snippets/src/picker.ts`, номер формата 1): карточки с каноническими именами в каждом стиле (старое имя раскрывается, как у `/icon`), рисунки всех стилей (12 карточек × до 4 стилей; обычно 15–60 КБ, у эмодзи до 250 КБ), наборы с автором и лицензией, части от других авторов (Feather у Lucide), строки установки из README тега, адреса edge API и сайта.
- **Код считает сама сетка** теми же функциями, что `get_icon`: чистая часть генератора переехала в общий модуль (`packages/snippets/src/look.ts`), а тесты и `pnpm mcp check` сверяют код выбора с ответом `get_icon` побайтно. Поэтому «Выбрать» не ходит к серверу и работает, даже если клиент не пускает вызовы инструментов из рамки.
- **Что получает ассистент** (`pickerContext`, `pickerMessage`): в контекст (`updateModelContext`) — имя, стиль, цвет, код, строки установки, текст указания авторства и страница иконки, текстом и данными; затем сообщение в чат (`sendMessage`) на языке чата. Клиент не принял контекст — сообщение просит взять код у `get_icon`; код в сообщение не идёт: у Claude там предел 8 000 знаков, а SVG эмодзи бывает до 21 КБ. Сообщения не поддерживаются — сетка просит сказать имя ассистенту.
- **Интерфейс — шаблон ресурса `ui://picker/{version}`**, версия — 8 знаков SHA-256 страницы. Клиенты могут хранить интерфейс у себя, и новая сборка получает новый адрес. Старый адрес отдаёт текущую страницу: список инструментов клиент хранит до часа. Не версия — «ресурса нет». У содержимого `_meta.ui.prefersBorder: true`, доменов в политике нет: сетке не нужна сеть.
- **Регистрация — всегда.** Сервер собирается на каждый запрос и не знает, умеет ли клиент MCP Apps; спецификация советует отдавать такому клиенту обычный инструмент. Инструмент — `registerAppTool` SDK (адрес интерфейса и прежний плоский ключ `ui/resourceUri`), ресурс — шаблон SDK сервера: `registerAppResource` принимает только постоянный адрес. Возможность `resources` без `listChanged`, подсказки кэша — как у списка инструментов.
- **Вид** (`apps/mcp/src/picker/`): `App` SDK MCP Apps, обработчики — до `connect()`; разметка через DOM, рисунки — `renderIcon` ядра со своим префиксом ID у каждой карточки; карточки — группа радиокнопок со стрелками, Home и End; без хранилищ браузера: в рамке без своего адреса они недоступны. Тема и язык — из контекста клиента. Переменные оформления клиента не подставляются: их имена совпадают с токенами сайта (`--color-text-primary` и другие) и затёрли бы их; берётся только шрифт. zod внутри SDK получает настройку «без eval» до своей загрузки (`jitless.ts`): SDK отключает пробу позже, чем zod её делает, и строгая политика рамки писала нарушение.
- **Сборка без Vite** (`packages/pipeline/src/mcp/picker-build.ts`): навыки MCP Apps советуют Vite, но rolldown уже собирает функции и скрипт тега. Вид собирается для браузера в один модуль, токены переносятся из блока `@theme` `apps/site/app/globals.css`, всё встроено в одну страницу: один `<style>` и один `<script>` — их число сборка проверяет. 272 КБ, в gzip 72 КБ; бюджет — 80 КБ (`PICKER_GZIP_BUDGET`). Готовая сборка SDK со всеми зависимостями была бы около 129 КБ. Страница попадает в функцию модулем без файла `virtual:iconavo/picker`, как README; кода вида в самой функции нет — это сверяет тест.
- **Новая зависимость** — `@modelcontextprotocol/ext-apps` 2.0.4 (MIT): в `apps/mcp` и в конвейере для страницы-хоста. В функцию попадает только его серверная часть — 561 байт без своих зависимостей. Обязательные соседи SDK — клиент и ядро SDK MCP 2.4.0 — стали dev-зависимостями `apps/mcp`, новых пакетов не добавив; новый в lock-файле — только `@standard-schema/spec` (MIT, типы).

### Просмотр и проверки

- **`pnpm mcp picker`** — страница просмотра на `http://127.0.0.1:4286`: шесть сценариев из `data/` (порядок карточек — как ответил живой поиск 20 ноября 2026) в рамках со строгой политикой спецификации, хост — `AppBridge` SDK, под рамкой — что получил ассистент. Рамки за краем экрана Chrome не рисует и не меряет, поэтому проверка открывает сценарии по одному (`?only=…`).
- **`pnpm mcp picker --check`** — Chrome, Firefox и WebKit (`picker-check.ts`): рисунки, тема и язык, стиль без сдвигов, цвет только монохромным, «Выбрать» — что ушло ассистенту, ровно как считает общий модуль, клавиатура, клиент без сообщений, пустая выдача, высота рамки, ноль нарушений политики и ошибок, axe в обеих темах и контрольный запуск: нет данных, нет токенов, чужая картинка, кнопка без подписи — каждую поломку замечает своя строка. В CI — шаг задачи `browser`, отчёт — артефакт `picker-…html`. С `--base=` — страница и ответы живого сервера.
- **`pnpm mcp check`** — шесть инструментов, вызов `pick_icon` на обоих протоколах (12 вариантов, картинка 384 × 288, данные сетки) и строка «сетка выбора»: адрес у инструмента, шаблон, чтение, MIME, версия — отпечаток страницы, код выбора — как у `get_icon`.
- **MCP Inspector** сетку не рисует: в нём видно инструмент, ресурс и картинку; саму сетку — страница просмотра и клиенты (Claude, ChatGPT).

## Уточнение от 20 ноября 2026 (второе) — сетка после проверки в Claude и ChatGPT

### Что показала проверка

Владелец проверил живую сетку в обоих клиентах в тот же день.

- **Claude** сначала ответил текстом через `search_icons` и только потом предложил сетку. После «Выбрать» сообщение «Picked … · Filled.» встало в поле ввода: дописать можно, но код всё равно пришлось просить вторым запросом. Сетка при этом написала «Tell the assistant …», хотя сообщение уже было в поле.
- **ChatGPT** показал сетку сразу, но после «Выбрать» сам отправил «Выбрана иконка …». Дописать «дай код» было нельзя, и ассистент кода не дал. Сетка в ChatGPT была по-русски.

### Решения владельца 20 ноября 2026

- **Без переключателя стиля, заголовка «12 icons for …» и подсказки «Tell the assistant …».** Карточка показывает иконку в том стиле, в котором она нашлась. Это заменяет решение выше о приглушённых карточках.
- **Цвет остаётся, добавлена толщина линии** — как в панели сайта.
- **Формат кода выбирается в сетке, как в панели сайта:**
  - «SVG and CSS» — SVG, SVG+CSS, CSS;
  - «Components» — HTML, React, Vue, Svelte, Solid, Astro.

  Работают SVG, CSS, HTML и React. SVG+CSS, Vue, Svelte, Solid и Astro — «Soon», как на сайте: заработают в сетке, когда появятся на сайте.
- **Select сразу просит код выбранного формата** — без второго запроса.
- **Всё по-английски** — и сетка, и сообщение в чат, на любом языке чата.
- **Вид утверждён** по странице просмотра `pnpm mcp picker` в тот же день.

### Как устроено

- **Сетка сверху вниз:**
  1. 12 карточек;
  2. Color и Stroke width;
  3. две группы кнопок формата;
  4. набор, лицензия и автор выбранной иконки и кнопка Select.
- **Color и Stroke width:**
  - толщина — ползунок 0,5–3 с шагом 0,25 и подписью «2 px», как у поля толщины панели;
  - толщина меняет превью только линейных иконок (`hasStrokeWidth` ядра);
  - поле цвета скрыто, если все наборы выдачи цветные, толщины — если линейных иконок нет.
- **Кнопки «Soon»** — с `aria-disabled` и подсказкой при наведении и фокусе: их видно с клавиатуры, выбор они не меняют.
- **Начальные значения:** кнопка формата — `format` из входа `pick_icon` (по умолчанию HTML), цвет — `color`.
- **Кнопка Select** после отправки становится «Selected» и неактивна, пока человек не поменяет иконку, формат, цвет или толщину.
- **Для экранных дикторов** — невидимые заголовок «Pick an icon» и объявление «Sent to the chat». Видимых текстов три: пустая выдача, ошибка и подсказка у запасной картинки.
- **После Select ассистент получает две вещи:**
  - **в контекст** — код выбранного формата с цветом и толщиной, строки установки (у HTML и React), указание авторства, страницу иконки и просьбу ответить этим кодом;
  - **в чат** — просьбу по-английски: «Use lucide:house (Lucide, outline, #E11D48, stroke 1.5) — give me the React code.» ChatGPT отправляет её сразу, Claude кладёт в поле ввода.

  Клиент не принял контекст — к просьбе добавляется вызов `get_icon` с теми же настройками.
- **Формат `css`** — новое значение у `get_icon`, `get_matching_set` и `pick_icon` (изменение только добавлением). Это CSS-класс с иконкой-маской (у цветных — картинкой фона) и элемент `<span>` с ним — вид «CSS» панели сайта.
  - Код класса переехал с сайта в общий модуль `packages/snippets/src/code.ts`: `cssClassCode`, `cssSpanCode`, `svgDataUrl`, `pixelBox`.
  - Вывод панели сайта прежний — его держит `panel-code.test.ts`.
- **Описания инструментов и инструкция сервера:** человек просит найти, показать или выбрать иконку — сразу `pick_icon`. `search_icons` и `get_icon` — когда ассистент выбирает сам, например в коде интерфейса.
- **Данные сетки — прежние, формат 1.** Новое только значение `format: "css"`: сетка прежней версии из кэша клиента его не знает и покажет картинку-сетку со списком.
- **Размер страницы** — 268,5 КБ, в gzip 70,9 КБ из 80.

### Проверки

- **`pnpm mcp picker --check`:**
  - строка «Стиль» заменена строками «Формат кода, Soon неактивны» и «Толщина линии — только линиям»;
  - «Тема и язык» стала «Тема чата, всё по-английски»: в русском чате сетка английская;
  - Select — HTML, React со своим цветом и CSS с толщиной: ушло ровно то, что считает общий модуль, кнопка — «Selected»;
  - «Клиент без сообщений» — ничего не ушло, кнопка — «Selected».

  20 ноября 2026 — все строки «да» в Chrome, Firefox и WebKit.
- **`pnpm mcp check`** — ещё `get_icon` с форматом `css`.
- **Тесты** — код выбора в сетке побайтно как у `get_icon` во всех четырёх форматах, со своим цветом и толщиной.
