# ADR-0010. Обогащение и эмбеддинги в конвейере

Статус: принято 15 октября 2026, модель эмбеддингов выбирается по эталону.

Вопрос: откуда поиск узнаёт смысл иконки, если у автора набора мало тегов или они только на английском?

Решение:

1. Обогащение. Модель, которая понимает изображения, получает PNG иконки, её имя и теги и возвращает короткое описание и синонимы на русском и английском. Результат сохраняется в файл метаданных набора и в пакет для разработчиков не попадает.
2. Кэш по отпечатку. Обогащение повторяется только для новых и изменённых иконок, а задачи отправляются пакетно — так дешевле.
3. Эмбеддинги. Многоязычная модель считает вектор текста иконки: имя, теги, описание и синонимы. Векторы изображений — по желанию, для «похожих иконок» и поиска по картинке.
4. Контроль качества. Выборочная ручная проверка описаний, например 50 иконок на набор, и фильтр запрещённых слов. Описание не должно утверждать того, чего нет на картинке.

Выбор модели: 2–3 многоязычные модели эмбеддингов сравниваются на эталоне из ADR-0009. Побеждает лучшая доля попаданий в первую пятёрку с учётом цены и скорости.

Последствия:

- Появляется статья бюджета на ИИ: разовая плата за обогащение каждой иконки и плата за векторы запросов.
- При смене модели эмбеддингов векторы всех иконок пересчитываются целиком.
- Новый язык добавляется дообогащением синонимов; многоязычная модель понимает запросы на нём и без этого.
