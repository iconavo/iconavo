# ADR-0025. Второй хост

Статус: принято 16 октября 2026 по рекомендации.

Вопрос: как сделать, чтобы падение основного провайдера не выключило иконки у пользователей?

Решение:

- Второй хост — Bunny CDN (ADR-0007): хранилище и CDN по адресу `cdn2.домен` с той же раскладкой файлов.
- Выкладка идёт сначала на основной хост, потом на второй. Манифест второго хоста обновляется последним, после сверки контрольных сумм.
- Переключение делает ядро пакета (ADR-0006), а не DNS: если основной хост молчит, тот же файл запрашивается со второго.
- Раз в сутки CI сверяет содержимое хостов; при расхождении приходит оповещение.
- Edge API на втором хосте нет: при сбое основного провайдера ядро берёт иконки поштучно со статики второго хоста.
- jsDelivr, который раздаёт файлы из npm-пакетов, — возможный третий уровень; решение — после запуска.

Уточнение от 22 октября 2026 (шаг 4 фазы 2, второй хост):

- **Устройство.** Хранилище Bunny (Storage Zone) `iconavo-cdn` и зона CDN (Pull Zone) `iconavo`, источник которой — это хранилище. Адреса — `cdn2.iconavo.dev` и собственный адрес зоны `iconavo.b-cdn.net`. Раскладка файлов та же, что на `cdn.iconavo.dev` (ADR-0004, ADR-0022).
- **Выгрузка — родной HTTP-интерфейс хранилища, не S3.**
  - S3-интерфейс Bunny на эту дату — предварительная версия (public preview с 9 июля 2026). Он включается только при создании хранилища, не хранит `Cache-Control` и не обещает ETag = MD5.
  - Родной интерфейс давно стабилен. Ключ — пароль хранилища в заголовке `AccessKey`, подписи нет. При записи сервер сверяет SHA-256 из заголовка `Checksum` и отвергает несовпавший файл. Список папки отдаёт SHA-256 каждого файла: поле `Checksum` есть в ответах, хотя в официальной схеме его нет.
  - Клиент свой, без зависимостей — `packages/pipeline/src/cdn/bunny.ts`. Общее с клиентом R2 (интерфейс хранилища, повторы, остановки) — `storage.ts`.
- **Порядок `pnpm cdn upload`.**
  1. Сборка `dist-cdn/`.
  2. Файлы версий на R2: в наборе файл сумм последним, затем сверка по списку — размер и ETag = MD5.
  3. Файлы версий на Bunny: так же, сверка — SHA-256 из списка против файла сумм.
  4. Манифест R2.
  5. Манифест Bunny — последним.

  Манифесты пишутся, только когда файлы новой версии есть на обоих хостах. Ядро берёт версию из манифеста одного хоста, а файл при медленном ответе просит у другого (ADR-0030). Если версии там нет, ядро запомнило бы иконку как несуществующую.
- **Остановки.**
  - «СТОП» на R2 — на Bunny ничего не выгружается: иначе хосты разойдутся навсегда, потому что файлы версий не перезаписываются.
  - «СТОП» на Bunny — манифест R2 тоже не пишется. Цена: пока Bunny недоступен, новая версия не выходит ни на одном хосте. Запасной выход на случай долгого сбоя — в бэклоге.
  - Показ (`--dry-run`) сравнивает оба хоста всегда.
- **Ограничения хранилища Bunny.**
  - До 100 одновременных соединений с одного адреса и до 5 одновременных списков папок.
  - При превышении Bunny отвечает 429 или 400, поэтому 400 у Bunny повторяется, а у R2 — нет.
  - Выгрузка шлёт 32 записи одновременно, списки — по одному.
  - У списка папки своё ожидание — 120 с: у material-symbols в одной папке около 47 тысяч файлов.
- **Ключ.** Пароль хранилища (Storage → FTP & API Access → Password, не Read-only) — секрет GitHub Actions `BUNNY_STORAGE_PASSWORD`. В локальном `.env` он нужен только для показа и сверки. Сброс кэша CDN через API не нужен — манифест идёт мимо кэша, — поэтому главного ключа аккаунта Bunny нет нигде.
- **Настройки Bunny — ставит владелец в панели.**
  - Хранилище `iconavo-cdn`: тариф Standard, основной регион Frankfurt (адрес интерфейса `storage.bunnycdn.com`), без реплик, S3 compatibility выключено. Тариф и S3 после создания не меняются.
  - Зона CDN `iconavo`: выключены Smart Cache (он не кэширует JSON), встроенный CORS (заголовок двоился бы с правилом), Optimizer, Perma-Cache, Origin Shield. Сжатие br и gzip Bunny делает сам.
  - Hostnames: `cdn2.iconavo.dev`, бесплатный сертификат (Verify & Activate SSL), Force SSL — http переводится на https.
  - DNS в Cloudflare: CNAME `cdn2` → `iconavo.b-cdn.net`, Proxy status — DNS only (серое облако). Через прокси Cloudflare второй хост перестал бы быть независимым; `pnpm cdn check` ловит это по заголовку `Server`.
  - Шесть правил Edge Rules. Шаблоны без адреса хоста, поэтому `iconavo.b-cdn.net` ведёт себя так же. Ставятся до первой выгрузки: Override Cache Time 0 не трогает то, что уже лежит в кэше.
    1. «Раздача: кэш версий» — Request URL `*/v/*`: Override Cache Time 31536000; Set Response Header `Cache-Control: public, max-age=31536000, immutable`.
    2. «Раздача: манифест мимо кэша» — Request URL `*/manifest.json`: Override Cache Time 0; Set Response Header `Cache-Control: public, max-age=300`.
    3. «Раздача: CORS и защита» — Request URL `*`: Set Response Header `Access-Control-Allow-Origin: *`, `X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: cross-origin`.
    4. «Раздача: CSP для SVG» — File Extension `svg`: Set Response Header `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`.
    5. «Раздача: тип JSON» — File Extension `json`: Set Response Header `Content-Type: application/json; charset=utf-8`.
    6. «Раздача: тип SVG» — File Extension `svg`: Set Response Header `Content-Type: image/svg+xml; charset=utf-8`.

    Правила 5 и 6 добавлены после первой выгрузки: тип, присланный при записи, Bunny не хранит и отдаёт тип по расширению, без `charset` (`application/json`, `image/svg+xml`). Решение владельца 22 октября 2026: правила, а не отступление в проверке, — заголовки двух хостов одинаковые.
  - Баланс аккаунта — с автопополнением: пустой баланс останавливает сервис. Цены на 22 октября 2026: хранилище $0,01 за ГБ в месяц, трафик $0,01 за ГБ в Европе и Северной Америке, минимум $1 в месяц на аккаунт.
- **Манифест мимо кэша CDN Bunny.** Перезапись файла в хранилище не сбрасывает копию в кэше CDN. Поэтому манифест, как и на Cloudflare (ADR-0023), читается из хранилища на каждый запрос.
- **Проверка — `pnpm cdn check`.**
  - Те же адреса и проверки, что у `cdn.iconavo.dev`, на обоих хостах по очереди.
  - Состояние кэша второго хоста — заголовок `CDN-Cache`: у файлов версий HIT или MISS, у манифеста BYPASS или MISS на обоих запросах.
  - `Server` у ответов файлов начинается с `BunnyCDN`, у основного хоста — с `cloudflare`.
  - В конце — манифесты хостов побайтно одинаковые.
  - Подсказки «где поправить» — правила зоны CDN Bunny.
- **Сверка — `pnpm cdn verify` и workflow «Сверка хостов» (`.github/workflows/verify.yml`).**
  - Сборка, затем сравнение обоих хранилищ с ней по спискам, без записи. Код 1, если чего-то недостаёт или что-то отличается.
  - Запуск — каждый день в 05:47 UTC и вручную. Оповещение — письмо GitHub о неудачном запуске по расписанию.
  - Группа одновременности своя, не «Выкладки»: иначе сверка могла бы отменить ждущую выкладку. Если сверка совпала с выкладкой, она может покраснеть — тогда повторить после выкладки.
- **«Выкладка» с ветки.** Вручную с другой ветки настоящая выгрузка идёт, только если `data/` там та же, что в `main`: иначе хосты получили бы прежний манифест. Ожидание задачи — 90 минут, с запасом на первую полную выгрузку на новый хост; повтор докачивает только недостающее.
- **Независимость.** Домен зарегистрирован у Cloudflare, и его DNS — тоже Cloudflare. При сбое DNS Cloudflare адрес `cdn2.iconavo.dev` не откроется, а `iconavo.b-cdn.net` — откроется. Это кандидат в запасной список ядра (фаза 3, бэклог). Решено 26 октября 2026 (шаг 1 фазы 3, решение владельца): `iconavo.b-cdn.net` — последний в запасном списке ядра, после `cdn2` (ADR-0030).
- **Проверено 22 октября 2026.**
  - Первая полная выгрузка в Bunny — из CI, ручным запуском «Выкладки» с ветки PR шага 4: 88 659 файлов, 68 МБ, 18 мин 51 с (весь запуск — 31 мин; material-symbols — 47 185 файлов за 8 мин 48 с). Сверка по SHA-256 из списка сошлась у всех пяти наборов: поле `Checksum` в списке Bunny есть. Манифест Bunny записан последним, на R2 — «без изменений».
  - Тип, присланный при записи, Bunny не хранит — добавлены правила 5 и 6. Правила подействовали и на файлы, уже лежавшие в кэше CDN: заголовки ставятся при отдаче, сброс кэша не понадобился.
  - `pnpm cdn verify` с компьютера владельца — «совпадают»: все файлы версий и манифесты обоих хостов на месте, 2 мин 46 с; список Bunny с 47 185 файлами material-symbols — 14 с.
  - Владелец открыл в браузере манифест и иконки пяти наборов на `cdn2.iconavo.dev` — всё на месте.
  - `pnpm cdn check` — «ок» у обоих хостов, манифесты совпадают. На `cdn2`: `CDN-Cache` у файлов версий HIT, у манифеста BYPASS; `Server` — `BunnyCDN-AMS1-…`; сжатие br и gzip, Chrome получает zstd; `http://` — 301 на https; `iconavo.b-cdn.net` отвечает так же.
  - Ответ 404 внутри `v/` на Bunny получает от правила «Раздача: кэш версий» `Cache-Control` на год с `immutable` и хранится в кэше CDN (`CDN-Cache: HIT`); у Cloudflare 404 не кэшируется. Это допустимо: папка версии неизменяема, а файлы ложатся на хост раньше, чем манифест на неё укажет, — имени, которого нет в версии, в ней не будет никогда.

Уточнение от 23 октября 2026 — страховка от счёта до запуска (решение владельца; мониторинг расходов перенесён после запуска, ADR-0028). Bunny списывает деньги с баланса с автопополнением, поэтому бот, который качает иконки с `cdn2`, тратил бы их без предупреждения. Ставит владелец в панели Bunny:
- **Зона CDN `iconavo` → Limits → Monthly bandwidth limit — 100 ГБ.**
  - Своего трафика у проекта до запуска почти нет: проверки CI — мегабайты в сутки.
  - Худший случай — около $1 по цене Европы и Северной Америки ($0,01 за ГБ) и не больше $6 в самом дорогом регионе ($0,06 за ГБ на Ближнем Востоке и в Африке; цены на 23 октября 2026).
  - Когда лимит исчерпан, Bunny выключает зону до следующего расчётного месяца: `cdn2.iconavo.dev` не отвечает, `pnpm cdn check` и «Сверка хостов» краснеют. Файлы в хранилище не пропадают.
  - Перед запуском лимит поднять — пункт фазы 7 в роадмапе.
- **Billing → Auto-Recharge — сумма $10.** Автопополнение остаётся включённым, потому что пустой баланс останавливает сервис. Bunny пополняет, когда баланс падает до 20% от суммы, то есть до $2, и не чаще раза в 6 часов. Если сумма уже больше, а поменять её нельзя, — выключить автопополнение и включить заново с $10.

Уточнение от 26 октября 2026 (шаг 1 фазы 3, запасной список ядра):

- **Зону CDN `iconavo` нельзя удалять и переименовывать никогда.** Адрес `iconavo.b-cdn.net` будет зашит в опубликованные версии пакета, а `cdn2.iconavo.dev` смотрит на зону через CNAME. Освободившееся имя зоны может занять кто угодно и отдавать сайтам свою разметку вместо иконок. Если второй хост когда-нибудь сменится, зона остаётся за нами — хотя бы пустой, с лимитом трафика.
- **jsDelivr для иконок не нужен:** в пакетах npm только целые наборы, от 0,1 до 1,5 МБ в сжатом виде (ADR-0030). jsDelivr раздаёт только скрипт тега для страниц без сборщика (ADR-0032).

Почему: два независимых провайдера почти никогда не падают одновременно, а переключение внутри ядра работает без настройки DNS.
