# ADR-0032. Веб-компонент

Статус: принято 16 октября 2026 по рекомендации, с опорой на Iconify.

Вопрос: как устроен тег `<iconavo-icon>`?

Решение:

- SVG рисуется внутри shadow DOM: стили страницы не ломают иконку, ID не конфликтуют, а при серверном рендере сервер отдаёт только сам тег. Так же устроен веб-компонент Iconify ([источник](https://iconify.design/docs/iconify-icon/)).
- Перед регистрацией тег проверяет, не зарегистрирован ли он уже, поэтому две версии пакета на одной странице не ломают сайт.
- Рисуются только видимые иконки, как у Iconify; атрибут `noobserver` это отключает.
- До загрузки тег занимает 1em × 1em, поэтому вёрстка не прыгает.
- На старте есть только режим SVG. Режимы фона и маски, которые Iconify использует для анимированных иконок, добавляются вместе с первым анимированным набором ([источник](https://iconify.design/docs/iconify-icon/modes.html)).

Уточнение от 26 октября 2026 (шаг 1 фазы 3, README пакета; решение владельца — скрипт с jsDelivr):

- **Атрибуты тега:** `icon`, `width`, `height`, `color`, `stroke-width`, `rotate`, `flip`, `inline`, `label`, `placeholder`, `noobserver` (ADR-0031). Описание для разработчиков — `packages/icon/README.md`.
- **До выполнения скрипта** тег — неизвестный пустой элемент 0×0, и текст рядом прыгает. README предлагает строку CSS в `<head>`: `iconavo-icon:not(:defined){display:inline-block;width:1em;height:1em}`. Явные `width` и `height` она не учитывает.
- **Страница без сборщика** — самостоятельный ES-модуль с ядром внутри (`dist/iconavo-icon.js`, имя уточнит шаг 5) с jsDelivr, с точной версией в адресе (решение владельца).
  - Такие адреса jsDelivr кэширует навсегда, а теги и диапазоны версий — 7 дней (документация jsDelivr).
  - `configure` и `addIcons` на такой странице импортируются из того же адреса, в одном модуле с подключением.
  - Хэш SRI (`integrity`) вписывает публикация шага 11.
  - Свой адрес на `cdn.iconavo.dev` — в бэклоге, к запуску.
- **Строгая CSP.** Разметка иконки вставляется через политику Trusted Types `iconavo`; стили тега — `adoptedStyleSheets`, а не `<style>`. Это требования к шагам 4–5; что разрешить в CSP, написано в README.

Уточнение от 27 октября 2026 (шаг 5 фазы 3, тег; решения владельца — Playwright сейчас и загрузка за полэкрана):

- **Три входа пакета** — одна регистрация `define(dev)`, отличается только режим разработки по умолчанию (ADR-0031):
  - `index.js` — обычная сборка, режим выключен;
  - `development.js` — условие экспорта `development`, режим включён;
  - `script.js` — вход для страниц без сборщика, режим включён на `localhost`, `127.0.0.1`, `[::1]` и `file:`. Из него rolldown собирает `dist/iconavo-icon.js` — имя окончательное, как в README: один сжатый модуль с ядром внутри (`pnpm icon build`).
  - `sideEffects` пакета — список этих входов: с `false`, как у ядра, сборщик выбросил бы регистрацию. Это проверяет тест: сборка строки `import "@iconavo-ui/icon"` сохраняет `customElements.define`.
  - Класс тега создаётся внутри `define`: импорт пакета на сервере, где нет `HTMLElement`, ничего не ломает.
- **Регистрация.** Первая копия на странице регистрирует тег, остальные видят его в `customElements.get` и пропускают. Иконки, настройки и загрузка у копий общие (ADR-0030).
- **Shadow DOM** — открытый.
  - Стили — один `CSSStyleSheet` на все теги через `adoptedStyleSheets`; в среде без них (jsdom в тестах разработчика) тег работает без стилей.
  - `:host{display:inline-block}` и `:host([hidden]){display:none}`: без второго правила атрибут `hidden` перестал бы прятать тег.
  - `inline` — только CSS, `vertical-align:-.125em`.
- **Резерв места** — пустой `<svg>` сразу в `connectedCallback`, без отложенной задачи: скрипт, который вставил тег и тут же меряет, не увидит 0×0. Размеры: заданные; одна сторона — квадрат; без размеров и с `auto` — `1em` (у `auto` размер после загрузки меняется на сетку набора). Атрибуты и содержимое тега на странице не трогаются — гидратация React не увидит чужого.
- **Ленивая загрузка.**
  - Один IntersectionObserver на страницу с `rootMargin: 50%`: иконка грузится за полэкрана до появления (решение владельца). README поправлен: «when it comes near the visible part of the page».
  - При первом появлении тег активен навсегда; с `noobserver` и без IntersectionObserver — сразу. Тег, уже убранный со страницы, поздним сигналом не активируется.
  - Запас не действует во внутренних прокручиваемых блоках и в чужих iframe — так устроен IntersectionObserver (бэклог).
- **Загрузка и перерисовка.**
  - `loadIcon` — только при активации, смене имени и возвращении тега на страницу. Сигнал хранилища лишь перерисовывает: иначе после «ошибки» запросы шли бы по кругу.
  - Неудавшаяся иконка запрашивается снова, когда тег возвращают на страницу, меняют ему имя или ту же иконку показывает новый тег. При прокрутке назад — нет (бэклог).
  - Перерисовки копятся до одной микрозадачи на страницу; то же состояние с теми же атрибутами второй раз не рисуется, поэтому отсчёт 150 мс до заглушки не начинается заново.
- **Подпись** — `ElementInternals`: `role="img"` и `aria-label` у тега, сразу при смене `label`, не дожидаясь видимости. Внутренний `<svg>` — `aria-hidden`.
- **Цвет** — свойством стиля внутреннего `<svg>` из скрипта, а не атрибутом: так работает и `var(--brand)`, а строгая CSP свойства из скрипта не запрещает. У React — атрибут: его разметку отдаёт сервер (ADR-0033).
- **Trusted Types.**
  - Политика `iconavo` создаётся при первой нарисованной иконке и лежит под ключом `Symbol.for("iconavo.trusted-types")` без версии формата. Так она одна на страницу для всех копий и версий тега и для React (шаг 7): вторая политика с тем же именем без `'allow-duplicates'` — исключение.
  - `createHTML` — тождественная функция навсегда.
  - Отказ в политике — `null`; запись, которую браузер всё же запретил, — пустое место и одно предупреждение `Trusted Types blocked icons, allow "trusted-types iconavo"` вместо исключения на каждую иконку.
- **Свойств и событий у тега в 0.1 нет**: React 19 и Vue ставят атрибуты. События и `:state()` — бэклог.
- **Песочница:**
  - `/tag` — две копии сразу, заглушки, рамка, подпись, `inline`, цвет и атрибуты;
  - `/many` — 5000 иконок, подключённых, как в README без сборщика.

  Политика обеих страниц — строгая, как в README, плюс хэш стиля страницы и пустая иконка вкладки.
- **Проверка в браузерах** — `pnpm sandbox --check` (ADR-0035). 27 октября 2026 тег прошёл все проверки в Chrome, Firefox и WebKit.

Почему: один тег работает в любом фреймворке и на обычной HTML-странице.
