# ADR-0024. Edge API: устройство и правила

Статус: технические части приняты 16 октября 2026 по рекомендации, продуктовые ждут вашего подтверждения.

Вопрос: как работает API, совместимое по адресам с Iconify (ADR-0004)?

Решение:

- Функции на Cloudflare Workers читают файлы прямо из хранилища R2, без лишних походов в интернет.
- Пачка `/{набор}.json?icons=…`: один запрос — один набор, ответ в формате IconifyJSON, отсутствующие имена перечислены в `not_found`, неизвестный набор — ошибка 404. Так же отвечает Iconify ([источник](https://iconify.design/docs/api/icon-data.html)).
- Имена в пачке сортируются, повторы убираются, ключ кэша строится из отсортированного списка.
- Ядро пакета режет пачки так, чтобы адрес укладывался в 500 символов, как компоненты Iconify; сервер принимает и более длинные адреса.
- SVG собирается на лету с параметрами color, width, height, rotate, flip, box, download; сначала отражение, потом поворот, как у Iconify.
- CSS: монохромные иконки — через маску с цветом текста, цветные — через фон ([источник](https://iconify.design/docs/api/svg.html)).
- Ошибки — короткий JSON с кодом и понятным сообщением.

Продуктовые решения — за вами:

- Открытость API. Рекомендация: API публичный, бесплатный, без ключа и с документацией — им смогут напрямую пользоваться разработчики и ИИ-ассистенты.
- Лимиты. Рекомендация: иконки — без жёстких лимитов, их обслуживает кэш CDN; поиск — 60 запросов в минуту с одного IP без ключа, больше — с бесплатным ключом.

Почему: устройство как у Iconify делает API привычным, а кэш и лимиты защищают от лишних расходов.
