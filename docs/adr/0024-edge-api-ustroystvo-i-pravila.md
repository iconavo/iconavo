# ADR-0024. Edge API: устройство и правила

Статус: технические части приняты 16 октября 2026 по рекомендации; продуктовые — открытый бесплатный API без ключа и лимиты — подтверждены владельцем 17 октября 2026 (отметки в [сводке решений](README.md)).

Вопрос: как работает API, совместимое по адресам с Iconify (ADR-0004)?

Решение:

- Функции на Cloudflare Workers читают файлы прямо из хранилища R2, без лишних походов в интернет.
- Пачка `/{набор}.json?icons=…`: один запрос — один набор, ответ в формате IconifyJSON, отсутствующие имена перечислены в `not_found`, неизвестный набор — ошибка 404. Так же отвечает Iconify ([источник](https://iconify.design/docs/api/icon-data.html)).
- Имена в пачке сортируются, повторы убираются, ключ кэша строится из отсортированного списка.
- Ядро пакета режет пачки так, чтобы адрес укладывался в 500 символов, как компоненты Iconify; сервер принимает и более длинные адреса.
- SVG собирается на лету с параметрами color, width, height, rotate, flip, box, download; сначала отражение, потом поворот, как у Iconify.
- CSS: монохромные иконки — через маску с цветом текста, цветные — через фон ([источник](https://iconify.design/docs/api/svg.html)).
- Ошибки — короткий JSON с кодом и понятным сообщением.

Продуктовые решения — владельца, подтверждены 17 октября 2026:

- Открытость API. Рекомендация: API публичный, бесплатный, без ключа и с документацией — им смогут напрямую пользоваться разработчики и ИИ-ассистенты.
- Лимиты. Рекомендация: иконки — без жёстких лимитов, их обслуживает кэш CDN; поиск — 60 запросов в минуту с одного IP без ключа, больше — с бесплатным ключом.

Уточнение от 23 октября 2026 (шаг 7 фазы 2; решения владельца — объём, тариф, выкладка, кэш):

- **Объём.** Три адреса: пачка `/{набор}.json?icons=…`, SVG `/{набор}/{иконка}.svg` и CSS `/{набор}.css?icons=…`.
  - `/collections`, `/collection` и `/last-modified` из ADR-0004 — в фазе 4, вместе с сайтом и MCP: им нужны данные о наборах (`info.json`), которых на раздаче нет.
  - `/last-modified` ядру не нужен: постоянного кэша в браузере нет (ADR-0030).
- **Где код.**
  - Функция — `apps/api` (`@iconavo-ui/api`): маршруты, параметры, кэш, ответы. Справка API на английском — `apps/api/README.md`.
  - Сборка SVG с размерами, поворотами и отражениями — в ядре `packages/core` (`iconData`, `iconToSvg`, разбор `rotate`, `flip` и размеров). Её же возьмёт рендер пакета в фазе 3 (ADR-0031), и картинка по ссылке API совпадёт с иконкой из пакета.
  - Без параметров SVG ядра побайтно равен файлу статики: это проверяет тест конвейера на всех иконках и алиасах `data/` (`packages/pipeline/src/cdn/svg-core.test.ts`).
  - Сборка, превью и проверка — команда `pnpm api` конвейера (`packages/pipeline/src/api/`).
- **Данные.** Функция читает через привязку R2 `CDN` те же файлы, что лежат на `cdn.iconavo.dev`:
  - `manifest.json` — в памяти минуту, одна загрузка на все одновременные запросы. R2 не ответил — служит прежняя копия, без неё — 503;
  - файлы имён `v/{версия}/{набор}/{имя}.json` — не больше шести запросов к R2 сразу: это лимит соединений одного вызова Workers.
- **Пачка.**
  - Имена — только через запятую, без повторов, по кодам символов: порядок имён не меняет ответ.
  - Неверное имя попадает в `not_found` без чтения R2.
  - `aliases` есть всегда, `not_found` — только если что-то не нашлось. Не нашлось ничего — ответ без размеров набора.
  - Ключи JSON — по кодам символов, как у файлов статики.
  - Не больше 100 имён на запрос, иначе 400. Ядро режет пачки по 500 символов адреса и не больше 100 имён, это 20–40 имён (посчитано на наших наборах 27 октября 2026). Лимит — на размер запроса, а не на частоту: он держит в узде чтение R2 в обход кэша и 10 мс процессора бесплатного тарифа.
- **SVG.** Параметры `color`, `width`, `height`, `rotate`, `flip`, `box` и `download` — как у Iconify, но строже: неверное значение даёт 400 с понятным текстом, а не тихо другой результат.
  - `rotate=90` у Iconify означает 180°, здесь это ошибка: нужно `90deg` или `1`.
  - `color` — по закрытым правилам: hex (`#` можно опустить), имя цвета, `rgb()`, `rgba()`, `hsl()`, `hsla()`.
  - `box` — прозрачный прямоугольник по итоговому холсту; у Iconify — по холсту до поворота.
- **CSS** — как getIconsCSS у Iconify с селекторами по умолчанию: маска у монохромных, фон у цветных; параметры `color`, `mode`, `square`, `format`, `download`. Свои селекторы, `pseudo` и `var` — в бэклоге: это главная поверхность для подмены CSS.
- **Ошибки** — JSON `{"error","message","status"}` по-английски, коды — в `apps/api/README.md`. Неизвестный набор — 404; Iconify отвечает 200 с телом «404».
- **Кэш** — Cache API дата-центра. Ключ: поколение, метка сборки, версия набора и проверенные параметры в постоянном порядке (ADR-0023).
  - В кэш попадают только ответы, которым понадобился R2.
  - Новый Workers Cache (многоуровневый, июль 2026) не взят: ему нужны wrangler и сброс по тегам после каждого выпуска. Кандидат на после запуска.
- **Заголовки** ставит сама функция:
  - `X-Iconavo-Version` — версия набора, `X-Iconavo-Build` — сборка, `X-Cache` — `HIT` или `MISS`; все три открыты через `Access-Control-Expose-Headers`;
  - CORS, `nosniff`, CORP, у SVG — та же CSP, что на статике.
- **Выкладка — своим кодом, без wrangler** (решение владельца). wrangler весит около 200 МБ вместе с движком workerd и по умолчанию отправляет телеметрию.
  - `pnpm api build` — rolldown `1.2.14` собирает один ES-модуль `dist-api/worker.js`. Он уже стоял в lock-файле внутри Vitest и size-limit, теперь он прямая зависимость конвейера.
  - Метка сборки — 8 знаков SHA-256 бандла.
  - `metadata.json`: модуль, `compatibility_date` `2026-10-01`, привязка `CDN` → `iconavo-cdn`, журналы.
  - Workflow «Edge API» (`.github/workflows/api.yml`): «Сборка» → «Выкладка» → «Проверка».
    - «Выкладка» работает из окружения `api` (только `main`), без checkout и `pnpm install`. Один запрос `curl -X PUT /accounts/{id}/workers/scripts/iconavo-api` загружает версию и сразу её выкладывает.
    - «Проверка» — `pnpm api check --expect-build`.
    - Та же сборка уже отвечает — выкладки нет.
  - Ключ — `CLOUDFLARE_API_TOKEN`, секрет окружения `api`, право Account · Workers Scripts · Edit. Идентификатор аккаунта — существующий `R2_ACCOUNT_ID`.
- **Разовая настройка в панели Cloudflare** (владелец, до первой выкладки). Домен и выключенный workers.dev загрузка новых версий не трогает.
  1. Workers & Pages → Create → Worker «Hello World», имя `iconavo-api` → Deploy.
  2. Settings → Domains & Routes → Add → Custom Domain → `api.iconavo.dev`.
  3. Там же: workers.dev — Disable, Preview URLs — Disable.
- **Журналы Workers** — только наши сообщения об ошибках (`invocation_logs: false`), без журнала запросов с IP (ADR-0028).
- **Тариф — бесплатный до запуска** (решение владельца): 100 000 запросов в сутки и 10 мс процессора на запрос. Кончился лимит — ядро возьмёт иконки со статики (ADR-0030).
  - Переход на платный ($5 в месяц) — пункт фазы 7.
  - Перед ним — ограничение частоты: у платного тарифа нет суточного потолка запросов (бэклог).
- **Проверка** — `pnpm api check`; она же входит в `pnpm cdn check` («Выкладка», «Сверка хостов»).
  - Сначала ждёт до 3 минут, пока API отдаст версию из манифеста R2.
  - Пачка в двух порядках: второй ответ — из кэша и побайтно тот же; тело совпадает с файлами статики той же версии.
  - SVG без параметров — побайтно файл статики.
  - `color=red&height=64`; `rotate=90deg&flip=horizontal` — точная строка `transform`.
  - CSS; 404 у набора и у иконки.
  - CORS, защита, `br` и `gzip`, переход с http.
  - Время первого ответа каждого адреса.
- **Превью** — `pnpm api preview` на 127.0.0.1:4281: тот же бандл в Node с данными `dist-cdn/`, страница для глаз.
- **Проверено 23 октября 2026 на превью с данными всех пяти наборов:**
  - бандл — 29 КБ, в gzip 10 КБ, повторная сборка — та же метка;
  - SVG `lucide:heart` без параметров побайтно равен файлу статики;
  - пачка в двух порядках — один и тот же ответ, второй из кэша;
  - повороты, отражения и `box` у всех наборов, включая неквадратный `fluent-emoji-flat:swan` и `phoenix-bird` с градиентами в `<defs>`;
  - CSS: Lucide — маской с цветом текста, Fluent Emoji — фоном.
- **Проверено 23 октября 2026 после слияния (PR #49): первая выкладка из CI.**
  - «Edge API»: сборка `a6d7d0f1`, на Linux та же метка, что на Windows. Затем выкладка одним запросом: права Account · Workers Scripts · Edit хватило и для привязки R2. Затем `pnpm api check --expect-build` — «ок» у всех девяти адресов.
  - Cloudflare сам сжимает ответы функции: `br` на «br, gzip», `gzip` на «gzip». Своё сжатие не нужно, пункт бэклога закрыт.
  - Повтор пачки — `X-Cache: HIT`. Домен `api.iconavo.dev`, привязанный в панели, после загрузки версии через API на месте.
  - Время первого ответа с машины GitHub:
    - пачка из кэша — 33–47 мс;
    - SVG без параметров и с параметрами — 160–290 мс;
    - CSS — 250–280 мс.
    - Новую версию набора проверка дождалась за 0,8–1 с.
  - «Выкладка» на том же слиянии: `pnpm cdn check` — «ок» у обоих хостов статики и у API.
  - Страница превью с живым API: все 78 картинок загрузились; CSS — маской у Lucide, фоном у Fluent Emoji.
  - Владелец принял шаг 23 октября 2026.

Уточнение от 26 октября 2026 (шаг 8 фазы 2, поиск, ADR-0049):

- **Четвёртый адрес** — `/search?query=…`. Параметры, ответ и «сначала текст» описаны в ADR-0049, справка — в `apps/api/README.md`.
- **Привязки:**
  - `SEARCH` — закрытый бакет `iconavo-search`, функция из него только читает;
  - `SEARCH_LIMIT` — ограничение частоты Workers: 60 поисков в минуту с адреса, считаются только запросы мимо кэша. Это рекомендация «Лимиты» выше — для поиска, без ключей.
- **Секреты:**
  - `MEILISEARCH_URL`, `MEILISEARCH_SEARCH_KEY` и `POLZA_API_KEY` хранятся в окружении `api`;
  - при выкладке jq вписывает их в `metadata.json` как `secret_text`, файл лежит во временной папке раннера и в артефакт не попадает;
  - нет секрета — выкладка красная;
  - сменили ключ — ручной запуск «Edge API» с «выложить заново».
- **Манифест** держится в памяти минуту и в кэше дата-центра 30 секунд, чтобы холодная копия функции не ждала R2. Новый выпуск набора виден через API не позже чем через полторы минуты. Так же хранится версия индекса поиска.
- **Поколение кэша** — 2 с 26 октября 2026: повторный замер скорости поиска шёл с чистыми ключами.
- **Проверка:** `pnpm api check` проверяет и поиск; `pnpm api bench` меряет скорость поиска — ручной запуск «Edge API» с «замер скорости».
- **Бандл** — 60 КБ, в gzip 19 КБ.

Уточнение от 28 октября 2026 (шаг 6 фазы 3: кэш файлов имён, ADR-0030):

- **Кэш файлов имён.** Прочитанный из R2 файл `v/{версия}/{набор}/{имя}.json` функция кладёт и в кэш дата-центра, и новую пачку из знакомых иконок собирает без R2. Чтение одно на все адреса, поэтому ускоряются и SVG, и CSS.
  - Ключ — `…/__cache/{поколение}/file/v/{версия}/{набор}/{имя}.json`, без метки сборки: файл зависит только от версии набора (ADR-0022), и выкладка функции кэш файлов не сбрасывает. Поколение по-прежнему сбрасывает всё.
  - Хранится текст файла из R2, 30 дней. При каждом чтении он проверяется, как файл из R2.
  - Файла нет в R2 — в кэш не пишется: ответ целиком с `not_found` и так лежит в кэше.
  - В кэш попадают ответы, которым понадобились файлы имён, — из кэша файлов или из R2.
- **Бюджет обращений.** На бесплатном тарифе Workers — не больше 50 обращений к Cache API за запрос (`match` и `put` вместе с `fetch`; на платном — 1 000; документация Cloudflare от 12 октября 2026). Чтения R2 считаются отдельно, до 1 000: новая пачка из 100 имён отвечает 200 (проверено вживую 28 октября 2026).
  - Ответ целиком (чтение и запись) и манифест (чтение и запись раз в минуту) — до 4 обращений; на файлы — 40 (`FILE_CACHE_CALLS`), запас — 6.
  - Проба: сначала ищутся 6 имён (`FILE_PROBE`), взятых равномерно по пачке. Нашлось хоть одно — ищутся и остальные, пока хватает бюджета. Ни одного — пачка новая, и обращения уходят на запись прочитанного из R2.
  - Так новая пачка из 30 имён ложится в кэш целиком, из 40 — 34 файла, а пачка из 40 знакомых имён целиком собирается из кэша.
  - Записи — после ответа (`waitUntil`): сначала ответ целиком, затем файлы, не больше 6 одновременно.
  - На платном тарифе (фаза 7) `FILE_CACHE_CALLS` поднимается так, чтобы хватало на поиск и запись каждого имени, — тогда проба не нужна.
- **Сбои кэша.** Раньше сбой Cache API при поиске ответа целиком давал 500. Теперь сбой — как промах: ответ из R2, и до конца запроса кэш не трогается. Испорченная запись файла — файл из R2 и запись поверх. Кэш больше не превращает ответ в ошибку. У `/search` то же место пока не защищено (бэклог).
- **`Server-Timing`** у пачек, SVG и CSS — время в функции и откуда файлы: `manifest`, `cache` (`hit` или `miss`), `files` (нашлось в кэше / искали), `r2` (прочитано) и `total`. Только латиница; в копии ответа в кэше его нет. `Timing-Allow-Origin: *` — как у поиска.
- **Замер пачек** — `pnpm api bench --batches`, протокол и цифры — в ADR-0030. Ручной запуск «Edge API» с «замер пачек» идёт и с ветки: замер только читает открытые адреса, без выкладки.
- **Бандл** — 65,5 КБ, в gzip 20,8 КБ.

Уточнение от 30 октября 2026 (шаг 2 фазы 4: каталог наборов, ADR-0004, ADR-0022):

- **Адреса — как у Iconify:**
  - `/collections` — `{набор: IconifyInfo}`; `version` — версия у автора: npm или 7 знаков коммита;
  - `/collection?prefix=` — имена по категориям автора и `uncategorized`, `hidden`, `aliases` («алиас → иконка»), `suffixes` без ведущего дефиса, как у Iconify. С `info=true` — ещё `info` первым полем, с полным текстом лицензии (наше дополнение). `chars` принимается и ничего не меняет;
  - `/last-modified` — время выпуска по манифесту; неизвестный набор — пустой ответ;
  - `prefix` и `prefixes` (через запятую, `mdi-` — начало имени) — как у Iconify; `pretty` не читается.
- **Наш адрес** `/changelog[?prefix=]` — до 100 последних выпусков наборов, свежие сверху.
- **Данные** — файлы каталога в R2 (ADR-0022) по полю `catalog` манифеста.
  - Оглавление (≈ 20 КБ) разбирается один раз и живёт в памяти копии функции по отпечатку.
  - Тело `/collection` отдаётся как лежит, `info` дописывается без разбора тела — в пределах 10 мс процессора.
- **Кэш.** Оглавление — в кэше дата-центра 30 дней: оно неизменяемо. Готовые ответы `/collection` и `/changelog` — по ключу «поколение, сборка, отпечаток оглавления, адрес, параметры». Обращений к Cache API — до 6 за запрос.
- **Заголовки.** В адресах нет версии, поэтому браузеру — 5 минут (`public, max-age=300`), как у манифеста. `X-Iconavo-Version` — версия набора у `/collection`, отпечаток каталога у остальных.
- **Ошибки:**
  - без `prefix` — 400 `prefix_required`;
  - неизвестный набор — 404 `set_not_found`;
  - манифест без `catalog` или файла каталога нет в R2 — 503 `storage_unavailable`.
- **Проверка** `pnpm api check` ждёт до 3 минут, пока API отдаст оглавление из манифеста R2: функция и «Выкладка» после слияния выкладываются параллельно. Затем сверяет:
  - наборы `/collections` — это наборы манифеста;
  - у `lucide` — `total` = `info.total` = число имён в категориях, есть полный текст лицензии;
  - `/last-modified` совпадает с манифестом, выпуски — свежие сверху;
  - ответы 400 и 404.

  Манифест без `catalog` — строки каталога пропускаются с пометкой.
- **Превью** `pnpm api preview` — раздел «Каталог наборов»: таблица наборов с витриной и примеры ответов.

Почему: устройство как у Iconify делает API привычным, а кэш и лимиты защищают от лишних расходов.
