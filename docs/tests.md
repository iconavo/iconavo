# Проверки пакета: что проверено и что нет

Отчёт шага 9 фазы 3 (ADR-0035), дополнен на шаге 10 (ADR-0050): живые примеры и сайт документации. README пакета (`packages/icon/README.md`) — договор с разработчиками. Здесь каждое его обещание и то, чем оно проверено. Проверки идут сами на каждом pull request, без интернета для иконок: хосты иконок — превью на машине CI. Пока любая из них красная, PR не сливается.

## Виды проверок

| Проверка | Что делает | Команда | Где в CI |
| --- | --- | --- | --- |
| Модульные тесты | Код ядра, тега и React в Node, без браузера: очередь, пачки, повторы, запасные хосты на поддельном времени, рендер, разметка React на сервере | `pnpm test` | задача `check` |
| Покрытие ядра | Какая доля кода ядра выполняется в тестах. Меньше 90% строк, веток или функций — проверка красная | `pnpm test --coverage` | `check`, таблица «Покрытие тестами» |
| Тег в браузерах | Песочница: тег на странице со строгой CSP, заглушки, рамка, подпись, ленивая загрузка, сбои сети | `pnpm sandbox --check` | `browser (chrome \| firefox \| webkit)` |
| React в браузерах | Пример на Next.js в режиме разработки и в продакшене, те же страницы на React 18; гидратация, сеть, доступность | `pnpm example --check` | `browser (…)` |
| Визуальное сравнение | Каждое имя пяти наборов через тег и React рядом с SVG статики | `pnpm visual` | `browser (…)` |
| Размер | Бюджеты в gzip: ядро 5 КБ, тег 2 КБ, React 2,5 КБ | `pnpm size` | `check`, таблица «Размер пакетов» |
| Живые примеры | Примеры для StackBlitz и `create-next-app` на архивах пакетов этой ветки: `npm install` в чистую копию, сборка, разработка и продакшен; иконки, серверный HTML, консоль, сеть, доступность | `pnpm starters --check` | `starters (chrome \| firefox \| webkit)` |
| Сайт документации | Продакшен-сборка сайта: обход страниц, заголовки и noindex, ссылки и якоря, разделы README, иконки, доступность в светлой и тёмной теме, ширина телефона | `pnpm site --check` | `site (…)` |
| Живой сайт | `iconavo.dev` после выкладки: та ли сборка, заголовки, noindex, ссылки, переходы с `www` и `http` | `pnpm site --live` | workflow «Сайт», задача «Проверка» |

Браузеры — Chrome (установленный), Firefox и WebKit — движок Safari — из Playwright. В CI каждый браузер идёт своей задачей, итог задач `browser`, `starters` и `site` — проверка `browsers`, она обязательна для слияния.

## Обещания README и чем они проверены

Обозначения: **тесты** — модульные тесты Vitest (файл рядом с кодом, `*.test.ts`); **песочница** — строка отчёта `pnpm sandbox --check`; **пример** — строка `pnpm example --check`; **сравнение** — `pnpm visual`; **вручную** — проверено владельцем при приёмке шага.

### Установка

| Обещание | Чем проверено |

| Скрипт для страниц без сборщика — один ES-модуль, всё внутри | тесты `pipeline/src/icon/build.test.ts`: без импортов, четыре функции; на этом скрипте работают страницы песочницы и сравнение |

| В архиве пакета — только сборка, README и LICENSE | живые примеры «Архивы пакетов» — по самому архиву |

### Загрузка и ошибки

| Обещание | Чем проверено |
| --- | --- |
| Пока иконка грузится, место занято — текст не прыгает | песочница «Место до загрузки» и «Сеть: медленная»; пример «Место до загрузки» |
| Заглушка — через 150 мс; скелетон, спиннер или ничего; без движения при «уменьшить движение» | песочница «Заглушка» и «Без анимации»; пример «Заглушки»; тесты `react/style.test.ts` |
| Тег грузит иконку за полэкрана до появления, `noobserver` — сразу | песочница «Лениво»; тесты `icon/element.test.ts` |
| В прокручиваемом блоке и в чужом iframe — только когда видно; для печати — `noobserver` | не проверяется: так устроен IntersectionObserver браузера (ниже, «Что не проверено») |
| React грузит иконку при монтировании | пример «Иконки из браузера», «Сеть» |
| В React стили заглушек приходят со скриптом; до него — пустое место нужного размера | пример «Серверный HTML» — страница без JavaScript |
| Иконки одного момента — одним запросом на набор, имена по порядку, адрес до 500 символов и до 100 имён; 100 иконок Lucide — 4 запроса; что уже грузится, повторно не запрашивается | тесты `core/load.test.ts` («пачки», «без повторов»); пример «Сеть: каждое имя по разу»; вручную: DevTools и журнал песочницы (шаг 2) |
| Хосты по порядку: API пачками, затем статика по одной иконке по манифесту | тесты `core/load.test.ts` («запасные хосты», «статика»); песочница «Сеть: API отказал» и «API и первый хост статики отказали» |
| API молчит 1,5 с — те же иконки со статики; между хостами одного вида — 750 мс; отказавший хост не ждут; первый ответ побеждает; попытка — до 5 с | тесты `core/load.test.ts` на поддельном времени; песочница «Сеть: API молчит» — настоящий браузер, около 1,5 с |
| Неудачная попытка повторяется через 1, 2 и 4 с, пока иконка на странице; потом — как отсутствующая и одно предупреждение; при следующем показе — запрос снова | тесты `core/load.test.ts` («повторы»); песочница «Сеть: ничего не отвечает» — попытки в 0, 1, 3 и 7 с |

## Визуальное сравнение: как оно устроено

- **Эталон** — SVG-файл каждого имени, ровно такой, какой отдаёт `cdn.iconavo.dev`. Его собирает код конвейера, а не пакет, и браузер открывает его как картинку. Путь «файл автора → `data/`» проверяет контроль качества фазы 1 (ADR-0016), так что вместе выходит «как у автора».
- **Пакет** — тег `<iconavo-icon>` из скрипта для страниц без сборщика и компонент React в серверном HTML, как его отдаёт Next.js. Данные — через `addIcons`, без сети.
- **Сравнение** — по клетке на имя, pixelmatch с порогом контроля качества: сглаживание краёв не в счёт.
- **Допуск — 0,5% пикселей иконки**: 12 пикселей из 2304 при размере 48 px, 21 из 4096 при 64 px (Fluent). SVG-картинку и тот же SVG в странице браузер сглаживает разными способами. У иконок с тонкими линиями и мелкими деталями расходятся 1–6 отдельных пикселей на краю — глазом не видно даже рядом. Настоящая поломка заметно больше: пропавшая стрелка часов в черновом PR #85 — 39–40 пикселей (ниже). Иконки «в допуске» отчёт показывает отдельно, с картинками.
- **Контрольная клетка** на каждой странице: пакет нарочно рисует её иначе, чем эталон. Если сравнение её не заметило, проверка слепая — это красный итог. Пустой эталон — тоже.
- **Первый прогон, 28 октября 2026**, весь каталог: 44 398 имён, тег и React, расхождений больше допуска нет ни в одном браузере. Firefox — 57 с, WebKit — 98 с, Chrome — около 8 минут на компьютере владельца; в CI вся задача браузера с установкой — от 3 до 8 минут. В допуске — несколько десятков иконок, не больше 6 пикселей; в CI на Linux — не больше 4.

## Как понять, что тесты не слепые

- **Контрольная клетка** в визуальном сравнении — на каждой странице.
- **Контрольный запуск** в проверке примера: страница портится до гидратации, и React обязан это заметить — и React 19, и React 18.
- **Контрольные запуски живых примеров:**
  - хосты иконок не отвечают — проверка обязана увидеть пустые иконки и предупреждение «failed to load»;
  - у Next.js заголовок портится до гидратации — ошибка обязана быть замечена.
- **Контрольный запуск сайта** подкладывает семь поломок, и каждую проверка обязана заметить: кнопку без подписи, атрибут `style`, слишком широкий блок, иконку-блок в строке, убранную метку robots, битую ссылку и испорченный заголовок до гидратации.
- **Нарочно сломанная функция** — черновой PR #85: `replaceIds` переписывает ID, а ссылки на них — нет. PR закрыт без слияния, как #78 у бюджета размера. CI покраснел там, где ждали:
  - `check` — упали 7 тестов: 6 в `ids.test.ts` и `svg-core.test.ts` («каждая ссылка ведёт на свой ID»);
  - `browsers` — во всех трёх браузерах визуальное сравнение поймало `fluent-emoji-flat:eleven-oclock`: у часов пропала красная минутная стрелка — её заливка градиентом по ссылке на ID; 39–40 пикселей у тега и у React при допуске 21.
  - Остальные 20 иконок с ID сломанные ссылки рисуют так же: у 14 обрезка — весь холст, у `teacher` фильтр почти не виден, у скрипки градиенты тонкие — 6 пикселей, в пределах допуска. Поэтому целость ссылок отдельно проверяют модульные тесты (`ids.test.ts` и `svg-core.test.ts` по всем иконкам).

## Что не проверено и почему

- **Настоящий Safari и VoiceOver.** Нужен Mac. Вместо Safari — WebKit, его движок: в CI на Linux, у владельца на Windows. По документации Playwright у WebKit вне Mac отличаются видео, графика и сеть.
- **Edge** отдельно не проверяется: это тот же движок, что у Chrome.
- **Подпись тега в Firefox и WebKit.** Дерево доступности Playwright даёт только у Chrome. Firefox проверен вручную Экранным диктором на шаге 5. axe-core подпись тега тоже не видит: она задана через ElementInternals, а их axe по умолчанию не видит (Deque, axe-core 4.13). Подпись у React — обычные атрибуты, её axe проверяет.
- **Плавность прокрутки 5000 иконок** — только глазами владельца (шаг 5).
- **Живые хосты и настоящий интернет.** CI проверяет пакет на превью своей машины. Живые адреса проверяют `pnpm cdn check` и `pnpm api check`; учения с выключенным хостом — в фазе 5.
- **Старые версии браузеров.** README обещает две последние, а Playwright даёт одну — текущую.
- **Сборщики, кроме rolldown, Turbopack и webpack**, например Vite.
- **React 18 внутри Next.js**: Next.js 16 работает только с React 19. Поэтому React 18 проверяется на своей странице, без Next.js.
- **Повороты и отражения в визуальном сравнении.** Сравниваются иконки без настроек; повороты проверяют модульные тесты и страница `/render` (шаг 4).
- **Скрипт с jsDelivr и установка из npm** — шаг 11, публикация беты. До неё живые примеры проверяются на архивах `pnpm pack` этой ветки, а после — `pnpm starters --check --npm`: lock-файл, живые хосты, jsDelivr, подписи npm.
- **Сам StackBlitz и `create-next-app`** — после публикации беты: ссылки открываются вручную, в Chrome и Firefox.
- **Запас наблюдателя в iframe и прокручиваемом блоке, печать.** Так устроен IntersectionObserver браузера — README только предупреждает.
- **Подпись тега для axe.** Кнопку, где есть только иконка тега с подписью, axe пропускает: ElementInternals он не видит. Её имя проверяет дерево доступности Chrome.
- **Тест пяти минут** — знакомый разработчик и документация, после публикации беты.

## Как запустить у себя

```
pnpm check                          # всё, что в задаче check: линтер, типы, тесты с покрытием, размер
pnpm sandbox --check [--browser=…]  # тег в браузерах; отчёт .cache/reports/sandbox/check.html
pnpm example --check [--browser=…]  # Next.js и React 18; отчёт .cache/reports/example/check.html
pnpm visual [набор…] [--browser=…]  # визуальное сравнение; отчёт .cache/reports/visual/index.html
pnpm starters --check [--browser=…] # живые примеры; отчёт .cache/reports/starters/check.html
pnpm site --check [--browser=…]     # сайт документации; отчёт .cache/reports/site/check.html
```

Без `--browser` — все три браузера по очереди. На медленном компьютере удобнее один браузер, все три гоняет CI.

## Где смотреть в CI

- PR → Checks → «CI»: `check`, `browser (…)`, `starters (…)` и `site (…)` по каждому браузеру и итог `browsers`.
- На странице запуска, в Summary, — таблицы: покрытие, размер, тег, пример, визуальное сравнение, живые примеры, сайт.
- Артефакты запуска — HTML-отчёты каждого браузера со снимками и картинками расхождений: `sandbox-…`, `example-…`, `visual-…`, `starters-…`, `site-….html`. Открываются в браузере, хранятся 14 дней.
