# Фаза 2 подробно: доставка через CDN и npm

За три недели иконки становятся доступны по ссылке с двух независимых хостов, а пакеты данных — через npm. Отдельный сервер для иконок не нужен: статика плюс небольшие функции на серверах CDN. Постоянно работающий сервис нужен только поиску.

Технические решения фазы записаны в ADR-0022…0028, и промпты ниже на них опираются. Продуктовые решения ждут вашей отметки там же: [Решения (ADR)](adr/README.md)

## Как это устроено

> Схема «путь иконки · конвейер, CI, два хоста, npm» — в исходном документе в Claude, сюда она не переносилась.

Пунктир — запасной путь: ядро пакета само переключается на второй хост, когда основной не отвечает, а делается это в фазе 3. Edge API из шага 7 работает на тех же серверах CDN поверх этих файлов.

## Словарь фазы

| Термин | Что это простыми словами |
| --- | --- |
| CDN | Сеть серверов по миру, которая отдаёт файлы с ближайшего к пользователю |
| Объектное хранилище | «Диск в облаке» для файлов, например Cloudflare R2 |
| Хост | Адрес, с которого отдаются файлы, например cdn.вашдомен |
| Кэш | Сохранённая копия файла у браузера или CDN, чтобы не качать заново |
| HTTP-заголовки | Служебные пометки к файлу: сколько хранить в кэше, кому можно его загружать |
| immutable | Пометка «по этому адресу файл никогда не изменится, храни сколько угодно» |
| Манифест | Маленький файл со списком текущих версий наборов |
| CORS | Разрешение чужим сайтам загружать ваши файлы из своего кода |
| content-type | Пометка о типе файла: JSON, SVG и так далее |
| Brotli | Сжатие файлов при передаче, браузер распаковывает сам |
| Scope в npm | Пространство имён ваших пакетов, у Iconavo это @iconavo-ui |
| dist-tag | Метка версии в npm: latest — стабильная, next — предварительная |
| Provenance | Подпись, доказывающая, что пакет собран в CI из конкретного коммита |
| Секрет | Токен или ключ, который хранится в настройках GitHub, а не в коде |

## Решения перед стартом

До шагов нужно выбрать двух провайдеров, адреса и имя в npm. Решения записываются в ADR, чтобы Claude Code на них опирался.

| Решение | Варианты | Для старта |
| --- | --- | --- |
| Основной хост | Cloudflare R2 + CDN, Bunny Storage + CDN, AWS S3 + CloudFront | R2: нет платы за исходящий трафик, есть бесплатный уровень |
| Второй хост | Другой провайдер с той же раскладкой файлов | Любой из списка, кроме основного |
| Запасной путь без затрат | jsDelivr раздаёт файлы прямо из npm-пакетов | Подключить в фазе 3 как третий уровень |
| Адреса | Поддомены вашего домена | `cdn.iconavo.dev` и `cdn2.iconavo.dev`: домен `iconavo.dev` зарегистрирован на Cloudflare (ADR-0004) |
| Scope в npm | Организация с именем проекта | @iconavo-ui, занят в фазе 0 |
| Мониторинг | UptimeRobot, Better Stack и аналоги | Любой с бесплатным тарифом и оповещениями |
| Edge-функции | Cloudflare Workers, Vercel Edge Functions, Netlify Edge Functions | У того же провайдера, что основной CDN |
| Поисковый сервис | Meilisearch Cloud, Typesense Cloud, свой сервер, Postgres + pgvector | Meilisearch Cloud (ADR-0027); модель эмбеддингов — Gemini с длиной вектора 1024 (ADR-0010); качество сверяется с `docs/eval/baseline.json` |

Тарифы меняются, поэтому попросите Claude Code сравнить их на текущую дату с поиском в интернете.

## Шаги 1–3: файлы, хранилище, заголовки

Первые три шага выкладывают иконки в интернет по постоянным адресам. Цикл работы с Claude Code тот же, что в фазе 1.

### Шаг 1. Раскладка файлов, ≈1 день

Зачем: у каждого файла постоянный адрес, содержимое по которому никогда не меняется.

```
/plan Фаза 2, шаг 1. Добавь сборку раздачи: из data/ собери папку dist-cdn/ со структурой v/{версия набора}/{набор}/{иконка}.json и манифестом manifest.json (набор → текущая версия). Версию набора считай из хэшей фазы 1. Покажи дерево папок для Lucide и пример одного файла.
```

Как проверить: найдите в папке любую иконку по пути и откройте файл, а в манифесте найдите все пять наборов.

Готово, когда пересборка без изменений не меняет ни одного пути.

### Шаг 2. Хранилище и CDN, ≈2 дня

Ваша часть — создать аккаунт у провайдера, бакет и подключить поддомен. Claude Code подскажет, куда нажимать в интерфейсе провайдера.

```
/plan Фаза 2, шаг 2. Мы используем [провайдер] с бакетом [имя] и адресом cdn.[домен]. Напиши скрипт выгрузки dist-cdn/ в бакет: загружать только новые файлы, манифест — последним. Расскажи по шагам, какие ключи доступа создать и куда их положить, не показывая их в чате и не сохраняя в репозитории.
```

Как проверить: откройте в браузере `https://cdn.[домен]/manifest.json` и адрес любой иконки — файлы должны открыться.

Готово, когда выгрузка работает одной командой.

### Шаг 3. Заголовки, ≈1,5 дня

Зачем: правильные заголовки делают иконки быстрыми и доступными с любого сайта.

```
/plan Фаза 2, шаг 3. Настрой заголовки: для v/... — Cache-Control: public, max-age=31536000, immutable; для manifest.json — короткий кэш, например 5 минут. Для всех — Access-Control-Allow-Origin: *, правильный Content-Type, сжатие Brotli. Напиши команду pnpm cdn check, которая проверяет заголовки на трёх адресах и пишет «ок» или что не так.
```

Как проверить самостоятельно:

1. Откройте адрес иконки в Chrome и DevTools: F12 или Cmd+Option+I на Mac.
2. Вкладка Network, обновите страницу, кликните по запросу и откройте Headers.
3. В разделе Response headers — ответ сервера, а не Request headers — ищите `cache-control` с `immutable`, `access-control-allow-origin: *` и `content-encoding`.
   - Chrome получает сжатие `zstd`: он его понимает, и Cloudflare выбирает его. `br` и `gzip` — другим браузерам и программам.
   - На обновление страницы ответ — `304 Not Modified`: файл тот же, браузер берёт свою копию, и заголовка сжатия нет. Чтобы скачать файл заново, отметьте во вкладке Network «Disable cache».

Правила Cloudflare, которые добавляют эти заголовки, и полный список проверок `pnpm cdn check` — в ADR-0023.

Готово, когда `pnpm cdn check` пишет «ок» на всех адресах.

## Шаги 4–6: второй хост, npm, мониторинг

Эти шаги делают раздачу надёжной: запасной хост, официальные пакеты и оповещения о сбоях.

### Шаг 4. Второй хост, ≈2 дня

Зачем: если основной провайдер ляжет, иконки на сайтах ваших пользователей не должны пропасть.

```
/plan Фаза 2, шаг 4. Подключи второй хост [провайдер 2] с той же раскладкой файлов по адресу cdn2.[домен]. Выгрузка идёт на оба хоста, затем скрипт сверяет контрольные суммы файлов. Добавь в pnpm cdn check проверку второго хоста.
```

Как проверить: один и тот же адрес иконки открывается на обоих хостах, а `pnpm cdn check` пишет «ок» для двух. Само переключение между хостами появится в фазе 3, в ядре пакета.

Сверку контрольных сумм хостов делает `pnpm cdn verify`, а каждый день — workflow «Сверка хостов». Настройки Bunny, порядок выгрузки и правила зоны CDN — в ADR-0025.

Готово, когда сверка контрольных сумм не находит расхождений.

### Шаг 5. Публикация в npm, ≈2 дня

Ваша часть — аккаунт npm с двухфакторной аутентификацией и организация iconavo-ui под scope @iconavo-ui; для публичных пакетов она бесплатна.

```
/plan Фаза 2, шаг 5. Подготовь пакеты данных @iconavo-ui/icons-[набор] для пяти наборов: данные, метаданные, файл лицензии автора набора и README. Публикация — только из GitHub Actions, через trusted publishing, с provenance, под тегом next. Объясни по шагам, что настроить на npmjs.com, включая первую публикацию нового пакета, и сделай пробную публикацию одного пакета.
```

Как проверить: на странице пакета на npmjs.com есть отметка о provenance, среди тегов — next, внутри пакета — файл лицензии автора набора.

Как это устроено (ADR-0026):
- `pnpm packages prepare` собирает пакеты в `dist-npm/` и показывает, какая версия выйдет. Сама ничего не публикует.
- Публикует workflow «Публикация в npm» из `main`, а `pnpm packages verify` проверяет, что в npm ровно эта сборка.
- Первая версия нового пакета выходит через временный токен: доверенную публикацию npm включает только у существующего пакета. Порядок и все настройки npmjs.com дословно — в ADR-0026.

Готово, когда все пять пакетов опубликованы из CI.

### Шаг 6. Мониторинг и расходы, ≈1 день

Перенесён в фазу 8 — после запуска (решение владельца 23 октября 2026, ADR-0028). Промпт ниже — для того времени. До запуска:
- «Сверка хостов» и «Публикация в npm» раз в сутки проверяют хосты и пакеты, а при сбое GitHub присылает письмо;
- у зоны CDN Bunny стоит лимит трафика 100 ГБ в месяц, а автопополнение баланса — $10 (ADR-0025).

Зачем: о сбое вы должны узнать раньше пользователей, а о росте счёта — раньше конца месяца.

```
/plan Фаза 2, шаг 6. Помоги настроить мониторинг: проверка доступности обоих хостов каждые 5 минут с оповещением мне в [Telegram или почту], еженедельная сводка трафика и расходов. Подскажи, где у провайдеров включить оповещения о расходах. Запиши всё в docs/ops.md вместе с инструкцией, что делать при сбое хоста.
```

Как проверить: временно поставьте в мониторе неверный адрес — должно прийти оповещение.

Готово, когда тестовое оповещение получено, а docs/ops.md описывает действия при сбое.

## Шаги 7–8: edge API и поисковый сервис

Эти шаги дают гибкость, как у Iconify, и запускают поиск как сервис. Решения записаны в ADR-0006 и ADR-0009.

### Шаг 7. Edge API, ≈3 дня

Зачем: одна пачка вместо сотни запросов, SVG нужного цвета и размера прямо по ссылке и CSS-иконки.

```
/plan Фаза 2, шаг 7. Сделай edge-функции на [провайдер CDN] по ADR-0006 и ADR-0004: /{набор}.json?icons=… отдаёт пачку из статичных файлов; /{набор}/{иконка}.svg?color=&width=&height=&rotate=&flip= отдаёт SVG с параметрами; /{набор}.css?icons=… отдаёт CSS-иконки. Имена в пачке сортируй, ответы кэшируй на CDN. Добавь в pnpm cdn check проверки новых адресов.
```

Как проверить:

- Откройте в браузере `https://api.iconavo.dev/lucide/heart.svg?color=red&height=64` — должно появиться красное сердце размером 64 px.
- Пачка с теми же именами в другом порядке возвращает тот же ответ.
- Повторный запрос приходит из кэша. В DevTools это видно по заголовку `x-cache: HIT`: кэш ведёт сама функция, а не правила Cloudflare.
- До выкладки то же самое можно посмотреть локально: `pnpm api preview` открывает на `http://127.0.0.1:4281/` страницу с сеткой SVG, CSS-иконками, пачкой и ошибками.

Как это устроено (ADR-0024):
- Функция `apps/api` читает те же файлы в R2, что лежат на `cdn.iconavo.dev`. SVG с поворотами и отражениями собирает ядро `packages/core`: его же возьмёт пакет в фазе 3.
- Новый выпуск набора функция замечает сама, не позже чем через минуту: версия набора входит в ключ кэша (ADR-0023).
- `pnpm api build` собирает функцию в один файл. Выкладывает её только CI, workflow «Edge API», одним запросом к API Cloudflare из окружения GitHub `api`.
- Функцию `iconavo-api`, домен `api.iconavo.dev` и выключенный `workers.dev` владелец один раз настраивает в панели Cloudflare. Порядок дословно — в ADR-0024.

Готово, когда `pnpm cdn check` проверяет и статику, и edge.

### Шаг 8. Поисковый сервис, ≈3 дня

Зачем: прототип из фазы 1 становится сервисом, к которому обращаются сайт, пакет и MCP.

```
/plan Фаза 2, шаг 8. Разверни Meilisearch (ADR-0027) с моделью эмбеддингов из ADR-0010, загрузи в него индекс из конвейера и настрой обновление индекса при каждом выпуске данных. Подключи /search в edge API с кэшем популярных запросов. Замерь задержку на 100 запросах из эталона и покажи результаты таблицей.
```

Как проверить: поиск отвечает через edge, 95% ответов на 100 запросов эталона приходят не дольше чем за 0,3 с (ADR-0040), а Hit@5 по эталону не ниже прототипа — сравнение с `docs/eval/baseline.json` (ADR-0048). Для скорости — векторы слов и фраз каталога заранее, кэш запросов и сначала текст, если вектора нет (ADR-0040).

Готово, когда `/search` работает, а выпуск новых данных сам обновляет индекс.

## Ключи и секреты

Ключ доступа к хранилищу или npm — это ключ от всего проекта. Утечка позволит подменить иконки на сайтах всех ваших пользователей.

- Никогда не вставляйте токены в чат с Claude и не пишите их в файлы проекта. Храните их в менеджере паролей.
- Для CI ключи кладутся в секреты репозитория: Settings → Secrets and variables → Actions.
- Для локальной работы — файл .env, внесённый в .gitignore. Попросите Claude Code проверить это.
- Права ключей — минимальные: ключ выгрузки пишет только в свой бакет.
- Ключ выкладки функции edge API (`CLOUDFLARE_API_TOKEN`) лежит только в окружении GitHub `api`, из которого можно выкладывать лишь из `main`. По силе он равен ключу записи в бакет: функция привязана к бакету раздачи (ADR-0028).
- В npm — двухфакторная аутентификация и публикация только из CI, без личного токена на компьютере.
- Перед первой публикацией выполните `/security-review`: Claude проверит изменения на уязвимости и утечки данных.
- Если ключ попал в чат или в коммит, сразу отзовите его у провайдера и выпустите новый.

## Если что-то пошло не так

| Симптом | Вероятная причина | Что сказать Claude Code |
| --- | --- | --- |
| Чужой сайт не грузит иконку, в консоли ошибка CORS | Нет заголовка Access-Control-Allow-Origin | «Проверь CORS на бакете и в правилах CDN, покажи заголовки ответа» |
| После обновления видна старая версия | Кэшируется манифест или адрес без версии | «Проверь, что версия есть в каждом адресе, а у манифеста короткий кэш» |
| Иконки грузятся медленно | Нет сжатия или CDN не кэширует файлы | «Проверь content-encoding и попадания в кэш CDN» |
| Счёт неожиданно вырос | Горячие ссылки или боты | «Покажи топ адресов и сайтов-источников трафика за неделю» |
| Публикация в npm падает | Не настроена доверенная публикация или имя занято | «Покажи лог задачи в Actions и объясни ошибку простыми словами» |
| Хосты отдают разные файлы | Выгрузка прервалась на одном из них | «Перезапусти выгрузку и сверку сумм для второго хоста» |
