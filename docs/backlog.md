## Ждут вашего решения

- [ ] **Бесплатный тариф GitHub и закрытый репозиторий мешают планам.** Проверено по документации GitHub и npm:

    - Автослияние PR в закрытых репозиториях на GitHub Free недоступно.
    - PR, открытый роботом CI со стандартным токеном (`GITHUB_TOKEN`), не запускает проверки — нужен отдельный токен.
  - **Шаг 5 фазы 2 (ADR-0026).** Подпись provenance в npm ставится только при публикации из публичного репозитория. А репозиторий по плану закрыт до беты пакетов в фазе 3 (ADR-0036).
  - Варианты: тариф GitHub Team, открыть репозиторий раньше или публиковать данные без подписи до его открытия.
  - Когда: до шага 9 фазы 1.

- [ ] **Четыре иконки Material Symbols выходят за холст в самом источнике.**
  - Это `handshake-outline-sharp`, `satellite-alt-sharp`, `satellite-alt-outline-sharp` и `zone-person-urgent-sharp`. Нашёл контроль качества на шаге 6.

    - оставить как есть (рекомендация) — иконки останутся в отчёте как напоминание;
    - сообщить Google;
    - когда появится список известных находок, отметить их «так задумано автором».
  - Когда: до первой публикации (фаза 2).

## Исправить до первой публикации (фаза 2)

После публикации имена иконок не удаляются (ADR-0005): ошибка останется навсегда хотя бы алиасом.

- [ ] **`material-symbols:format-color` — неверное имя.**
  - Должно быть `format-color-fill-outline`: это контурный вариант иконки `format_color_fill`, ведро с краской. Затронуты 3 имени — обычное, rounded и sharp.
  - Причина: в `sources/material-symbols.ts` правило сначала меняет `_` на `-`. После этого конец названия `_fill` не отличить от пометки залитого варианта `-fill`.
  - Исправление: замену `_` → `-` поставить последней. После правки сверить имена с Iconify. Должны остаться только расхождения версий: `done-outline*` есть только у нас, `power-plug*` — только у Iconify.

- [ ] **`fluent-emoji-flat:pinata` — у Iconify `piata`.**
  - Правило `ñ` → `n` в `sources/fluent-emoji-flat.ts` даёт имя, которого нет у Iconify. Ассистент, который пишет имя по памяти, промахнётся.
  - Рекомендация: основное имя как у Iconify (`piata`), а `pinata` добавить алиасом, когда появятся алиасы (шаги 7–8).

## Ошибки в коде — сейчас не мешают

- [ ] **Валидатор пропускает алиас на несуществующую иконку `constructor`.**
  - Где: `packages/schema/src/cross.ts`, функция `checkNamesAndAliases`.
  - Причина: проверка через `in` видит встроенные свойства объекта.
  - Исправление: `Object.hasOwn`.
- [ ] **Санитайзер считает опасным закодированный перевод строки внутри контура.**
  - Где: `packages/pipeline/src/sanitize/policy.ts`, функция `checkValue`. Речь о `&#10;`, `&#9;`, `&#13;` в значении атрибута.
  - Последствие: атрибут удаляется, а весь набор останавливается с пометкой «признак подмены источника».
  - В пяти наборах такого нет, но при расширении каталога до 15–25 наборов (фаза 5) будут ложные тревоги.
  - Исправление: такие символы заменять пробелом.
- [ ] **Конфликт имён не останавливает загрузку.**
  - Где: `packages/pipeline/src/cli.ts`, команда `fetch`.
  - Сборка (`pnpm data`) с шага 5 останавливает набор при конфликте имён. А загрузка конфликт и нарушение правила имён только печатает и завершается успешно, хотя по ADR-0001 должна остановиться.
  - Когда: до шага 9, где решения принимает CI.
- [ ] **В `info.json` разрешены лишние поля.**
  - Где: `packages/schema/src/info.ts` (`looseObject`).
  - CLAUDE.md говорит, что в наших файлах лишние поля запрещены. Значит, опечатка в необязательном поле пройдёт незамеченной.
  - Решить: сделать схему строгой или записать исключение (совместимость с форматом Iconify).
- [ ] **Минимальная версия Node указана неточно.**
  - В `package.json` стоит `"node": ">=22"`. Но конвейер читает конфиги `sources/*.ts` напрямую, а это работает только с Node 22.18 и новее.
  - Исправление: указать `>=22.18`.

## Не забыть на шаге 7

- **Загрузчик скачивает git-источники с переводами строк CRLF.**
  - Так происходит, если в git включён `core.autocrlf`, как на этом компьютере: CRLF есть в SVG и JSON Lucide в `.cache/sources`.
  - Данные пока не страдают: разбор XML сводит CRLF к LF, а размеры исходников в отчёте сборки считаются с LF.
  - Но на шаге 7 в `data/` пойдут тексты LICENSE и теги из JSON. До этого запускать git в загрузчике с `-c core.autocrlf=false` (`packages/pipeline/src/sources/git.ts`).

## Не забыть на шаге 8

- **Алиасы-переименования.**
  - У Iconify есть 268 старых имён Material Symbols после переименований у Google (`ad-units → mobile-text`).
  - Lucide хранит старые имена в JSON рядом с иконками (ADR-0012).
  - Плюс `pinata` (см. выше).
  - Решить, какие из них брать.
- **Отпечатки и ID.**
  - В ID иконки есть её имя (`{набор}--{иконка}-{n}`), поэтому у иконок с ID (21 во Fluent) тело меняется при переименовании.
  - Перед расчётом отпечатка имя в ID нужно заменять заглушкой, иначе такое переименование не найдётся.

## Не забыть на шаге 9

- **Итог контроля качества для PR из CI.**
  - Сейчас набор со «СТОП» даёт код выхода 1, а подробности есть только в `qc.html`.
  - Для PR из CI (ADR-0019) нужна короткая сводка, которую читает машина, например `qc.json` рядом с отчётом. По ней CI решит, можно ли слить PR автоматически и что вынести в описание.
  - Ещё нужно решить, где хранить `qc.html` из CI, чтобы на него можно было сослаться из PR. Например, как артефакт задачи.
