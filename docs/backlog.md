- **Порядок вариантов на сайте (фаза 4).** В `metadata.json` ключи `suffixes` записаны по кодам символов, а не в порядке Thin → Light → Regular → Bold. Сайту нужен свой порядок.
- **Список известных находок контроля.**

  - Не попадает иконка, у которой изменился исходник автора, а результат остался тем же.
  - Точнее был бы список известных находок, как для четырёх обрезанных Material Symbols.
- **Ежедневная пересборка открытого PR Fluent Emoji.**
  - Пока PR робота открыт, он пересобирается каждый день, а для Fluent это ≈254 МБ скачивания.
  - Если станет мешать — не собирать, когда не изменились ни версия, ни main.
- **PR, закрытый роботом, тоже считается отклонённым.** Робот закрывает свой PR, когда версия уже в main. Если автор потом откатит выпуск и выпустит ту же версию снова, робот её не предложит. Случай редкий.
- **Расписание выключается после 60 дней без активности.** Это правило GitHub для открытых репозиториев: касается робота обновления (`update.yml`) и «Сверки хостов» (`verify.yml`). Пока идёт разработка, активность есть; после запуска — следить мониторингом (ADR-0028).
- **`pin` по имени тега.** `pnpm sources pin lucide 1.60.0` сейчас не работает: нужен полный хэш коммита. Для наборов на тегах удобно принимать имя тега.
- **Векторы только на компьютере владельца (шаг 11, ADR-0047).** В git их нет, поэтому на новой машине и в CI они считаются заново: около 100 ₽ и полчаса на три модели. Для поискового сервиса фазы 2 решить, кто их считает: CI с ключом Polza в секретах или сам Meilisearch.
- **Тип задачи Gemini не передаётся (шаг 11).** У gemini-embedding-001 есть режимы «запрос» и «документ» (`RETRIEVAL_QUERY`, `RETRIEVAL_DOCUMENT`), но через Polza они не передаются. Если на замере шага 12 Gemini окажется близко к лучшей, проверить её с ключом Google напрямую. Gemini выбрана (ADR-0010): проверить с ключом Google и типами «запрос» и «документ» в фазе 2, вместе с быстрым путём к модели (ADR-0040).
- **Вектор запроса через Polza считается около 2 секунд (шаг 11, ADR-0047).** Так у всех трёх моделей, с компьютера владельца; у OpenAI первые запросы шли до 7 секунд. Для поиска по мере ввода (ADR-0040) это слишком медленно. Цель владельца — выдача не позже 0,3 с после паузы в наборе для 95% поисков (ADR-0040, 21 октября 2026). Способ на фазу 2: векторы слов и фраз каталога заранее, кэш запросов, сначала текст, если вектора нет; быстрый путь к модели — ключ провайдера напрямую или модель внутри Cloudflare. Сначала замерить с рабочего сервера.
- **«Корзина» двусмысленна (шаг 11).** Все три модели понимают её как магазинную корзину, а не мусорную: с «trash» совпало 0–1 из 5. Проверено на замере шага 12:
  - «мусорная корзина» и «добавить в корзину» находятся — 5 из 5 в пятёрке гибрида Gemini;
  - «корзинка», где ожидается мусорное ведро, не находится ни в одном варианте: все выдают магазинные корзины.

  Дальше — в пункте про разговорные слова.
- **Разговорные слова и абстракции (шаг 12).** Главные промахи гибрида Gemini:
  - «бутерброд» находит бутерброды, а не меню;
  - «корзинка» находит магазинные корзины, а не мусорное ведро;
  - абстракции («успех», «эффективность», quality) — слабее всего: Hit@5 по этому типу 76%.

  Варианты: разговорные синонимы при обогащении (ADR-0020) или словарь разговорных замен. Настраивать только по рабочей части эталона.
- **Material Symbols лишний раз в пятёрке (шаг 12).** В первой пятёрке гибрида Gemini у набора 38% мест при 29% подходящих иконок, и подходят из этих мест только 44% (у Lucide — 71%, у Phosphor — 77%). Разобрать на поисковом сервисе в фазе 2: похожие иконки одного понятия, тексты описаний.
- **Замер поиска по наборам (фаза 4).** Решение владельца 21 октября 2026: Hit@5 с фильтром по каждому набору мерить вместе с фильтром на сайте. Нужно 1 885 новых пар разметки, около 80 ₽; включается настройкой `PER_SET_MODEL` в `search/config.ts`.
- **Кэш векторов запросов на сайте (фаза 2).** На шаге 12 векторы запросов замера и страницы поиска хранятся по хэшу запроса (`.cache/search/queries`, ADR-0048). Для сайта нужен кэш популярных запросов на edge (ADR-0009).
- **Замер поиска в CI (фаза 2).** ADR-0021 требует замер при каждом изменении поиска, данных или модели, но векторы иконок есть только на компьютере владельца (ADR-0047), а запросам нужен ключ Polza. Решить вместе с поисковым сервисом: векторы считает CI с ключом в секретах или сам Meilisearch.
- **pixelmatch 8.** Версия 8.0.0 (6 октября 2026) считает цвет иначе (OKLab) и лучше работает с прозрачностью. Обновлять, когда версия проживёт хотя бы несколько недель. При обновлении меняются числа отличий, поэтому пороги ADR-0016 нужно перепроверить на всех наборах.
- **Уборка старых версий в хранилищах (шаги 2 и 4 фазы 2, ADR-0022).** Выгрузка ничего не удаляет, а по ADR-0005 старые версии хранятся год. Нужна отдельная команда, которая убирает из `v/` версии старше 12 месяцев, которых нет в манифесте, — в бакете R2 и в хранилище Bunny: сначала показ, потом удаление. До запуска каждое хранилище растёт примерно на размер набора при каждом его обновлении.
- **Смена формата файлов уже выложенной версии (шаг 2 фазы 2, ADR-0022).** Папка `v/{версия}/` неизменяема и в бакете не перезаписывается: если код раздачи начнёт писать другие байты для той же версии (например, повороты в SVG на шаге 7), выгрузка остановится конфликтом. Тогда нужна новая схема адресов — `v2/` или версия формата в пути; решать при первом случае.
- **Предварительные запросы `OPTIONS` (шаг 3 фазы 2, ADR-0023).** Сейчас на них ответ 403: у бакета нет настройки CORS. Обычный GET их не делает. Если понадобятся запросы со своими заголовками — настройка CORS у бакета (`AllowedOrigins: ["*"]`, методы GET и HEAD) вдобавок к правилу заголовков.
- **Кэш манифеста на CDN (шаги 3 и 4 фазы 2, ADR-0023, ADR-0025).** Манифест идёт мимо кэша Cloudflare и Bunny: проверка и мониторинг видят файл в хранилище. Его можно кэшировать без потери «5 минут» — Cloudflare отдаёт возраст копии в `Age`. Решить на шаге 7 вместе со сбросом кэша через API.
  - У второго хоста свой довод: хранилище Bunny в одном регионе (Франкфурт), и при его сбое манифест `cdn2` не откроется, хотя файлы версий лежат в кэше CDN.
  - Варианты: копия манифеста в кэше CDN Bunny с отдачей устаревшей копии, пока хранилище недоступно, или реплика хранилища во втором регионе.
- **Запасной выход при долгом сбое Bunny (шаг 4 фазы 2, ADR-0025).** Манифесты пишутся, только когда новая версия есть на обоих хостах, поэтому пока Bunny недоступен, новые иконки не выходят и на `cdn.iconavo.dev`. До запуска это безопасно. После запуска понадобится явный способ выложить версию только на основной хост, например флаг выгрузки с записью в отчёте и догонялкой второго хоста потом.
- **`iconavo.b-cdn.net` для ядра (фаза 3, ADR-0025, ADR-0030).** DNS домена `iconavo.dev` — у Cloudflare, поэтому при сбое DNS Cloudflare `cdn2.iconavo.dev` не откроется. Собственный адрес зоны Bunny от Cloudflare не зависит и отдаёт то же самое: правила зоны не привязаны к адресу. Решить в фазе 3, ставить ли его в запасной список ядра после `cdn2`.
- **Ключ только для чтения для сверки (шаг 4 фазы 2).** «Сверке хостов» запись не нужна, а сейчас у неё те же ключи, что у «Выкладки». Можно дать ей токен R2 «Object Read» и Read-only password хранилища Bunny — отдельные секреты.
