- **Уборка старых версий в хранилищах (шаги 2 и 4 фазы 2, ADR-0022).** Выгрузка ничего не удаляет, а по ADR-0005 старые версии хранятся год. Нужна отдельная команда, которая убирает из `v/` версии старше 12 месяцев, которых нет в манифесте, — в бакете R2 и в хранилище Bunny: сначала показ, потом удаление. До запуска каждое хранилище растёт примерно на размер набора при каждом его обновлении.
- **Смена формата файлов уже выложенной версии (шаг 2 фазы 2, ADR-0022).** Папка `v/{версия}/` неизменяема и в бакете не перезаписывается: если код раздачи начнёт писать другие байты для той же версии, выгрузка остановится конфликтом. Тогда нужна новая схема адресов — `v2/` или версия формата в пути; решать при первом случае. Шаг 7 формат статики не менял: повороты и отражения делает edge API, а SVG ядра без параметров побайтно равен файлам статики — это проверяет тест (ADR-0024).
- **Предварительные запросы `OPTIONS` (шаг 3 фазы 2, ADR-0023).** Сейчас на них ответ 403: у бакета нет настройки CORS. Обычный GET их не делает. Если понадобятся запросы со своими заголовками — настройка CORS у бакета (`AllowedOrigins: ["*"]`, методы GET и HEAD) вдобавок к правилу заголовков.
- **Кэш манифеста на CDN (шаги 3 и 4 фазы 2, ADR-0023, ADR-0025).** Решено на шаге 7 (ADR-0023): манифест `cdn.iconavo.dev` остаётся мимо кэша Cloudflare. Сброс кэша через API не понадобился: edge API берёт версию набора в ключ кэша.
  - Открыт довод второго хоста: хранилище Bunny в одном регионе (Франкфурт), и при его сбое манифест `cdn2` не откроется, хотя файлы версий лежат в кэше CDN.
  - Варианты: копия манифеста в кэше CDN Bunny с отдачей устаревшей копии, пока хранилище недоступно, или реплика хранилища во втором регионе.
- **Ограничение частоты для `api.iconavo.dev` (фаза 7, ADR-0024, ADR-0028).** Запросы с непопулярными наборами имён идут мимо кэша ответов. С шага 6 фазы 3 знакомые файлы имён лежат в кэше дата-центра (ADR-0024), но новые иконки по-прежнему читают R2. На бесплатном тарифе Workers такие запросы сдерживает суточный потолок в 100 000, а у платного тарифа потолка нет. Перед переходом на платный нужно правило ограничения частоты (Rate Limiting Rule зоны iconavo.dev, у бесплатной зоны — одно правило).
- **Сбой кэша у `/search` даёт 500 (шаг 6 фазы 3, ADR-0024, ADR-0049).** Поиск готового ответа в кэше дата-центра (`search/handler.ts`) ничем не защищён: если Cache API откажет, поиск ответит 500, а не досчитает выдачу. У пачек, SVG и CSS это исправлено на шаге 6: сбой кэша — как промах. Для поиска — то же самое, отдельным PR.
- **Workers Cache для edge API (после запуска, ADR-0024).** Новый кэш Workers многоуровневый: попадание не запускает функцию, и холодных пачек меньше. Ему нужны wrangler и сброс по тегам после каждого выпуска набора, поэтому на шаге 7 взят Cache API. Вернуться, когда вырастет трафик (фаза 8, вместе с расходами).
- **Задержка холодной пачки из дальних регионов (фаза 3, ADR-0030).** Пачку, которой нет в кэше дата-центра, функция собирает из R2 по 6 файлов за раз: 30 имён — около пяти раундов, 100 — около семнадцати. Ядро переключается на статику, если хост молчит 750 мс — сделано на шаге 3 фазы 3, 27 октября 2026. Замерить из нескольких регионов вместе с ядром; если мало — кэш файлов имён в памяти или Workers Cache.
- **Запоминать отказавший хост (после беты, ADR-0030).** Сейчас каждая новая пачка начинает с `api`: если API молчит, иконки появляются на 0,75 с позже. У Iconify последний ответивший хост становится первым до конца жизни страницы. У нас запасной уровень — статика с запросом на иконку, поэтому запоминать стоит только надолго отказавший API, и с возвратом к нему. Решать по данным мониторинга (фаза 8).
- **Манифест статики — на жизнь страницы (ADR-0030).** Если API недоступен, а набор вышел новой версией, пока страница открыта, новые иконки статика не найдёт до перезагрузки: ядро запомнит их как «нет». Вариант — держать манифест в памяти столько же, сколько его `max-age`, 5 минут; это около 0,03 КБ кода.
- **Всплеск запросов статики на медленной сети (шаг 6 фазы 3, ADR-0030, ADR-0025).** Пачка API приходит около порога 750 мс, и к статике уходят манифесты и файлы, которые потом отменяются. Часть этого трафика — на Bunny с лимитом 100 ГБ в месяц. Замерить на учениях фазы 5; если мешает — отдельный порог для перехода с API на статику.
  - Шаг 5, 27 октября 2026, с компьютера владельца. Пачка из 24 имён, которой нет в кэше дата-центра, — 0,67 с, из кэша — 0,11–0,13 с. Когда пачки уходят сразу несколько, они отвечают около 1,2 с.
  - Ленивая загрузка тега это усиливает: каждая прокрутка даёт новую пачку, которой нет в кэше. На странице «5000 иконок» с живым API первые 216 иконок дали 213 запросов — почти всё по одной со статики. Через превью API на этом компьютере — 7 запросов на 160 иконок, 5000 иконок — около 216 запросов, все пачками.
  - Варианты:
    - отдельный порог для перехода с API на статику, например 1,5–2 с;
    - больше имён в пачке при прокрутке;
    - кэш файлов имён в функции (пункт выше).
  - Решение владельца 27 октября 2026 (ADR-0030) — отдельный шаг 6 фазы 3, сразу после шага 5:
    1. кэш файлов иконок в функции edge API;
    2. затем по замеру — отдельный порог перехода на статику, около 1,5 с;
    3. пачки при прокрутке не укрупнять.
- **Сигнал отмены для `setLoader` (после беты).** Загрузчик сейчас не отменить: молчание дольше 5 с считается сбоем, а поздний ответ всё равно принимается. Второй аргумент `signal` — расширение README.
- **«Нет» на сервере живёт до перезапуска (шаг 7, ADR-0033).** На сервере хранилище у модуля, поэтому имя, которого не было в момент запроса — новая иконка до выпуска набора или опечатка, — остаётся «нет» до перезапуска процесса. Браузер запрашивает его сам. Решить вместе с адаптером React.
- **Свои селекторы, `pseudo` и `var` в CSS edge API (ADR-0024).** У Iconify они есть. На шаге 7 их нет: это главная поверхность для подмены CSS. Если понадобятся — только по закрытым правилам, без `{ } ; \ < >`.
- **Адреса `/collections`, `/collection` и `/last-modified` (фаза 4, ADR-0004).** Делать вместе с сайтом и MCP: им нужны данные о наборах (`info.json`), которых на раздаче пока нет.
- **Запасной выход при долгом сбое Bunny (шаг 4 фазы 2, ADR-0025).** Манифесты пишутся, только когда новая версия есть на обоих хостах, поэтому пока Bunny недоступен, новые иконки не выходят и на `cdn.iconavo.dev`. До запуска это безопасно. После запуска понадобится явный способ выложить версию только на основной хост, например флаг выгрузки с записью в отчёте и догонялкой второго хоста потом.
- [x] **`iconavo.b-cdn.net` для ядра (фаза 3, ADR-0025, ADR-0030).** DNS домена `iconavo.dev` — у Cloudflare, поэтому при сбое DNS Cloudflare `cdn2.iconavo.dev` не откроется. Собственный адрес зоны Bunny от Cloudflare не зависит и отдаёт то же самое: правила зоны не привязаны к адресу. Решить в фазе 3, ставить ли его в запасной список ядра после `cdn2`. Решено 26 октября 2026 (шаг 1 фазы 3, решение владельца): да, последним; зону `iconavo` не удалять никогда (ADR-0025, ADR-0030).
- **Первая версия нового набора после января 2027 (фаза 5, ADR-0026).** npm перестанет пускать токены с обходом двухфакторной защиты к прямой публикации: цель — январь 2027 (GitHub Changelog, 31 июля 2026). Тогда временный токен сможет только подготовить версию (`npm stage publish`), а выпустит её владелец с 2FA на npmjs.com. Новый набор фазы 5 — это как раз новый пакет: до него добавить в workflow подготовку версии вместо публикации и записать порядок в ADR-0026.
- **Обогащение новых иконок в CI (фаза 5, ADR-0046, ADR-0019).** Решение владельца 27 октября 2026: автоматизировать к фазе 5, когда наборов станет 15–25 и обновления пойдут чаще.
  - Сейчас робот обновления описаний не делает: после слияния его PR `pnpm enrich {набор}` запускается вручную. Без описаний новая иконка находится только по английскому имени и тегам автора — без русских синонимов и без вектора.
  - Векторы поиска уже считаются сами: «Поисковый индекс» после «Выкладки». Локальный `pnpm embed` нужен только для прототипа и замеров, автоматизировать его не нужно.
  - Вариант — ежедневный workflow «Описания» на `main`: находит базовые иконки без описаний, запускает `pnpm enrich` с лимитом `--max-cost` и открывает PR с `search.json` и автослиянием. Отчёт `.cache/reports/enrich/` — артефакт для выборочной проверки (ADR-0020).
  - Ключ `ANTHROPIC_API_KEY` — секрет окружения GitHub только для `main`, как у `search` и `api`.
  - Пакет Message Batches отвечает от минут до часа: отправить с `--no-wait`, результат забрать следующим запуском.
  - На 27 октября 2026 без описаний 10 базовых иконок — по 5 у Lucide и Material Symbols после PR робота #60 и #61; по оценке `pnpm enrich --dry-run` — около $0,002.
- **Одобрение каждой версии npm перед запуском (шаг 5 фазы 2, ADR-0026).** Сейчас CI публикует сам (решение владельца 23 октября 2026).
  - npm умеет «публикацию с одобрением» (`npm stage publish`): версия ждёт, пока сопровождающий подтвердит её на npmjs.com с 2FA. Так взлом CI не выпустит пакет без человека.
  - Цена — каждое обновление набора ждёт владельца, а CI не видит ждущие версии (`npm stage list` требует входа).
  - Решить к фазе 7, когда у пакетов появятся пользователи. Другой вариант человеческого шага — обязательные проверяющие у окружения `npm` в GitHub.
- **Тег `latest` в день запуска (фаза 7, ADR-0026).**
  - `NPM_TAG` в `src/npm/config.ts` → `"latest"`: CI выпустит новую версию каждого пакета под `latest`.
  - До этого `latest` указывает на первую версию: npm ставит его на первую публикацию, даже с `--tag next`. Проверено 23 октября 2026: у всех пяти пакетов `latest` — `1.0.0`, а `next` — `1.0.1`.
- **Журнал изменений для пользователей npm (фаза 4).** В пакете нет CHANGELOG: `data/{набор}/CHANGELOG.md` написан для владельца. Пользователю пакета нужен свой — что вышло в каждой версии npm. Кандидат — лента «Что нового» сайта (ADR-0018) со ссылкой из README.
- **`homepage` пакетов npm (фаза 4).** Поля нет, пока нет сайта; потом — страница набора на сайте.
- [x] **jsDelivr из пакетов npm (фаза 3, ADR-0025).** Теперь пакеты есть, и jsDelivr отдаёт их файлы по адресу вида `cdn.jsdelivr.net/npm/@iconavo-ui/icons-lucide@next/icons.json`. Решить вместе с запасным списком ядра (ADR-0030), нужен ли третий уровень. Решено 26 октября 2026 (шаг 1 фазы 3, решение владельца): для иконок — нет, в пакетах только целые наборы, от 0,1 до 1,5 МБ в сжатом виде. С jsDelivr идёт только скрипт тега для страниц без сборщика (ADR-0032).
- **`stroke-width` в SVG edge API (фаза 4, ADR-0041, ADR-0031).** Экспорт «Ссылка» на сайте — адрес SVG с параметрами, а толщины линии среди них пока нет. Добавить параметр по правилу ядра: менять `stroke-width` там, где он задан у рисунка, — готовая функция ядра `setStrokeWidth` (шаг 4 фазы 3).
- [x] **Одна политика Trusted Types на страницу (шаг 5, ADR-0032).** Две копии ядра, которые создают политику `iconavo`, при строгой CSP без `'allow-duplicates'` получат исключение у второй. Политику создавать лениво, в try/catch, как Iconify, и хранить в общем хранилище (ADR-0030). Сделано на шаге 5, 27 октября 2026:
  - политика создаётся при первой нарисованной иконке, в try/catch;
  - лежит под отдельным ключом `Symbol.for("iconavo.trusted-types")` без версии формата — её найдёт и следующая версия хранилища, и React;
  - на странице `/tag` с двумя копиями — один запрос на создание (ADR-0032).
- **`inline` и `color` в React без атрибута `style` (шаг 7, ADR-0033, ADR-0031).**
  - `inline` — это `vertical-align: -0.125em`, а атрибутов `style` в серверном HTML нет: нужен другой способ.
  - `color` ядро ставит атрибутом `<svg>`. CSS страницы, заданный самому `<svg>` (например, класс `text-…` в `className`), главнее атрибута. Проверить, устраивает ли это, или нужен другой способ.
- **Свой адрес скрипта на `cdn.iconavo.dev` (к запуску, ADR-0032).** Сейчас скрипт тега для страниц без сборщика — с jsDelivr. Свой адрес — один бренд и наши два хоста, но нужна выгрузка файлов пакета и правка ADR-0022.
- **События и состояния тега (после беты, ADR-0031).** `load` и `error` или CSS `:state(loading | loaded | missing | error)` — для своих заглушек и тестов. В 0.1 их нет.
- **Запас наблюдателя тега не везде (шаг 5, ADR-0032).** Запас в полэкрана (`rootMargin`) не действует во внутренних прокручиваемых блоках и в чужих iframe: там иконка грузится, только когда её уже видно. Чужой iframe — это и живые примеры StackBlitz шага 10. Вариант — `scrollMargin` у IntersectionObserver, когда его поддержат все браузеры из ADR-0034.
- **Повтор при прокрутке назад (шаг 5, ADR-0032).** Неудавшуюся иконку тег запрашивает снова, когда его возвращают на страницу, меняют имя или ту же иконку показывает новый тег, но не при прокрутке назад: тег активен навсегда. Если понадобится — снова наблюдать тег после «ошибки» и отвечать только на переход «не видно → видно».
- **Невидимые иконки не печатаются (шаг 5).** Тег, который ни разу не подходил к видимой части страницы, при печати остаётся пустым. Для печати есть `noobserver`; упомянуть в документации шага 10.
- **Подпись тега в Safari не проверена (шаг 5, ADR-0035).** Подпись через ElementInternals проверена по дереву доступности Chrome; Firefox — Экранным диктором; в WebKit на Windows скринридера нет. VoiceOver в настоящем Safari — на Mac, к бете.
- **Бюджет тега впритык (шаг 5, ADR-0034).** Тег сверх ядра — 1,98 КБ из 2. Новое свойство тега придётся окупать, например короче тексты предупреждений, или осознанно пересматривать бюджет.
- **Имена иконок в типах (после беты).** Автодополнение имён в TypeScript по наборам; в 0.1 имя — просто строка.
- **Серверные компоненты React без обёртки (после беты, ADR-0033).** Асинхронный `Icon` для серверных компонентов (условие экспорта `react-server`) рисовал бы иконку в HTML без `IconavoProvider`. Ему нужен запрос с сервера на каждую страницу и кэш.
- **Подписи npm в ежедневной проверке.** `pnpm packages verify` сверяет provenance по содержимому, но не проверяет криптографическую подпись. Для этого есть `npm audit signatures` в проекте, который ставит пакеты, — добавить в проверку примеров фазы 3.
- **Скорость поиска из дальних регионов (фаза 8, ADR-0049).** С машины GitHub в США 95% первых ответов приходят за 0,37 с при цели 0,3 с: Meilisearch и бакет — во Франкфурте, и первый ответ из США обычно приходит только по словам.
  - Варианты: поисковая часть функции рядом с Meilisearch (Smart Placement, отдельная функция для `/search`) или короткий срок вне Европы.
  - Решать по данным о том, откуда приходят пользователи.
- **Ключ или обход лимита поиска для сайта и MCP (фаза 4, ADR-0049).** Сайт с серверным рендером и MCP ходят в `/search` с немногих адресов, и лимит 60 поисков в минуту с адреса им мал.
- **Робот обновления ищет свои PR среди 30 последних** (проверка безопасности 26 октября 2026).
  - `update.yml` берёт `gh pr list --limit 30` и только потом отсеивает PR форков.
  - Тридцать PR из веток форка с именем `auto/{набор}` вытеснят PR робота из списка. Тогда робот снова предложит отклонённую версию или пересоберёт ветку поверх коммита владельца.
  - Исправление — искать по владельцу ветки: `head=iconavo:auto/{набор}`.
- **Ключ только для чтения для замера сервиса в CI (ADR-0049).** Шаг «Замер сервиса» в `search.yml` получает ключ администратора Meilisearch, хотя хватило бы ключа только для чтения — отдельного секрета `MEILISEARCH_READ_KEY` в окружении `search`.
- **Фразы робота индекса — полтора часа с нуля (ADR-0049).** Каждая фраза — отдельная запись в бакет, а с нуля их считают только при смене модели или эмбеддера. Если понадобится быстрее — больше записей одновременно или пачки фраз в одном файле.
- **Ключ только для чтения для сверки (шаг 4 фазы 2).** «Сверке хостов» запись не нужна, а сейчас у неё те же ключи, что у «Выкладки». Можно дать ей токен R2 «Object Read» и Read-only password хранилища Bunny — отдельные секреты.
