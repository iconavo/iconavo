## Шаг 1. Название

Имя войдёт во всё: в домен, в scope `@iconavo-ui` на npm, в тег `<iconavo-icon>` и в адреса API. Поменять его потом очень дорого, поэтому на выбор стоит потратить пару дней.

- [x] Придумать 5–10 вариантов: латиница, строчные буквы, коротко, легко произнести и записать на слух.
- [x] Для каждого проверить, свободны ли домен, организация на GitHub, scope в npm и аккаунты в соцсетях.
- [x] Поискать совпадения среди зарегистрированных товарных знаков — в WIPO Global Brand Database и TMview. Я не юрист: при серьёзных сомнениях нужна консультация специалиста.

Промпт для Claude в чате, с поиском в интернете:

```
Помоги проверить названия для платформы иконок: [варианты]. Для каждого проверь домены .com и .dev, организацию на GitHub, scope в npm и явные совпадения с известными брендами. Сведи всё в таблицу.
```

Готово, когда имя выбрано и все проверки пройдены.

## Шаги 2–5. Защита и аккаунты

Аккаунты — фундамент безопасности проекта: тот, кто ими завладеет, сможет подменить иконки на сайтах всех ваших пользователей. Поэтому сначала защита, потом всё остальное.

### Шаг 2. Менеджер паролей и двухфакторная защита

- [x] Установить менеджер паролей, например 1Password или *Bitwarden*. Все пароли, ключи и коды восстановления проекта хранятся только там.
- [x] Включать двухфакторную защиту в каждом новом аккаунте — через приложение-аутентификатор или ключ доступа (passkey). Коды восстановления сразу сохранять в менеджер паролей.

### Шаг 3. Домен и Cloudflare

- [x] Создать аккаунт Cloudflare с двухфакторной защитой.
- [x] Купить домен — проще всего прямо в Cloudflare Registrar, тогда домен и DNS будут в одном месте. Если домен куплен у другого регистратора, переключите его на DNS Cloudflare.
- [x] Способ оплаты для хранилища R2 и Workers понадобится к фазе 2, сейчас его можно не добавлять.

### Шаг 4. GitHub

- [x] Личный аккаунт с двухфакторной защитой.
- [x] Организация с именем проекта на бесплатном плане. Владелец — вы, а репозиторий создаст Claude Code в шаге 9.

### Шаг 5. npm

- [x] Аккаунт на npmjs.com с двухфакторной защитой.
- [x] Организация `iconavo-ui`: так вы занимаете scope `@iconavo-ui` — имя `@iconavo` оказалось занято. Для публичных пакетов это бесплатно, а публиковать пакеты будет CI, а не вы вручную.

## Шаги 6–7. Компьютер и папка проекта

### Шаг 6. Программы

- [x] Claude Code у вас уже есть.
- [x] Git, Node.js LTS, pnpm и GitHub CLI поставит Claude Code; вы вводите пароль администратора и подтверждаете системные окна.
- [x] Редактор кода, например VS Code, — чтобы открывать файлы проекта и вписывать ключи в `.env`.
- [x] По желанию — GitHub Desktop, чтобы видеть историю изменений без терминала.

Промпт для Claude Code:

```
Я продуктовый дизайнер, не разработчик. Проверь, установлены ли у меня Git, Node.js LTS, pnpm и GitHub CLI, и помоги поставить недостающее. Потом помоги войти в GitHub через gh auth login. Объясняй каждый шаг простыми словами.
```

### Шаг 7. Папка проекта и план

- [x] Создать папку проекта, например `Projects/iconavo`.
- [x] Скопировать в папку проекта готовую папку `docs/`: в ней `README.md` с оглавлением, `roadmap.md`, `phase-0.md`…`phase-3.md` и папка `adr/` с отдельным файлом на каждое решение. Claude Code будет опираться на неё в каждой сессии.

## Шаги 8–10. Старт с Claude Code

### Шаг 8. Первый запуск

- [ ] Открыть папку проекта в Claude Code и выполнить `/init` — появится файл CLAUDE.md.
- [ ] Дописать в CLAUDE.md правила из вкладки «Фаза 1 подробно», раздел «Подготовка», и строку: «План и решения — в docs/, ADR — в docs/adr/».

### Шаг 9. Репозиторий, монорепозиторий и CI

Рекомендация: репозиторий закрытый до беты, а открывается вместе с публичной бетой пакетов (ADR-0036).

```
/plan Я продуктовый дизайнер, не разработчик. План и решения лежат в docs/. 1) Прочитай docs/README.md: там план, вкладки фаз и решения в docs/adr/. 2) Создай монорепозиторий по ADR-0007: pnpm workspaces, TypeScript, папки packages/, apps/, sources/, data/. 3) Допиши в CLAUDE.md команды проекта. 4) Создай закрытый репозиторий в организации iconavo на GitHub через gh и отправь туда код. 5) Настрой CI по фазе 0: Biome, проверка типов, Vitest с одним примером теста, size-limit. 6) Защити ветку main: слияние только через pull request с зелёными проверками. Объясняй простыми словами.
```

### Шаг 10. Проверка

- [ ] На вкладке Actions в GitHub последний запуск зелёный.
- [ ] Попросите Claude в отдельной ветке специально сломать тест: в pull request должен появиться красный крестик, а кнопка слияния — заблокироваться.
- [ ] Выполните `/security-review`: в репозитории не должно быть ключей и паролей.

## Шаги 11–13. Ключи для фазы 1 и секреты

Ключи понадобятся для эталона поиска (шаг 14) и для обогащения в шаге 10 фазы 1. Их можно завести и в первые недели фазы 1.

### Шаг 11. Claude Platform

- [ ] Аккаунт Claude Platform с двухфакторной защитой и способом оплаты. Это отдельно от подписки Max 5x: подписка — для вас, API — для программ конвейера.
- [ ] Месячный лимит расходов, например $50 на время фазы 1.
- [ ] Ключ для конвейера — сразу в менеджер паролей.

### Шаг 12. Эмбеддинги

- [ ] Ключи двух облачных кандидатов из ADR-0007: OpenAI и Google (ключ Gemini выдаётся в Google AI Studio). По желанию — ещё Voyage AI.
- [ ] Лимит расходов у каждого провайдера.
- [x] Вместо открытой BGE-M3 берём Qwen3-Embedding-8B: она доступна через тот же ключ Polza AI, запускать её на компьютере не нужно (ADR-0007).

### Шаг 13. Секреты

- [ ] Попросите Claude Code создать `.env.example` с именами ключей без значений и добавить `.env` в `.gitignore`.
- [ ] Сами впишите значения в `.env` через редактор. В чат с Claude ключи не вставляются никогда.
- [ ] Для CI внесите те же ключи в GitHub: Settings → Secrets and variables → Actions.

## Шаги 14–15. Эталон поиска и лендинг

### Шаг 14. Эталон поиска

Эталон генерирует нейросеть — это ваше решение из ADR-0021. Берётся модель OpenAI или Google, а не Claude: Claude будет делать обогащение, и эталон не должен ему подыгрывать.

```
/plan По ADR-0021 сгенерируй эталон поиска моделью OpenAI или Google, не Claude. 200 запросов, по 100 на русском и английском, типы как в ADR-0021, для каждого — описание ожидаемой иконки словами. Сохрани в docs/eval/queries.csv, раздели на рабочую и контрольную части и покажи мне 20 случайных строк.
```

- [ ] Просмотрите 20 строк: похоже ли это на то, как ищут люди. Это около 15 минут. Точные имена иконок проставятся после фазы 1.

### Шаг 15. Лендинг со списком ожидания

- [ ] Выбрать сервис для сбора почты, например Buttondown или Loops, и завести аккаунт — это ваша часть.
- [ ] Claude Code соберёт одну страницу: название, одно предложение о продукте, поле для почты и ссылку на политику конфиденциальности. Разместит её на Cloudflare по вашему домену.
- [ ] Шаг можно отложить, но лучше успеть до беты: из списка ожидания придут первые участники фазы 5.
