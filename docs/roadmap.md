# Roadmap запуска платформы иконок

15 октября 2026 · @Konstantin Yan

## Вводные

Публичный запуск — 1 июня 2027, если начать 12 октября 2026 и работать одному на полный день. Смысловой поиск, MCP-сервер и отдельная фаза редизайна добавили объёма, поэтому запуск сдвинулся на семь недель по сравнению с первой версией плана. Вдвоём запуск реален примерно к началу апреля 2027.

План опирается на такие допущения:

- Команда — один разработчик на полный день. При работе по вечерам все сроки примерно удваиваются.
- Ко дню запуска готовы 15–25 наборов иконок, пакет для разработчиков (веб-компонент и React), сайт-каталог со смысловым многоязычным поиском и MCP-сервер для ИИ-ассистентов.
- Главные отличия — смысловой многоязычный поиск и MCP-сервер. Остальные фичи сайта определяете вы, время под них заложено в фазе 4.
- Название проекта и стек сайта пока открыты, их фиксирует фаза 0.
- Интерфейс сначала собирает нейросеть как рабочий прототип. Визуальный дизайн из ваших макетов накладывается в фазе 6, когда продукт технически готов и проверен в бете.

До запуска сознательно не делаются адаптеры Vue и Svelte, сборочный плагин и плагин для Figma.

## Фаза 2. Доставка: CDN, edge API и npm

7 декабря 2026 – 27 декабря 2026. Цель — иконки отдаются с двух хостов, edge API собирает пачки и SVG с параметрами, поиск работает как сервис, а пакеты данных опубликованы под тегом `next`.

- [x] Раскладка статики `/v/{версия}/{набор}/{иконка}.json` и манифест текущих версий — `pnpm cdn build`, принято 21 октября 2026 (ADR-0022).
- [x] Объектное хранилище и CDN: `immutable` для версионированных файлов, короткий кэш для манифеста — бакет R2 `iconavo-cdn` с доменом `cdn.iconavo.dev`, `pnpm cdn upload` и workflow «Выкладка», принято 22 октября 2026 (ADR-0022).
- [x] CORS, правильный `content-type`, сжатие Brotli — три правила Cloudflare и проверка `pnpm cdn check`, принято 22 октября 2026 (ADR-0023).
- [x] Второй хост у другого провайдера и проверка переключения — Bunny `cdn2.iconavo.dev`: выгрузка на два хоста, сверка контрольных сумм `pnpm cdn verify` и ежедневная «Сверка хостов»; само переключение делает ядро пакета в фазе 3; принято 23 октября 2026 (ADR-0025).
- [x] Публикация пакетов данных из CI с provenance — пять пакетов `@iconavo-ui/icons-{набор}` под тегом `next`: доверенная публикация из workflow «Публикация в npm», подготовка `pnpm packages prepare` и проверка `pnpm packages verify`; принято 23 октября 2026 (ADR-0026).
- Мониторинг доступности, аналитика CDN и оповещения о расходах перенесены в фазу 8, после запуска (решение владельца 23 октября 2026, ADR-0028). До запуска сбой видно по ежедневным проверкам CI с письмом GitHub, а от счёта страхует лимит трафика второго хоста (ADR-0025).
- [x] Edge API: пачки иконок, SVG с цветом, размером и поворотом, CSS; ответы кэшируются на CDN — функция `iconavo-api` на `api.iconavo.dev`: сборка `pnpm api build`, превью `pnpm api preview`, проверка `pnpm api check`, выкладка только из CI — workflow «Edge API»; принято 23 октября 2026 (ADR-0006, ADR-0024).
- [x] Поисковый сервис: развернуть выбранный движок, загрузить индекс из конвейера, кэшировать популярные запросы на edge. Принято 26 октября 2026 (ADR-0027, ADR-0040, ADR-0049):
  - Meilisearch Cloud во Франкфурте, индекс из конвейера — `pnpm search-index` и workflow «Поисковый индекс» после каждой «Выкладки»;
  - `/search` в edge API: кэш, лимит частоты, «сначала текст»;
  - качество не хуже прототипа, из Европы 95% ответов — за 0,29 с.

Критерий выхода: при выключенном основном хосте иконки грузятся со второго, заголовки кэша проверены, edge API и поиск отвечают с CDN.

## Фаза 3. Пакет для разработчиков

28 декабря 2026 – 7 февраля 2027, с запасом на новогодние праздники. Цель — ядро, веб-компонент и адаптер React выходят бетой 0.x.

- [x] Ядро: реестр в памяти, очередь по наборам, дедупликация запросов; пачки через edge API, а при его недоступности — поштучно со статики. Принято 27 октября 2026: пачки за тик и общее хранилище — шаг 2 (PR #58), запасные хосты и статика — шаг 3 (PR #62) (ADR-0030).
- [x] Обработка ошибок: «иконки нет» кэшируется, сетевые сбои повторяются с нарастающей задержкой, работают запасные хосты. Принято 27 октября 2026 (шаг 3, PR #62, ADR-0030): хост молчит 750 мс — тот же запрос уходит на следующий, повторы через 1, 2 и 4 с; проверено в песочнице.
- [ ] Публичное API: `configure`, `addIcons`, `setLoader`, `loadIcons`.
- [x] Рендер: viewBox с поворотами и отражениями, размеры, уникальные ID, доступность. Принято 27 октября 2026 (шаг 4, PR #65, ADR-0031): одна функция ядра `renderIcon` для тега и React; сетка вариантов — в песочнице `/render`, подписи проверены Экранным диктором.
- [x] Веб-компонент: защита от двойной регистрации, shadow DOM, ленивый рендер, резерв места. Принято 27 октября 2026 (шаг 5, PR #67, ADR-0032):
  - тег `<iconavo-icon>` грузит иконку за полэкрана до появления;
  - по умолчанию — скелетон;
  - проверен в Chrome, Firefox и WebKit вместо Safari (`pnpm sandbox --check`, ADR-0035).
- [x] Быстрые пачки без кэша: функция edge API собирает пачку из файлов иконок в кэше дата-центра, а у ядра свой порог перехода с API на статику. Это шаг 6 — находка шага 5, порядок — решение владельца 27 октября 2026 (ADR-0030). Принято 28 октября 2026 (PR #70, #71):
  - знакомые иконки в новой пачке — в 3–20 раз быстрее;
  - порог перехода на статику — 1,5 с;
  - страница 5000 иконок с живыми хостами — 202 пачки, к статике ни одного запроса.
- [x] Адаптер React и пример на Next.js с SSR. Принято 28 октября 2026 (шаг 7, PR #75, ADR-0033):
  - иконки из `IconavoProvider` — в серверном HTML без мигания, остальные догружаются в браузере;
  - без предупреждений о гидратации в Chrome, Firefox и WebKit — и в режиме разработки, и в продакшене;
  - бюджет React — 2,5 КБ (решение владельца).
- [x] Бюджет размера ядра в CI, например до 5 КБ в gzip. Принято 28 октября 2026 (шаг 8, PR #77, ADR-0034):
  - ядро — 4,50 КБ из 5, тег — 1,98 из 2, React — 2,19 из 2,5, скрипт без сборщика — 5,89 из 7;
  - таблица размеров — на странице каждого запуска CI, превышение роняет проверку (проверено черновым PR #78).
- [x] Тесты: модульные, браузерные на Playwright, сбои сети, SSR. Принято 29 октября 2026 (шаг 9, PR #84, ADR-0035):
  - покрытие ядра — 100% строк и 95% веток, порог — 90%;
  - Chrome, Firefox и WebKit на каждом PR, обязательны для слияния: сбои сети, SSR и гидратация в Next.js и React 18, доступность axe-core;
  - все иконки пяти наборов через тег и React выглядят так же, как SVG статики.
- [ ] Краткая документация и живые примеры.

Критерий выхода: все иконки пяти наборов через пакет выглядят так же, как исходные SVG, бета опубликована.

## Фаза 6. Редизайн

3 мая 2027 – 23 мая 2027. Цель — наложить визуальный дизайн из ваших макетов на готовый и проверенный в бете продукт, ничего не сломав.

Бета проверяет функции и удобство на прототипе, поэтому редизайн не смешивается с исправлением ошибок. Макеты вы рисуете параллельно с бетой, а в этой фазе Claude Code их применяет.

- [ ] Макеты в Figma: главная, поиск, набор, иконка, генератор кода, сумка, документация, сетка выбора в чате.
- [ ] Переменные Figma сопоставлены с дизайн-токенами в коде (ADR-0038).
- [ ] Claude Code через Figma MCP применяет дизайн по слоям: сначала токены, затем стили компонентов, затем страницы.
- [ ] Скриншотные тесты Playwright: каждая страница в светлой и тёмной теме, на телефоне и компьютере.
- [ ] Проверка доступности по WCAG 2.2 AA: контраст, фокус, управление с клавиатуры.
- [ ] Сетка выбора в чате в новом дизайне (ADR-0045).
- [ ] 5–10 участников беты смотрят новый дизайн до запуска.

Критерий выхода: все страницы соответствуют макетам, скриншотные тесты и проверка доступности проходят, функции работают так же, как в бете.

## Сквозные задачи

Эти треки идут через все фазы и не получают отдельного окна в плане.

- Лицензии. Для каждого набора хранить SPDX-идентификатор, текст лицензии, NOTICE, источник и коммит. Наборы под NC, GPL и с неясной лицензией добавлять только после отдельного решения. Условия распространения перед запуском проверить с юристом.
- Безопасность. Двухфакторная аутентификация и provenance в npm, минимум зависимостей, закреплённые версии. Санитайзер покрыт тестами на вредоносные SVG, на сайте настроен CSP.
- Инфраструктура и расходы. Оповещения о трафике CDN, лимиты на API поиска, контроль горячих ссылок с чужих продакшен-сайтов.
- Приватность. Постоянного кэша в браузере по умолчанию нет, политика конфиденциальности описывает запросы к CDN.
- Документация. Пишется вместе с кодом, у каждого публичного метода есть пример.
- Бюджет на ИИ. Обогащение — разовая плата за каждую новую иконку, к ней добавляются поисковый сервис и векторы запросов. В аккаунтах провайдеров ставятся лимиты расходов.

## Метрики

Главная метрика — успешность поиска: доля поисковых сессий, которые заканчиваются копированием кода или скачиванием.

| Метрика | Как считать | Ориентир |
| --- | --- | --- |
| Успешность поиска | Сессии с копированием или скачиванием / все сессии с поиском | От 50% к запуску |
| Скорость поиска | Время от паузы в наборе до выдачи | Не дольше 0,3 с для 95% поисков (ADR-0040) |
| Время до первой иконки | Медиана от входа на сайт до первого копирования | Меньше минуты |
| Установки пакета | Загрузки npm в неделю | Рост неделя к неделе |
| Запросы к CDN | Иконок в сутки, в разрезе наборов | Рост неделя к неделе |
| Ошибки CDN | Доля ответов 5xx и таймаутов по логам | Меньше 0,1% |
| Скорость сайта | LCP, 75-й перцентиль | Меньше 2,5 с |
| Возвраты | Доля посетителей, вернувшихся в течение 4 недель | Замерить в бете |
| Качество поиска | Доля эталонных запросов на русском и английском с нужной иконкой в первой пятёрке | Строгий Hit@5 к запуску — не ниже 90% отдельно для русских и английских запросов (первый замер — 86% и 90%), дальше рост от релиза к релизу (ADR-0021) |
| Использование MCP | Вызовы инструментов в сутки и число подключённых клиентов | Рост неделя к неделе |

Ориентиры условные: после беты замените их реальными базовыми значениями.

## Риски

Главный риск — расползание сроков, и лечится он сокращением объёма, а не переносом даты запуска.

| Риск | Признак | Мера |
| --- | --- | --- |
| Сроки расползаются | Фаза длиннее плана в полтора раза | Резать объём по списку «после запуска», дату не двигать |
| Претензия по лицензии | Жалоба правообладателя или неясная лицензия | Проверка до добавления, быстрый процесс удаления, запись источника |
| Отказ CDN | Иконки пропадают на сайтах пользователей | Второй хост, мониторинг, рекомендация собирать иконки в бандл |
| Источник меняет структуру | Конвейер падает или выдаёт пустые иконки | Закреплённые версии, визуальные тесты, ручное подтверждение крупных изменений |
| Слабый поиск | Низкая успешность поиска в бете | Эталонные запросы, синонимы, разбор неудачных запросов |
| Счета за трафик | Расходы растут быстрее аудитории | Хранилище без платы за исходящий трафик, лимиты, контроль горячих ссылок |
| Захват npm-аккаунта | Неожиданная публикация пакета | 2FA, публикация только из CI, provenance |
| Тихий запуск | Слабый отклик в первые дни | Список ожидания, отзывы участников беты, повторные анонсы новых фич |
| Расходы на ИИ | Счета за обогащение и векторы растут быстрее каталога | Кэш по отпечатку, пакетная обработка, лимиты расходов |
| Неверные описания от ИИ | Иконка находится по словам, которых нет на картинке | Выборочная проверка, фильтр слов, разбор жалоб на результаты |
| Конкуренты в MCP | Похожие серверы для иконок уже есть | Отличаться качеством поиска на русском, выбором в чате и согласованными наборами |
