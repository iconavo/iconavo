## Что строим

Аналог Iconify: каталог иконок из открытых наборов, который отличается смысловым многоязычным поиском и MCP-сервером для ИИ-ассистентов. Принцип: где Iconify нашёл проверенное решение, берём такое же устройство (формат имён, IconifyJSON, адреса API).

## Архитектура (по ADR)

Конвейер → статика и edge → пакет и сайт:

1. **Конвейер данных** (`packages/pipeline`, фаза 1, ADR-0012…0021): загрузка наборов только из npm и git → очистка SVG своим санитайзером по белому списку → нормализация (сетка 24 или 32, атрибуты корня во внешний `<g>`, цвета в `currentColor`, префиксы ID) → SVGO с закреплённой версией (вывод побайтно детерминирован) → контроль качества рендером через resvg → метаданные и лицензии → отпечатки SHA-256 и журнал изменений → обогащение ИИ (описания, синонимы) и эмбеддинги. Результат кладётся в `data/`, реестр источников — в `sources/`.
2. **Доставка** (фаза 2, ADR-0006, 0022…0025): неизменяемая статика на Cloudflare R2 (`cdn.домен/v/{версия}/{набор}/{иконка}.json|.svg`, манифест `manifest.json` с коротким кэшем) плюс edge API на Workers (`api.домен`: пачки, SVG с параметрами, CSS, поиск). Второй хост статики — Bunny CDN. Выкладка: сначала файлы, потом сверка, манифест последним.
3. **Пакеты** (фаза 3, ADR-0029…0036): общее ядро плюс тонкие адаптеры — веб-компонент `<iconavo-icon>` (Shadow DOM) и React 18/19. Только ESM, бюджеты размера 5, 2 и 2 КБ. Ядро берёт пачки через edge, а при его сбое — поштучно со статики.
4. **Поиск** (ADR-0009, 0021, 0027, 0048): гибридный (текст + векторы), Meilisearch Cloud, документ на базовую иконку. Метрика качества — Hit@5 на эталоне из 200 запросов. Прототип на данных конвейера — `packages/pipeline/src/search/`, замер — `src/eval/`.
5. **Сайт** (Next.js на Vercel) и **MCP-сервер** (Workers, `mcp.домен`, инструменты в т. ч. `pick_icon`).

Ключевые соглашения из ADR, которые легко нарушить:
- Имя иконки — `набор:иконка`, части по `^[a-z0-9]+(-[a-z0-9]+)*$`, префиксы как у Iconify (`lucide`, `tabler`, `material-symbols`, `ph`, `fluent-emoji-flat`). Имя без двоеточия не принимается.
- Иконки никогда не удаляются: пропавшие помечаются `hidden`, переименованные становятся алиасами.
- Файлы данных совместимы с IconifyJSON; данные поиска лежат отдельно в `search.json`.
- Пакеты — semver, до запуска 0.x, публикация в npm только из CI с provenance, тег `next` до запуска.
- Первые наборы: Lucide, Tabler, Material Symbols, Phosphor, Fluent Emoji Flat — только с разрешительными лицензиями.

## Формат набора (ADR-0003)

Схемы — в `packages/schema` (zod 4, сообщения об ошибках по-русски). Набор состоит из четырёх файлов: `icons.json` (формат IconifyJSON, **единственный файл, который идёт в рантайм**), `info.json` (название, автор, лицензия полностью, сетка, признак цветного набора), `metadata.json` (категории и карта суффиксов вариантов) и `search.json` (теги и отпечатки каждой иконки; описания и синонимы ru/en — только у базовых иконок, ADR-0046; поля сверх IconifyJSON живут только здесь). Рядом — журнал выпусков `changelog.json` и `CHANGELOG.md` (ADR-0018). В `icons.json` лишние поля допустимы (совместимость), в наших файлах запрещены. Правило имён одно на всё: `^[a-z0-9]+(-[a-z0-9]+)*$`. Ядро `packages/core` не должно зависеть от zod.

## Правила работы

- Если меняешь больше двух файлов — сначала план.
- После изменений запускай тесты и показывай результат.
- Всё, что нужно оценить глазами, показывай HTML-страницей.
- Новые зависимости — только после моего согласия.
- Никогда не коммить токены, пароли и файлы `.env`.
- Один шаг — один коммит с понятным описанием на русском.
- Репозиторий открытый с 20 октября 2026 (ADR-0036): код, история коммитов, PR и логи CI видны всем.

Источники наборов (ADR-0012): конфиг на набор — `sources/{id}.ts` (экспорт по умолчанию, `satisfies SourceConfigInput`, имя файла = префикс набора; папки с SVG и правила имён вариантов — список `svgFolders`; сетка набора `grid` и, если холст источника другой, `sourceGrid` — ADR-0014; автор `author`, лицензия `license`, формат метаданных автора `metadata`, карта вариантов `suffixes`, витрина `samples` — ADR-0017), версии закреплены в `sources.lock.json`, скачанное лежит в `.cache/sources/{id}/{версия}/` (не в git). `pnpm sources fetch [id…]` скачивает по lock (при первом запуске набора закрепляет последнюю версию) и проверяет имена: нарушение правила или конфликт имён — «СТОП» и код выхода 1 (ADR-0001); повторный запуск без изменений не использует сеть, а при смене правил скачивания (папки, файлы метаданных) набор скачивается заново; git-источники приходят без перевода строк под систему; `pnpm sources pin <id> [версия|коммит]` меняет версию — `sources.lock.json` правь только этой командой. Для git в lock нужен полный хэш коммита, не ветка. Без версии `pin` берёт последнюю: у npm — `latest`, у git — последний коммит основной ветки автора, а при `source.latest: "tag"` (Lucide) — свежий тег выпуска вида `1.60.0` (ADR-0012). Код — `packages/pipeline/src/sources/`.

Эталон поиска (`docs/eval/queries.csv`, описание в `docs/eval/README.md`) генерируется скриптом `node --env-file=.env tools/eval/generate-queries.mjs` через Polza AI; повторный запуск меняет запросы и разбиение work/holdout — не запускай без просьбы. Подходящие иконки размечает `pnpm judge` (ниже, ADR-0048).

Очистка SVG (ADR-0013): `pnpm sanitize [id…]` прогоняет скачанные наборы (из `.cache/sources`, сеть не использует) через санитайзер по белому списку, печатает сводку и пишет HTML-отчёт `.cache/reports/sanitize.html`. Код выхода 1 — набор остановлен: исключено больше 1% иконок, найдено опасное (признак подмены источника), потеряны фигуры или атрибуты рисунка. Код — `packages/pipeline/src/sanitize/` (разбор XML — `src/svg/xml.ts`, без зависимостей); «вредные» SVG для тестов — `packages/pipeline/fixtures/harmful-svg/` (исключены из Biome). Санитайзер должен идти раньше SVGO: парсер SVGO читает сущности из DOCTYPE.

Нормализация (ADR-0014): `pnpm normalize [id…]` очищает и нормализует скачанные наборы (сеть не использует, в `data/` ничего не пишет): холст переводится на сетку набора (масштаб — атрибут `transform` на внешнем `<g>`, в координаты его впечатывает SVGO при сборке, `pnpm data`), атрибуты корня уходят во внешний `<g>`, в монохромных наборах цвета → `currentColor` (маски и clipPath не трогаются, фигурам без заливки цвет задаётся явно), ID → `{набор}--{иконка}-{n}`. Печатает сводку и пишет галерею `.cache/reports/normalize/index.html`: «было/стало» на светлом и тёмном фоне и в красном, 48/24/16 px, по 500 иконок на странице, список «Сначала посмотрите»; папка пересоздаётся при каждом запуске. Код выхода 1 — набор остановлен: исключено больше 1%, найдено опасное, больше 1% иконок вне сетки источника, результат не прошёл независимую проверку. Код — `packages/pipeline/src/normalize/`; общие помощники HTML-отчётов — `src/report/html.ts`, ссылки между элементами — `src/svg/refs.ts`.

Сборка (ADR-0015): `pnpm data [id…]` собирает скачанные наборы (сеть не использует): очистка и нормализация как в шаге 4 → SVGO 4.1.0 со своим явным списком плагинов (`packages/pipeline/src/optimize/config.ts`: точность 3 знака, только для сеток 24 и 32; `cleanupIds` выключен; масштаб впечатывается в координаты) → алиасы одинаковых вариантов (поле `variantAliases` в конфиге набора, ADR-0002) → контроль качества (шаг 6, ниже) → журнал (шаг 8, ниже) → метаданные и лицензия (шаг 7, ниже) → `data/{id}/icons.json` (IconifyJSON; ключи по кодам символов, отступ 2 пробела, LF; `lastModified` — дата последнего выпуска) и остальные файлы набора. Печатает размеры до и после и пишет галерею `.cache/reports/data/index.html`: «было / до SVGO / SVGO», значки алиасов, «Сначала посмотрите». `data/` хранится в git и руками не правится: повторная сборка без изменений источников даёт побайтно те же файлы, это проверяет `.github/workflows/data.yml` (пересобирает на Linux и падает, если `git status` не пуст). Код выхода 1 — набор остановлен: всё из шага 4, плюс SVGO или проверка после него не прошли, одно имя у нескольких файлов, неподдерживаемая сетка, файл не прошёл схему, «СТОП» контроля качества; файл остановленного набора не перезаписывается. Код — `packages/pipeline/src/build/` и `src/optimize/`. Любое изменение версии SVGO или его конфига — полная пересборка `data/`; попиксельное сравнение с прошлой версией делает контроль качества.

Контроль качества (ADR-0016): идёт внутри `pnpm data`, отдельной команды нет. Каждая иконка рисуется через resvg (`@resvg/resvg-wasm`: сетка = 64 px, прозрачный фон, запас 16 px вокруг холста) и сравнивается через pixelmatch.
- «СТОП» (файл набора не записывается):
  - resvg не нарисовал иконку;
  - иконка пустая: закрашено меньше 0,05% холста;
  - источник тот же, а изменилось или пропало больше 2% имён по сравнению с прошлой версией. Пропавшими считаются только видимые иконки, которых нет в источнике: скрытые и алиасы журнал переносит сам. Прошлая версия — версия набора в main: последний коммит, где менялись `data/{набор}/icons.json` или `changelog.json`, не новее общего предка HEAD и `origin/main` (без `origin/main` — от HEAD), вместе с `sources.lock.json` того же коммита. Читается через `git show`, git нужен; не читается — «СТОП».
- Только отчёт:
  - почти пустые — меньше 0,5% холста;
  - обрезанные — вылет за холст больше 2%;
  - отличия от исходника автора больше 1% пикселей. В монохромных наборах сравнивается только тёмная краска.
- `pnpm data --accept-changes` снимает только правило 2% — для задуманных изменений, проверенных в отчёте. Сравнение идёт с версией в main, поэтому на ветке флаг нужен при каждой сборке, пока изменения не попадут в main.
- Отчёт — `.cache/reports/data/qc.html` и раздел в `index.html`. Пороги — `packages/pipeline/src/qc/config.ts`, код — `src/qc/`.

Метаданные и лицензии (ADR-0017): тоже внутри `pnpm data`. Рядом с `icons.json` пишутся:
- `info.json` — автор, лицензия с полным текстом, витрина из шести иконок;
- `metadata.json` — категории автора и карта вариантов `suffixes`;
- `search.json` — отпечаток (ADR-0018) и теги каждой иконки, без алиасов;
- `LICENSE`, а `NOTICE` — только если он есть у автора.

Теги и категории берутся из файлов автора по формату `metadata` в конфиге: `lucide`, `tabler`, `phosphor` (модуль `dist/index.mjs` читается как текст, без запуска), `fluent-emoji`. Где их нет (Material Symbols) — теги из частей имени. Категории — как у автора, строчными только теги. Отчёт — `.cache/reports/data/metadata.html`, таблица — в конце вывода `pnpm data`.
- Лицензию подтверждает только владелец, прочитав текст в `metadata.html`. После его явного «подтверждаю» отпечаток из сообщения «СТОП» вписывается в `license.confirmed` конфига набора. Сам не вписывай.
- «СТОП» (файлы набора не записываются):
  - лицензия не подтверждена или изменилась у автора;
  - лицензия в `package.json` пакета npm не совпадает с конфигом;
  - метаданные автора не читаются;
  - больше 1% иконок без тегов автора;
  - в `samples` неизвестное имя.
- Разрешены только лицензии MIT, ISC и Apache-2.0: другая — ошибка конфига.
- Код — `packages/pipeline/src/metadata/`.

Журнал изменений (ADR-0018): тоже внутри `pnpm data`. Имена никогда не пропадают.
- Иконка, которой больше нет у автора, остаётся в `icons.json` со старым рисунком и `hidden: true`. Если тот же рисунок (отпечаток) появился под другим именем, старое имя становится его алиасом.
- Алиасы прошлой версии переносятся. Прежние имена от автора (Lucide — `aliases`, Phosphor — `alias`) становятся алиасами, если имя свободно. Старшинство: источник → прошлая версия → автор.
- Версия набора — 8 символов SHA-256 от `icons.json` без `lastModified`, лежит в `info.json`. Выпуск — версия, отличная от версии в main. Повторная сборка без изменений журнал не трогает, а ожидающий слияния выпуск сохраняет дату из `changelog.json` на диске.
- Рядом с `icons.json` пишутся:
  - `changelog.json` — для сайта и CI;
  - `CHANGELOG.md` — для людей, с блоком «Требуют вашего одобрения»: скрытия и переименования (ADR-0019).
- Отчёт — `.cache/reports/data/changelog.html`.
- «СТОП»:
  - прошлая версия не читается;
  - нарушена проверка слияния: пропало имя прошлой версии, родитель алиаса — не иконка, повторное слияние дало другой итог.
- Исправление имени после шага 8 становится переименованием: старое имя остаётся алиасом.
- Код — `packages/pipeline/src/changelog/`.

Автообновление (ADR-0019): робот `.github/workflows/update.yml` запускается раз в сутки в 03:17 UTC и вручную (Actions → «Обновление наборов» → Run workflow, поля: наборы, версия, только показ, без автослияния, переписать описание PR).
- Для каждого набора: `pnpm sources pin` → если версия не та, что в main, `pnpm sources fetch` и `pnpm data` → `pnpm pr <набор>` → PR из ветки `auto/{набор}`.
- PR открывает приложение GitHub организации: секреты `UPDATE_APP_CLIENT_ID` и `UPDATE_APP_PRIVATE_KEY`. Без приложения, вне main и на PR, которые меняют робота, — только показ.
- `pnpm data` пишет сводку для машины — `.cache/reports/data/summary.json`. `pnpm pr <набор>` читает её и пишет `.cache/update/{набор}/pr.json` (решение, заголовок, метки) и `body.md` (описание PR).
  - Флаги со ссылками, только https: `--run-url=`, `--changelog-url=`, `--qc-url=`, `--metadata-url=`, `--reports-url=`.
  - `--no-auto-merge` — не включать автослияние.
  - Код — `packages/pipeline/src/update/`.
- Решение и метки:
  - «сольётся сам» — иконки только добавлены или изменены;
  - «нужно одобрение»: скрытия, переименования, новые находки контроля у добавленных и изменённых иконок, исключённые при очистке, откат версии npm, новая лицензия (если это единственная причина «СТОП»);
  - «проблема» — другое «СТОП», в PR только `sources.lock.json`.
  - PR, которые ждут человека, приходят владельцу запросом на ревью.
- Новая лицензия в PR робота:
  - Владелец читает текст в отчёте и явно подтверждает.
  - Только после этого отпечаток вписывается в `sources/{набор}.ts` прямо в ветке `auto/{набор}`, затем `pnpm data {набор}` и коммит в ту же ветку.
  - Ветку с коммитом человека робот больше не трогает; сливает владелец.
- Закрытый без слияния PR — отклонённая версия, робот её больше не предлагает (Reopen — передумать). Открытый PR робот раз в сутки пересобирает от свежего main. Если версия уже в main, закрывает его; при красных проверках ставит «проблема».
- Где смотреть:
  - Actions → «Обновление наборов» → запуск, по строке на набор;
  - PR с меткой «автообновление»;
  - отчёты — ссылки в описании PR: артефакты запуска, хранятся 90 дней. Показать их локально: `gh run download <запуск>`, затем раздать папку через 127.0.0.1.

Обогащение (ADR-0046): `pnpm enrich [id…]` — описания и синонимы ru/en от Claude Haiku 5.5 для базовых иконок без описаний (у вариантов описаний нет: они берут их у базовой, ADR-0002). Команда читает `data/{набор}/`, рисует PNG 256×256 на белом фоне, отправляет пакет через Message Batches API (вдвое дешевле обычных запросов), ждёт результаты и дописывает `ru`, `en`, `promptVersion` в `search.json`. Ключ `ANTHROPIC_API_KEY` — из `.env` (команда его подхватывает) или переменной окружения; без ключа работает только `--dry-run`.
- Флаги: `--limit=N` — постоянная случайная выборка из N базовых иконок, повторный запуск с тем же N ничего не отправляет; `--max-cost=USD` — лимит стоимости прогона, проверяется по оценке до отправки, по умолчанию $5 (весь каталог по оценке ≈ $3, по факту первого прогона ≈ $1,75); `--dry-run` — только посчитать и оценить; `--no-wait` — отправить пакет и выйти, результаты заберёт следующий запуск.
- Состояние пакета — `.cache/enrich/{набор}/batch.json`: прерванный запуск продолжает опрос и ничего не отправляет повторно; файл удаляется после записи `search.json`. Отказы (отказ модели, обрезанный ответ, ошибка пакета, меньше 5 синонимов) в файл не пишутся и отправляются в следующий раз.
- `pnpm data` сеть не использует: описания переходят из `search.json` на диске к базовым иконкам с тем же отпечатком (переименования — по журналу); рисунок изменился — описание пропадает до следующего `pnpm enrich`; файл на диске не по схеме — «СТОП». После `pnpm enrich` повторная сборка даёт те же байты.
- Отчёт — `.cache/reports/enrich/index.html` (иконка, PNG для модели, описания и синонимы, отказы, стоимость и прогноз на каталог) и таблица в терминале. Код выхода 1 — «СТОП»: файлы набора не от этой сборки или оценка выше лимита.
- Промпт, модель, усилие, цены и константы оценки — `packages/pipeline/src/enrich/config.ts` и `prompt.ts`; смена промпта — новая `PROMPT_VERSION`, старые записи остаются (ADR-0020). Код — `packages/pipeline/src/enrich/`.
- Робот обновления описаний не делает: после слияния его PR запускайте `pnpm enrich {набор}` от `main`.

Эмбеддинги (ADR-0047): `pnpm embed [id…]` — векторы смысла для базовых иконок с описаниями (варианты берут вектор базовой) тремя моделями через Polza AI: `openai` (text-embedding-3-large, длина 3072), `gemini` (gemini-embedding-001, 3072) и `qwen` (qwen3-embedding-8b, 4096). Текст иконки один на оба языка: имя, теги, описание и синонимы en, затем ru (`TEXT_VERSION`). Ключ `POLZA_API_KEY` — из `.env` (команда его подхватывает) или переменной окружения; без ключа работает только `--dry-run`.
- Флаги: `--model=openai|gemini|qwen` (можно повторить) — только эти модели; `--max-rub=N` — лимит стоимости прогона в рублях: по оценке до отправки и по факту во время прогона, по умолчанию 200 ₽ (весь каталог тремя моделями по оценке ≈ 102 ₽, по факту первого прогона 75,86 ₽ и около часа); `--dry-run` — только посчитать и оценить.
- Векторы — только локально, в git их нет (решение владельца): `.cache/embeddings/{модель}/{набор}.f32` (float32 little-endian, каждый вектор длины 1) и `{набор}.json` — оглавление: строки «имя + хэш текста», размер и SHA-256 файла `.f32`, накопленный расход. Всего ≈ 640 МБ; на новой машине векторы считаются заново.
- Кэш — по хэшу текста (16 символов SHA-256): повторный запуск без изменений ничего не отправляет, поменялось описание — пересчитывается одна иконка, оглавление не сходится с `.f32` — векторы набора считаются заново.
- Запросы — пачки по 100 текстов, до 4 одновременно; векторы пишутся и по ходу, каждые 10 пачек, так что обрыв теряет только последние пачки. Сбой сети, таймаут 60 с, ответы 408, 425, 429 и 5xx — до 5 попыток (пауза по `Retry-After` или 1, 2, 4, 8 с). 401, 402, 403 — «СТОП» всего прогона (ключ, баланс); другой 4xx и вектор не той длины — «СТОП» модели, остальные модели идут. Посчитанное сохраняется и при остановке.
- Отчёт — `.cache/reports/embed/index.html` (готовность «модель × набор», чем отличаются модели: цена, символов на токен, время, место на диске; этот прогон) и таблица готовности в терминале. Код выхода 1 — «СТОП».
- `pnpm nearest [запрос…] [--model=…]` — ближайшие по смыслу иконки к запросам по каждой модели (косинус векторов), ключ нужен. Без запросов — пары ru/en из `NEAREST_PAIRS` (ни одной из контрольной части эталона, ADR-0021); запросы сравниваются парами — совпадение пятёрок. Время ответа на запрос — медиана без первого запроса, с этого компьютера через Polza. Страница — `.cache/reports/embed/nearest.html`.
- Модели, цены, размер пачки, инструкция запроса для Qwen, пары — `packages/pipeline/src/embed/config.ts`. Код — `packages/pipeline/src/embed/`.
- `pnpm data` векторы не трогает, робот обновления их не считает: после слияния его PR и после `pnpm enrich` запускайте `pnpm embed {набор}`.

Прототип поиска (ADR-0048): документ — базовая иконка, оттенки кожи Fluent — одна карточка (если есть основа и все пять оттенков). Текстовая часть — по именам, тегам и синонимам ru/en (без описаний), совпадения как в Meilisearch: точное слово, 1 опечатка от 5 букв и 2 от 9 (в первой букве — за две), последнее слово — ещё и как начало слова; служебные слова не ищутся; лучшее поле, а не сумма. Смысловая часть — косинус с векторами `.cache/embeddings`, укороченный вектор — первые L чисел, снова длины 1. Слияние — α·смысл + (1−α)·текст: текст — доля от лучшей возможной оценки запроса, смысл — место косинуса между 1-м и 100-м результатом. Точное имя (имя, вариант, оттенок, алиас, `набор:имя`) — всегда первым. Без векторов — только текст. Векторы запросов — кэш `.cache/search/queries/{модель}/{хэш}.f32`, промахи — пачками. Веса, служебные слова, α и длина каждой модели — `packages/pipeline/src/search/config.ts`. Код — `packages/pipeline/src/search/`.
- `pnpm search-page [--port=N] [--model=…]` — страница поиска на `http://127.0.0.1:4280` для ручной проверки: колонки «Текст» и гибрид каждой модели, у карточки — почему нашлась. Сервер слушает только 127.0.0.1 и сверяет заголовок Host; отчёты `.cache/reports/…` открываются по `/reports/…`. Три модели — около 1 ГБ памяти, `--model=` грузит только нужные. Первый запрос после запуска — до 16 с (соединение с Polza), дальше — около 2 с, повтор — из кэша. Свою копию после проверки останавливай.

Разметка эталона и замер (ADR-0048, ADR-0021): `pnpm judge [--limit=N] [--max-rub=N] [--dry-run]` — судья `google/gemini-3.8-flash` через Polza (не Claude, который писал описания) размечает всё неразмеченное в первых десятках вариантов замера: текст, смысл и гибрид каждой модели, сетка α, длины вектора, фильтр по набору — для модели из `PER_SET_MODEL` (пока не задана: замер по наборам — вместе с фильтром на сайте, фаза 4).
- Судья видит запрос, описание ожидаемой иконки и до 12 кандидатов: PNG 128×128 и имя без набора, перемешанные постоянным случаем; наших описаний не видит. Вердикт — «подходит» / «частично» / «нет»; 5% пар — повторно, для согласия судьи с собой. Круги повторяются, пока новых пар нет (подбор α меняет списки); круг без единого вердикта — остановка.
- `docs/eval/judgments.json` — вердикты, отпечатки иконок, текст запроса и описание (поменялось — пара размечается заново), расход; руками не правится. `docs/eval/overrides.json` — правки владельца: впиши после его явного указания, судья их не трогает. Колонки `expected_icons` в `queries.csv` больше нет.
- Стоимость: оценка до отправки (по константам, после первого прогона — по факту рублей на картинку), лимит `--max-rub` (по умолчанию 300 ₽); факт — `usage.cost_rub`. `--limit=N` — пилот: по запросу на ячейку «язык × тип». Весь эталон — только после согласия владельца на сумму. Страница — `.cache/reports/eval/judge.html` (20 случайных запросов для проверки).
- `pnpm eval [--model=…] [--baseline]` — Hit@5, MRR@10, P@5 для «Текст», «Смысл» и «Гибрид» каждой модели: ru и en, контрольная, рабочая и все 200, с интервалом Уилсона; α подбирается на рабочей части (середина лучшего плато), длины вектора, модели попарно (тест Мак-Немара), промахи — только рабочей части, «потолок» — запросы без подходящей иконки (в доли не входят). Неразмеченное в первых десятках или нет векторов запросов — «СТОП», код выхода 1. Правила выбора модели и длины — в ADR-0048. Отчёт — `.cache/reports/eval/index.html` и `eval.json`; `--baseline` пишет `docs/eval/baseline.json` — итог для фазы 2.
- Модель судьи, цены, пачки, сетка α, длины, допуски — `packages/pipeline/src/eval/config.ts`, промпт — `prompt.ts`. Код — `packages/pipeline/src/eval/`.
- Замер в CI пока не идёт: векторы иконок локальные (ADR-0047).

Проверка файла набора по схеме: `pnpm validate <файл>` (вид по имени `icons|info|metadata|search|changelog.json` или `--kind`). Код выхода 0 — ошибок нет, 1 — есть ошибки, 2 — неверный вызов. Примеры: `packages/schema/examples/{valid,broken}/`.

`size-limit` читает собранные файлы из `dist/`, поэтому перед `pnpm size` запускай `pnpm typecheck`.

## Ветка main

Защита `main` включена 20 октября 2026, когда репозиторий стал открытым:
- в `main` — только через pull request; одобрение другим человеком не требуется;
- слить можно только при зелёных проверках «CI» (задача `check`) и «Данные» (задача `data`); «Данные» на PR запускается всегда — обязательная проверка, которая не запустилась, заблокировала бы PR;
- прямые коммиты, перезапись (force push) и удаление `main` запрещены, в том числе администратору;
- ветку перед слиянием догонять до свежего `main` не обязательно;
- безопасные PR робота обновления сливаются сами (автослияние, ADR-0019), ветки после слияния удаляются автоматически.

## Ключи

Имена ключей — в `.env.example`, значения — в локальном `.env` (в git не попадает) и в секретах GitHub Actions. `ANTHROPIC_API_KEY` — обогащение иконок (`pnpm enrich` читает `.env` сам через `--env-file-if-exists`). Вместо ключей OpenAI и Google для эмбеддингов (шаг 12 фазы 0, ADR-0007) временно используется агрегатор Polza AI: `POLZA_API_KEY` (`pnpm embed` и `pnpm nearest` читают `.env` сами). `UPDATE_APP_CLIENT_ID` и `UPDATE_APP_PRIVATE_KEY` — приложение GitHub робота обновления (ADR-0019), только в секретах GitHub Actions. Значения ключей читай только из переменных окружения; не открывай `.env` и не выводи его содержимое.
