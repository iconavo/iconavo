## Что строим

Аналог Iconify: каталог иконок из открытых наборов, который отличается смысловым многоязычным поиском и MCP-сервером для ИИ-ассистентов. Принцип: где Iconify нашёл проверенное решение, берём такое же устройство (формат имён, IconifyJSON, адреса API).

## Архитектура (по ADR)

Конвейер → статика и edge → пакет и сайт:

1. **Конвейер данных** (`packages/pipeline`, фаза 1, ADR-0012…0021): загрузка наборов только из npm и git → очистка SVG своим санитайзером по белому списку → нормализация (сетка 24 или 32, атрибуты корня во внешний `<g>`, цвета в `currentColor`, префиксы ID) → SVGO с закреплённой версией (вывод побайтно детерминирован) → контроль качества рендером через resvg → метаданные и лицензии → отпечатки SHA-256 и журнал изменений → обогащение ИИ (описания, синонимы) и эмбеддинги. Результат кладётся в `data/`, реестр источников — в `sources/`.
2. **Доставка** (фаза 2, ADR-0006, 0022…0025): неизменяемая статика на Cloudflare R2 (`cdn.домен/v/{версия}/{набор}/{иконка}.json|.svg`, манифест `manifest.json` с коротким кэшем) плюс edge API на Workers (`api.домен`: пачки, SVG с параметрами, CSS, поиск). Второй хост статики — Bunny CDN. Выкладка: сначала файлы, потом сверка, манифест последним.
3. **Пакеты** (фаза 3, ADR-0029…0036): общее ядро плюс тонкие адаптеры — веб-компонент `<iconavo-icon>` (Shadow DOM) и React 18/19. Только ESM, бюджеты размера: ядро 5 КБ, тег 2 КБ, React 2,5 КБ (ADR-0034). Ядро берёт пачки через edge, а при его сбое — поштучно со статики: `cdn`, `cdn2`, затем `iconavo.b-cdn.net` (ADR-0030).
4. **Поиск** (ADR-0009, 0021, 0027, 0048, 0049): гибридный (текст + векторы), Meilisearch Cloud во Франкфурте, документ на карточку (базовая иконка с вариантами). Метрика качества — Hit@5 на эталоне из 200 запросов. Прототип на данных конвейера — `packages/pipeline/src/search/`, замер — `src/eval/`, робот индекса — `src/meili/`, общий модуль — `packages/search`.
5. **Сайт** (Next.js на Vercel) и **MCP-сервер** (Workers, `mcp.домен`, инструменты в т. ч. `pick_icon`).

Ключевые соглашения из ADR, которые легко нарушить:
- Имя иконки — `набор:иконка`, части по `^[a-z0-9]+(-[a-z0-9]+)*$`, префиксы как у Iconify (`lucide`, `tabler`, `material-symbols`, `ph`, `fluent-emoji-flat`). Имя без двоеточия не принимается. В пакете иконку задаёт атрибут и проп `icon`, как у Iconify (`<iconavo-icon icon="lucide:house">`), не `name` (ADR-0031).
- Иконки никогда не удаляются: пропавшие помечаются `hidden`, переименованные становятся алиасами.
- Файлы данных совместимы с IconifyJSON; данные поиска лежат отдельно в `search.json`.
- Пакеты — semver: для разработчиков до запуска 0.x, пакеты данных — с 1.0.0 (ADR-0005, ADR-0026); публикация в npm только из CI с provenance, тег `next` до запуска.
- Первые наборы: Lucide, Tabler, Material Symbols, Phosphor, Fluent Emoji Flat — только с разрешительными лицензиями.

## Формат набора (ADR-0003)

Схемы — в `packages/schema` (zod 4, сообщения об ошибках по-русски). Набор состоит из четырёх файлов: `icons.json` (формат IconifyJSON, **единственный файл, который идёт в рантайм**), `info.json` (название, автор, лицензия полностью, сетка, признак цветного набора), `metadata.json` (категории и карта суффиксов вариантов) и `search.json` (теги и отпечатки каждой иконки; описания и синонимы ru/en — только у базовых иконок, ADR-0046; поля сверх IconifyJSON живут только здесь). Рядом — журнал выпусков `changelog.json` и `CHANGELOG.md` (ADR-0018). В `icons.json` лишние поля допустимы (совместимость), в наших файлах запрещены. Правило имён одно на всё: `^[a-z0-9]+(-[a-z0-9]+)*$`. Ядро `packages/core` не должно зависеть от zod.

## Стек (ADR-0007)

Монорепозиторий на TypeScript с pnpm workspaces; Biome (линтер и форматирование), Vitest, Playwright, size-limit; Next.js; Cloudflare R2/Workers; Meilisearch; эмбеддинги через Polza AI — `google/gemini-embedding-001`, длина вектора 1024 (выбрана по замеру шага 12, ADR-0010); `openai/text-embedding-3-large` и `qwen/qwen3-embedding-8b` остаются в замере для сравнения. Перед выбором моделей и цен перепроверяй актуальные версии.

## Имена и ресурсы

Бренд Iconavo, организация GitHub `iconavo`, веб-компонент `<iconavo-icon>`. В документации scope npm — `@iconavo-ui`; на npm существует и название `iconavo` (организация/пользователь без публичных пакетов). ## Правила работы

- Если меняешь больше двух файлов — сначала план.
- После изменений запускай тесты и показывай результат.
- Всё, что нужно оценить глазами, показывай HTML-страницей.
- Новые зависимости — только после моего согласия.
- Никогда не коммить токены, пароли и файлы `.env`.
- Один шаг — один коммит с понятным описанием на русском.
- Репозиторий открытый с 20 октября 2026 (ADR-0036): код, история коммитов, PR и логи CI видны всем.

Источники наборов (ADR-0012): конфиг на набор — `sources/{id}.ts` (экспорт по умолчанию, `satisfies SourceConfigInput`, имя файла = префикс набора; папки с SVG и правила имён вариантов — список `svgFolders`; сетка набора `grid` и, если холст источника другой, `sourceGrid` — ADR-0014; автор `author`, лицензия `license`, формат метаданных автора `metadata`, карта вариантов `suffixes`, витрина `samples` — ADR-0017), версии закреплены в `sources.lock.json`, скачанное лежит в `.cache/sources/{id}/{версия}/` (не в git). `pnpm sources fetch [id…]` скачивает по lock (при первом запуске набора закрепляет последнюю версию) и проверяет имена: нарушение правила или конфликт имён — «СТОП» и код выхода 1 (ADR-0001); повторный запуск без изменений не использует сеть, а при смене правил скачивания (папки, файлы метаданных) набор скачивается заново; git-источники приходят без перевода строк под систему; `pnpm sources pin <id> [версия|коммит]` меняет версию — `sources.lock.json` правь только этой командой. Для git в lock нужен полный хэш коммита, не ветка. Без версии `pin` берёт последнюю: у npm — `latest`, у git — последний коммит основной ветки автора, а при `source.latest: "tag"` (Lucide) — свежий тег выпуска вида `1.60.0` (ADR-0012). Код — `packages/pipeline/src/sources/`.

Эталон поиска (`docs/eval/queries.csv`, описание в `docs/eval/README.md`) генерируется скриптом `node --env-file=.env tools/eval/generate-queries.mjs` через Polza AI; повторный запуск меняет запросы и разбиение work/holdout — не запускай без просьбы. Подходящие иконки размечает `pnpm judge` (ниже, ADR-0048).

Очистка SVG (ADR-0013): `pnpm sanitize [id…]` прогоняет скачанные наборы (из `.cache/sources`, сеть не использует) через санитайзер по белому списку, печатает сводку и пишет HTML-отчёт `.cache/reports/sanitize.html`. Код выхода 1 — набор остановлен: исключено больше 1% иконок, найдено опасное (признак подмены источника), потеряны фигуры или атрибуты рисунка. Код — `packages/pipeline/src/sanitize/` (разбор XML — `src/svg/xml.ts`, без зависимостей); «вредные» SVG для тестов — `packages/pipeline/fixtures/harmful-svg/` (исключены из Biome). Санитайзер должен идти раньше SVGO: парсер SVGO читает сущности из DOCTYPE.

Нормализация (ADR-0014): `pnpm normalize [id…]` очищает и нормализует скачанные наборы (сеть не использует, в `data/` ничего не пишет): холст переводится на сетку набора (масштаб — атрибут `transform` на внешнем `<g>`, в координаты его впечатывает SVGO при сборке, `pnpm data`), атрибуты корня уходят во внешний `<g>`, в монохромных наборах цвета → `currentColor` (маски и clipPath не трогаются, фигурам без заливки цвет задаётся явно), ID → `{набор}--{иконка}-{n}`. Печатает сводку и пишет галерею `.cache/reports/normalize/index.html`: «было/стало» на светлом и тёмном фоне и в красном, 48/24/16 px, по 500 иконок на странице, список «Сначала посмотрите»; папка пересоздаётся при каждом запуске. Код выхода 1 — набор остановлен: исключено больше 1%, найдено опасное, больше 1% иконок вне сетки источника, результат не прошёл независимую проверку. Код — `packages/pipeline/src/normalize/`; общие помощники HTML-отчётов — `src/report/html.ts`, ссылки между элементами — `src/svg/refs.ts`.

Сборка (ADR-0015): `pnpm data [id…]` собирает скачанные наборы (сеть не использует): очистка и нормализация как в шаге 4 → SVGO 4.1.0 со своим явным списком плагинов (`packages/pipeline/src/optimize/config.ts`: точность 3 знака, только для сеток 24 и 32; `cleanupIds` выключен; масштаб впечатывается в координаты) → алиасы одинаковых вариантов (поле `variantAliases` в конфиге набора, ADR-0002) → контроль качества (шаг 6, ниже) → журнал (шаг 8, ниже) → метаданные и лицензия (шаг 7, ниже) → `data/{id}/icons.json` (IconifyJSON; ключи по кодам символов, отступ 2 пробела, LF; `lastModified` — дата последнего выпуска) и остальные файлы набора. Печатает размеры до и после и пишет галерею `.cache/reports/data/index.html`: «было / до SVGO / SVGO», значки алиасов, «Сначала посмотрите». `data/` хранится в git и руками не правится: повторная сборка без изменений источников даёт побайтно те же файлы, это проверяет `.github/workflows/data.yml` (пересобирает на Linux и падает, если `git status` не пуст). Код выхода 1 — набор остановлен: всё из шага 4, плюс SVGO или проверка после него не прошли, одно имя у нескольких файлов, неподдерживаемая сетка, файл не прошёл схему, «СТОП» контроля качества; файл остановленного набора не перезаписывается. Код — `packages/pipeline/src/build/` и `src/optimize/`. Любое изменение версии SVGO или его конфига — полная пересборка `data/`; попиксельное сравнение с прошлой версией делает контроль качества.

Контроль качества (ADR-0016): идёт внутри `pnpm data`, отдельной команды нет. Каждая иконка рисуется через resvg (`@resvg/resvg-wasm`: сетка = 64 px, прозрачный фон, запас 16 px вокруг холста) и сравнивается через pixelmatch.
- «СТОП» (файл набора не записывается):
  - resvg не нарисовал иконку;
  - иконка пустая: закрашено меньше 0,05% холста;
  - источник тот же, а изменилось или пропало больше 2% имён по сравнению с прошлой версией. Пропавшими считаются только видимые иконки, которых нет в источнике: скрытые и алиасы журнал переносит сам. Прошлая версия — версия набора в main: последний коммит, где менялись `data/{набор}/icons.json` или `changelog.json`, не новее общего предка HEAD и `origin/main` (без `origin/main` — от HEAD), вместе с `sources.lock.json` того же коммита. Читается через `git show`, git нужен; не читается — «СТОП».
- Только отчёт:
  - почти пустые — меньше 0,5% холста;
  - обрезанные — вылет за холст больше 2%;
  - отличия от исходника автора больше 1% пикселей. В монохромных наборах сравнивается только тёмная краска.
- `pnpm data --accept-changes` снимает только правило 2% — для задуманных изменений, проверенных в отчёте. Сравнение идёт с версией в main, поэтому на ветке флаг нужен при каждой сборке, пока изменения не попадут в main.
- Отчёт — `.cache/reports/data/qc.html` и раздел в `index.html`. Пороги — `packages/pipeline/src/qc/config.ts`, код — `src/qc/`.

Метаданные и лицензии (ADR-0017): тоже внутри `pnpm data`. Рядом с `icons.json` пишутся:
- `info.json` — автор, лицензия с полным текстом, витрина из шести иконок;
- `metadata.json` — категории автора и карта вариантов `suffixes`;
- `search.json` — отпечаток (ADR-0018) и теги каждой иконки, без алиасов;
- `LICENSE`, а `NOTICE` — только если он есть у автора.

Теги и категории берутся из файлов автора по формату `metadata` в конфиге: `lucide`, `tabler`, `phosphor` (модуль `dist/index.mjs` читается как текст, без запуска), `fluent-emoji`. Где их нет (Material Symbols) — теги из частей имени. Категории — как у автора, строчными только теги. Отчёт — `.cache/reports/data/metadata.html`, таблица — в конце вывода `pnpm data`.
- Лицензию подтверждает только владелец, прочитав текст в `metadata.html`. После его явного «подтверждаю» отпечаток из сообщения «СТОП» вписывается в `license.confirmed` конфига набора. Сам не вписывай.
- «СТОП» (файлы набора не записываются):
  - лицензия не подтверждена или изменилась у автора;
  - лицензия в `package.json` пакета npm не совпадает с конфигом;
  - метаданные автора не читаются;
  - больше 1% иконок без тегов автора;
  - в `samples` неизвестное имя.
- Разрешены только лицензии MIT, ISC и Apache-2.0: другая — ошибка конфига.
- Код — `packages/pipeline/src/metadata/`.

Журнал изменений (ADR-0018): тоже внутри `pnpm data`. Имена никогда не пропадают.
- Иконка, которой больше нет у автора, остаётся в `icons.json` со старым рисунком и `hidden: true`. Если тот же рисунок (отпечаток) появился под другим именем, старое имя становится его алиасом.
- Алиасы прошлой версии переносятся. Прежние имена от автора (Lucide — `aliases`, Phosphor — `alias`) становятся алиасами, если имя свободно. Старшинство: источник → прошлая версия → автор.
- Версия набора — 8 символов SHA-256 от `icons.json` без `lastModified`, лежит в `info.json`. Выпуск — версия, отличная от версии в main. Повторная сборка без изменений журнал не трогает, а ожидающий слияния выпуск сохраняет дату из `changelog.json` на диске.
- Рядом с `icons.json` пишутся:
  - `changelog.json` — для сайта и CI;
  - `CHANGELOG.md` — для людей, с блоком «Требуют вашего одобрения»: скрытия и переименования (ADR-0019).
- Отчёт — `.cache/reports/data/changelog.html`.
- «СТОП»:
  - прошлая версия не читается;
  - нарушена проверка слияния: пропало имя прошлой версии, родитель алиаса — не иконка, повторное слияние дало другой итог.
- Исправление имени после шага 8 становится переименованием: старое имя остаётся алиасом.
- Код — `packages/pipeline/src/changelog/`.

Автообновление (ADR-0019): робот `.github/workflows/update.yml` запускается раз в сутки в 03:17 UTC и вручную (Actions → «Обновление наборов» → Run workflow, поля: наборы, версия, только показ, без автослияния, переписать описание PR).
- Для каждого набора: `pnpm sources pin` → если версия не та, что в main, `pnpm sources fetch` и `pnpm data` → `pnpm pr <набор>` → PR из ветки `auto/{набор}`.
- PR открывает приложение GitHub организации: секреты `UPDATE_APP_CLIENT_ID` и `UPDATE_APP_PRIVATE_KEY`. Без приложения, вне main и на PR, которые меняют робота, — только показ.
- `pnpm data` пишет сводку для машины — `.cache/reports/data/summary.json`. `pnpm pr <набор>` читает её и пишет `.cache/update/{набор}/pr.json` (решение, заголовок, метки) и `body.md` (описание PR).
  - Флаги со ссылками, только https: `--run-url=`, `--changelog-url=`, `--qc-url=`, `--metadata-url=`, `--reports-url=`.
  - `--no-auto-merge` — не включать автослияние.
  - Код — `packages/pipeline/src/update/`.
- Решение и метки:
  - «сольётся сам» — иконки только добавлены или изменены;
  - «нужно одобрение»: скрытия, переименования, новые находки контроля у добавленных и изменённых иконок, исключённые при очистке, откат версии npm, новая лицензия (если это единственная причина «СТОП»);
  - «проблема» — другое «СТОП», в PR только `sources.lock.json`.
  - PR, которые ждут человека, приходят владельцу запросом на ревью.
- Новая лицензия в PR робота:
  - Владелец читает текст в отчёте и явно подтверждает.
  - Только после этого отпечаток вписывается в `sources/{набор}.ts` прямо в ветке `auto/{набор}`, затем `pnpm data {набор}` и коммит в ту же ветку.
  - Ветку с коммитом человека робот больше не трогает; сливает владелец.
- Закрытый без слияния PR — отклонённая версия, робот её больше не предлагает (Reopen — передумать). Открытый PR робот раз в сутки пересобирает от свежего main. Если версия уже в main, закрывает его; при красных проверках ставит «проблема».
- Где смотреть:
  - Actions → «Обновление наборов» → запуск, по строке на набор;
  - PR с меткой «автообновление»;
  - отчёты — ссылки в описании PR: артефакты запуска, хранятся 90 дней. Показать их локально: `gh run download <запуск>`, затем раздать папку через 127.0.0.1.

Обогащение (ADR-0046): `pnpm enrich [id…]` — описания и синонимы ru/en от Claude Haiku 5.5 для базовых иконок без описаний (у вариантов описаний нет: они берут их у базовой, ADR-0002). Команда читает `data/{набор}/`, рисует PNG 256×256 на белом фоне, отправляет пакет через Message Batches API (вдвое дешевле обычных запросов), ждёт результаты и дописывает `ru`, `en`, `promptVersion` в `search.json`. Ключ `ANTHROPIC_API_KEY` — из `.env` (команда его подхватывает) или переменной окружения; без ключа работает только `--dry-run`.
- Флаги: `--limit=N` — постоянная случайная выборка из N базовых иконок, повторный запуск с тем же N ничего не отправляет; `--max-cost=USD` — лимит стоимости прогона, проверяется по оценке до отправки, по умолчанию $5 (весь каталог по оценке ≈ $3, по факту первого прогона ≈ $1,75); `--dry-run` — только посчитать и оценить; `--no-wait` — отправить пакет и выйти, результаты заберёт следующий запуск.
- Состояние пакета — `.cache/enrich/{набор}/batch.json`: прерванный запуск продолжает опрос и ничего не отправляет повторно; файл удаляется после записи `search.json`. Отказы (отказ модели, обрезанный ответ, ошибка пакета, меньше 5 синонимов) в файл не пишутся и отправляются в следующий раз.
- `pnpm data` сеть не использует: описания переходят из `search.json` на диске к базовым иконкам с тем же отпечатком (переименования — по журналу); рисунок изменился — описание пропадает до следующего `pnpm enrich`; файл на диске не по схеме — «СТОП». После `pnpm enrich` повторная сборка даёт те же байты.
- Отчёт — `.cache/reports/enrich/index.html` (иконка, PNG для модели, описания и синонимы, отказы, стоимость и прогноз на каталог) и таблица в терминале. Код выхода 1 — «СТОП»: файлы набора не от этой сборки или оценка выше лимита.
- Промпт, модель, усилие, цены и константы оценки — `packages/pipeline/src/enrich/config.ts` и `prompt.ts`; смена промпта — новая `PROMPT_VERSION`, старые записи остаются (ADR-0020). Код — `packages/pipeline/src/enrich/`.
- Робот обновления описаний не делает: после слияния его PR запускайте `pnpm enrich {набор}` от `main`.

Эмбеддинги (ADR-0047): `pnpm embed [id…]` — векторы смысла для базовых иконок с описаниями (варианты берут вектор базовой) тремя моделями через Polza AI: `openai` (text-embedding-3-large, длина 3072), `gemini` (gemini-embedding-001, 3072) и `qwen` (qwen3-embedding-8b, 4096). Текст иконки один на оба языка: имя, теги, описание и синонимы en, затем ru (`TEXT_VERSION`). Ключ `POLZA_API_KEY` — из `.env` (команда его подхватывает) или переменной окружения; без ключа работает только `--dry-run`.
- Флаги: `--model=openai|gemini|qwen` (можно повторить) — только эти модели; `--max-rub=N` — лимит стоимости прогона в рублях: по оценке до отправки и по факту во время прогона, по умолчанию 200 ₽ (весь каталог тремя моделями по оценке ≈ 102 ₽, по факту первого прогона 75,86 ₽ и около часа); `--dry-run` — только посчитать и оценить.
- Векторы — только локально, в git их нет (решение владельца): `.cache/embeddings/{модель}/{набор}.f32` (float32 little-endian, каждый вектор длины 1) и `{набор}.json` — оглавление: строки «имя + хэш текста», размер и SHA-256 файла `.f32`, накопленный расход. Всего ≈ 640 МБ; на новой машине векторы считаются заново. Векторы Gemini длины 1024 для поискового сервиса — ещё и в закрытом бакете R2 `iconavo-search`, их считает робот индекса (ADR-0049).
- Кэш — по хэшу текста (16 символов SHA-256): повторный запуск без изменений ничего не отправляет, поменялось описание — пересчитывается одна иконка, оглавление не сходится с `.f32` — векторы набора считаются заново.
- Запросы — пачки по 100 текстов, до 4 одновременно; векторы пишутся и по ходу, каждые 10 пачек, так что обрыв теряет только последние пачки. Сбой сети, таймаут 60 с, ответы 408, 425, 429 и 5xx — до 5 попыток (пауза по `Retry-After` или 1, 2, 4, 8 с). 401, 402, 403 — «СТОП» всего прогона (ключ, баланс); другой 4xx и вектор не той длины — «СТОП» модели, остальные модели идут. Посчитанное сохраняется и при остановке.
- Отчёт — `.cache/reports/embed/index.html` (готовность «модель × набор», чем отличаются модели: цена, символов на токен, время, место на диске; этот прогон) и таблица готовности в терминале. Код выхода 1 — «СТОП».
- `pnpm nearest [запрос…] [--model=…]` — ближайшие по смыслу иконки к запросам по каждой модели (косинус векторов), ключ нужен. Без запросов — пары ru/en из `NEAREST_PAIRS` (ни одной из контрольной части эталона, ADR-0021); запросы сравниваются парами — совпадение пятёрок. Время ответа на запрос — медиана без первого запроса, с этого компьютера через Polza. Страница — `.cache/reports/embed/nearest.html`.
- Модели, цены, размер пачки, инструкция запроса для Qwen, пары — `packages/pipeline/src/embed/config.ts`. Код — `packages/pipeline/src/embed/`.
- `pnpm data` векторы не трогает, робот обновления их не считает: после слияния его PR и после `pnpm enrich` запускайте `pnpm embed {набор}` — для прототипа и замера; индекс сервиса досчитает свои векторы сам после «Выкладки».

Прототип поиска (ADR-0048): документ — базовая иконка, оттенки кожи Fluent — одна карточка (если есть основа и все пять оттенков). Текстовая часть — по именам, тегам и синонимам ru/en (без описаний), совпадения как в Meilisearch: точное слово, 1 опечатка от 5 букв и 2 от 9 (в первой букве — за две), последнее слово — ещё и как начало слова; служебные слова не ищутся; лучшее поле, а не сумма. Смысловая часть — косинус с векторами `.cache/embeddings`, укороченный вектор — первые L чисел, снова длины 1. Раздача (ADR-0022, шаг 1 фазы 2): `pnpm cdn build` — из `data/` собирает папку `dist-cdn/` (в корне, не в git) по схеме адресов ADR-0004; сеть не использует, наборы не выбираются — манифест описывает все.
- Раскладка: `manifest.json` в корне (`{"sets": {набор: {version, lastModified}}}`, читаемо); `v/{версия}/{набор}/{имя}.json` и `.svg` на каждую иконку и каждый алиас (скрытые тоже: имена не пропадают); `v/{версия}/{набор}.checksums.json` — SHA-256 каждого файла версии, пути относительно `v/{версия}/`. Файл сумм лежит рядом с папкой набора, а не внутри: имена `info`, `icons`, `search` у наборов есть, а точки в имени быть не может.
- Версия — `version` из `info.json` (ADR-0018); сборка сверяет её с `icons.json`. Папка версии зависит только от версии: `lastModified` в файлах иконок нет, он только в манифесте.
- `{имя}.json` — IconifyJSON для одного имени, компактно (ключи отсортированы, без пробелов): `prefix`, `width`, `height`, при наличии `left`/`top`; `icons` — иконка (у алиаса — иконка в конце цепочки), `aliases` — вся цепочка; записи — как в `icons.json`. `{имя}.svg` — `<svg xmlns width="…em" height="1em" viewBox>`, ширина по пропорции вверх до сотых, как у SVG-адреса Iconify; у алиаса — SVG родителя.
- Без изменений — без записи: если файл сумм версии на диске тот же и в папке столько же файлов, набор пропускается («без изменений»); иначе файлы пишутся во временную папку `v/{версия}/.tmp-…`, подменяют старую, файл сумм пишется последним. Затем манифест (только если изменился) и уборка `v/`: версии не из манифеста, забытые временные папки. Повторный запуск не пишет ни байта. Пять наборов — 88 654 файла, ≈ 68 МБ, около 30 с; повтор — 2 с.
- «СТОП» (манифест не пишется, уборки нет, старые файлы набора не трогаются, код выхода 1): `icons.json` или `info.json` не читается или не по схеме; `prefix` не тот; нет `version` или он не от этого `icons.json` («запустите pnpm data …»); нет `lastModified`; повороты и отражения (`rotate`, `hFlip`, `vFlip`) у иконок или алиасов — статический SVG их пока не умеет.
- Отчёт — `.cache/reports/cdn/index.html` (сводка, манифест, дерево папок каждого набора, примеры файлов с адресами `https://cdn.iconavo.dev/…` и превью, контрольные суммы) и таблица в терминале. Константы — `packages/pipeline/src/cdn/config.ts`, код — `src/cdn/`; схемы `manifestSchema` и `checksumsSchema` — для выгрузки и сверки (шаги 2 и 4).

Заголовки и проверка раздачи (ADR-0023, шаг 3 фазы 2). `Content-Type` и `Cache-Control` хранятся у объектов R2 (выгрузка). Остальное добавляют три правила Cloudflare в зоне `iconavo.dev`; их ставит владелец в панели, дословно — в ADR-0023:
- правило кэша «Раздача: кэш по заголовкам файлов» — всё на `cdn.iconavo.dev`, кроме `/manifest.json`. CDN хранит файл по его `Cache-Control`, ответ без заголовка (404) — нет; браузеру — как у файла (Respect origin). Манифест мимо кэша CDN: проверка и мониторинг видят файл в R2, новая версия видна в браузерах через 5 минут;
- правило заголовков «Раздача: CORS и защита» — на все ответы хоста, включая 404: `Access-Control-Allow-Origin: *`, `X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: cross-origin`. CORS — правилом, а не настройкой бакета: бакет ставит его только на запрос с `Origin`, а копия в кэше CDN одна на всех;
- правило «Раздача: CSP для SVG» — `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`, только у `.svg`.

Сжатие Cloudflare делает сам: Chrome получает `zstd`, остальные — `br` или `gzip`. На обновление страницы ответ — `304` без тела и без заголовка сжатия. `OPTIONS` (предварительные запросы) не поддерживаются: простой GET их не делает. В зоне включён Always Use HTTPS (23 октября 2026): `http://` отвечает 301 на тот же адрес по https; у `cdn2` то же делает Force SSL у Bunny. Браузеры и так открывают `.dev` только по https (HSTS preload), переход нужен программам; заголовок HSTS не ставим.

`pnpm cdn check` проверяет живые адреса обоих хостов по очереди — `cdn.iconavo.dev`, затем `cdn2.iconavo.dev`; ключи не нужны, сборку команда не запускает.
- Адреса: манифест, файл сумм и иконка `lucide:heart` (.json и .svg) текущей версии из манифеста, несуществующее имя `_missing` (ждём 404) и манифест по `http://` (ждём переход на https).
- К файлу — два GET: с `Origin` и «br, gzip», затем без `Origin` и только gzip.
- Что проверяется:
  - код ответа, точные `Content-Type` и `Cache-Control`;
  - состояние кэша CDN (`cf-cache-status` у Cloudflare, `CDN-Cache` у Bunny): версии кэшируются на CDN, манифест — нет, на обоих запросах;
  - `Server` ответов файлов — от CDN этого хоста: `cloudflare` или `BunnyCDN`;
  - переход с `http://` на `https://`: последний адрес — манифест по http, ждём 301 или 308 на тот же адрес по https (колонка «HTTPS»);
  - CORS на обоих запросах;
  - `nosniff` и CORP, у SVG — CSP;
  - `br` и `gzip`;
  - содержимое: схема манифеста и файла сумм, SHA-256 иконки по файлу сумм.
- У 404 — только код, CORS и защита.
- В конце — манифесты хостов побайтно одинаковые; иначе названы наборы с разными версиями.
- Сбои сети и временные ответы — до 3 попыток по 30 с: с компьютера владельца новое соединение открывается до 10 с, и проверка идёт около 20 с на хост.

Пакеты npm (ADR-0026, шаг 5 фазы 2): пакет на набор `@iconavo-ui/icons-{набор}`.   - provenance из `iconavo/iconavo`, `publish.yml`, `refs/heads/main`;

  - на PR — только показ.

  Публикует только «живой» запуск: `main`, не показ, и `main` не ушёл вперёд. Задачи:
  - «Подготовка» — `pnpm packages prepare`, сверка файлов с `npm pack --dry-run`, артефакт `dist-npm`.
  - «Публикация» — окружение GitHub `npm` (публиковать из него можно только из `main`), право только `id-token: write`, без checkout и `pnpm install`. Перед каждым пакетом — реестр ещё раз: версия уже есть — пропуск, под тегом не та версия, от которой считал план, — «план устарел». Затем `npm publish --provenance --ignore-scripts`.
  - «Проверка» — `pnpm packages verify` с планом этого запуска на каждом «живом» запуске; после публикации ждёт до 15 минут.

  1. временный токен — в секрет `NPM_TOKEN` окружения `npm`;
  2. ручной запуск с «первой публикацией»;
  3. секрет удалить, токен отозвать;
  4. владелец включает Trusted Publisher: `iconavo` / `iconavo` / `publish.yml` / `npm`, Allowed actions — npm publish;

  6. «Require two-factor authentication and disallow tokens».

  Дословно — в ADR-0026. Не переименовывай `publish.yml` и окружение `npm`: к ним привязана доверенная публикация.

Edge API (ADR-0024, шаг 7 фазы 2): функция Cloudflare Workers `iconavo-api` на `api.iconavo.dev` работает поверх тех же файлов в R2. Справка для разработчиков — `apps/api/README.md`, на английском.
- **Адреса** (`/collections`, `/collection` и `/last-modified` — в фазе 4):
  - пачка `/{набор}.json?icons=a,b` — IconifyJSON с `not_found`, не больше 100 имён, порядок имён не важен;
  - SVG `/{набор}/{иконка}.svg` с параметрами `color`, `width`, `height`, `rotate`, `flip`, `box`, `download`; без параметров — побайтно файл статики;
  - CSS `/{набор}.css?icons=…` с параметрами `color`, `mode`, `square`, `format`, `download`;
  - поиск `/search?query=…` (ADR-0049): ответ как у Iconify плюс `results` и `semantic` (`full`, `pending`, `text`), кэш дата-центра по версии индекса, 60 поисков в минуту с адреса. Фраза из бакета и гибрид успели за 0,25 с — полная выдача, иначе сразу слова, а полная досчитывается в фоне. Ключи `MEILISEARCH_URL`, `MEILISEARCH_SEARCH_KEY`, `POLZA_API_KEY` — секреты окружения `api`, выкладка вписывает их в `metadata.json`.
- **Параметры строже, чем у Iconify**: неверное значение — 400, JSON с кодом. Например, `rotate=90` — ошибка, нужно `90deg` или `1`.
- **Код:**
  - функция — `apps/api/src/`: `handler.ts` — маршруты и кэш, `config.ts` — лимиты и заголовки;
  - сборка SVG с поворотами — ядро `packages/core`, её же возьмёт рендер фазы 3;
  - сборка, превью и проверка — `packages/pipeline/src/api/`.
- **Данные и кэш:**
  - манифест из R2 держится в памяти минуту и в кэше дата-центра 30 секунд, чтобы холодная копия функции не ждала R2; версия индекса поиска — так же;
  - файлы имён читаются из R2 по 6 запросов сразу;
  - прочитанные файлы имён лежат и в кэше дата-центра (шаг 6 фазы 3): 30 дней, ключ без метки сборки, и новая пачка из знакомых иконок собирается без R2. На бесплатном тарифе — не больше 50 обращений к кэшу за запрос (`match` и `put`), на файлы — 40 (`FILE_CACHE_CALLS`). Сначала проба 6 имён: ни одного в кэше — пачка новая, обращения уходят на запись. Сбой кэша — ответ из R2, а не ошибка;
  - ответы лежат в Cache API дата-центра. Ключ — поколение, сборка, версия набора и проверенные параметры, поэтому новый выпуск или новая сборка дают новые ключи и сбрасывать ничего не нужно (ADR-0023);
  - заголовки `X-Iconavo-Version`, `X-Iconavo-Build`, `X-Cache`; у пачек, SVG и CSS — `Server-Timing`: время в функции и откуда файлы (`files` — из кэша / искали, `r2` — прочитано).
- `pnpm api build` — rolldown собирает `dist-api/worker.js` (в корне, не в git).
  - Метка сборки — 8 знаков SHA-256 бандла.
  - `metadata.json` — тело запроса загрузки: привязка `CDN` → `iconavo-cdn`, `compatibility_date`.
  - Повтор без изменений не пишет ни байта.
- `pnpm api preview [--port=N]` — тот же бандл в Node на 127.0.0.1:4281 с данными `dist-cdn/`, которую команда собирает сама.
  - Страница для глаз: SVG с параметрами рядом со статикой, CSS, пачка, ошибки.
  - `?base=https://api.iconavo.dev` — те же картинки с живого API.
  - Сервер сверяет Host. Свою копию после проверки останавливай.
- `pnpm api check [--expect-build=…]` — живой адрес против статики той же версии; входит в `pnpm cdn check`.
  - Ждёт до 3 минут, пока API отдаст версию из манифеста R2.
  - Пачка в двух порядках: второй ответ — HIT и побайтно тот же.

Ядро пакета (ADR-0029, ADR-0030, ADR-0031, шаги 2–4 фазы 3): `packages/core` — `@iconavo-ui/core`, на нём стоят тег (шаг 5) и React (шаг 7).
- Два входа:
  - `@iconavo-ui/core` — ровно функции README `configure`, `addIcons`, `setLoader`, `loadIcons` и типы `IconavoIconSet`, `IconavoIcon`, `IconavoAlias`;
  - `@iconavo-ui/core/internal` — для адаптеров и edge API: проверка имён, разбор `rotate`/`flip`/размеров, `iconData`, `iconToSvg`, `svgToString`, рендер `renderIcon`, `setStrokeWidth`, `replaceIds`, `getIcon`, `subscribeIcon`, `loadIcon`, `store` (настройки `placeholder` и `dev`), `warn` (одно предупреждение на текст), пороги `ROTATE`, `ROTATE_CDN`, `TIMEOUT`, `RETRIES` и хосты по умолчанию `DEFAULT_API`, `DEFAULT_CDN`.
  - `"sideEffects": false`: в функцию edge API попадает только сборка SVG, без хранилища, загрузки и рендера — это проверяет тест сборки. Помощники тестов ядра — `src/fake.testing.ts`.
- Хранилище (`src/store.ts`): состояние каждого имени `набор:иконка` — данные, «загружается», «нет» или «ошибка». В браузере все копии ядра на странице делят его под `Symbol.for("iconavo.core.1")`: иконки, слушатели, настройки, загрузчики, показанные предупреждения, счётчик отрисовок `ids`; поля только добавляются, иначе — новая версия в ключе. На сервере у модуля своё.
- Загрузка (`src/load.ts`): очередь до конца задачи (`setTimeout`), пачка на набор, куски — адрес до 500 символов и до 100 имён, по самому длинному хосту `api`.
  - Попытка — как `sendQuery` у Iconify: пачкой через каждый хост `api`, затем по одной иконке со статики каждого хоста `cdn`; у набора с `setLoader` — только загрузчик. Версию набора статика берёт из манифеста своего хоста: один запрос за жизнь страницы, со своим таймером.
  - Источник молчит 750 мс (`ROTATE`) — следующий спрашивается параллельно, отказал — сразу. С последнего хоста `api` на статику — через 1,5 с (`ROTATE_CDN`, шаг 6, ADR-0030): статика просит по запросу на иконку, а новая пачка edge API собирается дольше 750 мс. Ответ есть у всех имён — остальные запросы отменяются. Попытка — до 5 с (`TIMEOUT`).
  - Неудавшаяся попытка повторяется через 1, 2 и 4 с, пока у имени есть слушатель (ожидание `loadIcons` не в счёт: у него один проход), потом — «ошибка». Хостов нет — «ошибка» сразу. «Нет» не запрашивается до конца жизни страницы, «ошибка» — при следующем показе.
  - Предупреждения в консоли — одно на текст за жизнь страницы: `not found`, `invalid icon name`, `failed to load` с самой ошибкой (ADR-0031).
  - Отмена — `AbortController` с `setTimeout`, не `AbortSignal.timeout`. Тесты ядра идут на поддельном времени (`fakeTime`): таймер повтора, переживший тест, иначе сходил бы на настоящий хост из CI.
- Рендер (шаг 4, ADR-0031): `renderIcon(icon, options)` в `src/render.ts` — атрибуты `<svg>` и рисунок строками, без DOM; на нём стоят тег и React.
  - Повороты и отражения в данных (алиасы чужого IconifyJSON) — как у Iconify: повороты по цепочке складываются, отражения гасятся, `iconData` сразу применяет их к рисунку и холсту (первый проход `iconToSVG` у Iconify). Форма `IconData` прежняя; статика по-прежнему останавливает наборы с поворотами в данных.
  - Уникальные ID (`src/ids.ts`, `replaceIds`) — `iconavo{n}_{k}` при каждой отрисовке: `n` — счётчик `ids` в общем хранилище, иконка без ID его не тратит. Переписываются `id`, `url(#…)`, `href="#…"`, `begin="….end"`; цвет `#abc` и классы — нет. В React вместо счётчика — `idPrefix` из `useId` (шаг 7).
  - Цвет — атрибутом `color` у `<svg>`, не стилем. Толщина линии (`setStrokeWidth`) — значения `stroke-width`, только если в рисунке есть `currentColor`.
  - Без подписи — `aria-hidden="true"`, с подписью — `role="img"` и `aria-label`, без `<title>`; подпись из пробелов — декоративная.
  - `svgToString` пишет атрибуты по порядку и экранирует `& " <`; без настроек вывод побайтно прежний.
- Размер: ядро вместе с `internal` — 4,50 КБ в gzip из 5 (`pnpm size`). Заглушки, Trusted Types и рамку режима разработки — в бюджеты тега и React.

Тег (ADR-0032, ADR-0031, шаг 5 фазы 3): `packages/icon` — `@iconavo-ui/icon`, тег `<iconavo-icon>` на ядре.

- Trusted Types — `src/trusted.ts`: политика `iconavo` при первой нарисованной иконке, под ключом `Symbol.for("iconavo.trusted-types")` без версии — одна на страницу; запрет — пустое место и одно предупреждение.
- Заглушки — классы резерва `skeleton` и `spinner` (у `none` стилей нет): показ через 150 мс — CSS-анимация `h .15s step-end`, без движения — без мерцания и вращения. Рамка режима разработки — класс `missing`.

- Размер: тег сверх ядра — 1,98 КБ из 2 (впритык), скрипт без сборщика — 5,89 КБ из 7 (`pnpm size`; CI собирает скрипт перед замером).

React (ADR-0033, ADR-0031, шаг 7 фазы 3): `packages/react` — `@iconavo-ui/react`, компонент `Icon` и обёртка `IconavoProvider` на ядре.
- Вход `src/index.ts` — без `"use client"`: четыре функции и типы ядра, `Icon`, `IconavoProvider`; так `loadIcons` вызывается в серверном компоненте. `"use client"` — первой строкой у `icon.ts` и `provider.ts`; tsc его сохраняет (тест на `dist/`). Без JSX — `createElement`; `forwardRef` для React 18; `"sideEffects": false`; peer `react ^18 || ^19`, необязательный — `@types/react`.
- Главное правило: на сервере и при гидратации разметка зависит только от пропсов, данных обёртки и чистых функций ядра (`src/state.ts`).
  - `getServerSnapshot` — иконка обёртки; её `not_found` и неверное имя — «нет»; остальное — заглушка.
  - `getSnapshot` после гидратации — иконка ядра, иначе обёртки, иначе «нет» обёртки, иначе состояние ядра.
  - Хранилище, `configure`, режим разработки и `CSS.supports` — только в листе стилей и в эффектах.
- Запрос — `loadIcon` в эффекте после подписки, при монтировании и смене имени, если иконки нет в обёртке; «ошибка» — снова при следующем монтировании; `not_found` обёртки браузер переспрашивает сам.
- Обёртка (`src/provider.ts`) ищет иконку лениво через `iconData` и кэширует по имени; вложенная ищет сначала у себя. В ядро ничего не пишет — поэтому тег иконок обёртки не видит.
- Рисует `renderIcon` ядра: ID — от `useId`, цвет — атрибут `color`, подпись — `role="img"` и `aria-label`, и у заглушки тоже. Рисунок — `dangerouslySetInnerHTML` объектом TrustedHTML политики `iconavo` тега, один объект на строку рисунка (`useMemo`): React сравнивает `__html` по ссылке. Политику не разрешили, а Trusted Types требуются — пустое место и одно предупреждение (`src/trusted.ts`).
- Резерв — как у тега: заданные размеры, одна сторона — квадрат, без размеров и `auto` — `1em`. Классы:
  - `iconavo-loading` — заглушка по умолчанию, вид — по `configure({ placeholder })`;
  - `iconavo-skeleton` и `iconavo-spinner` — из пропа, у `none` класса нет;
  - `iconavo-missing` — «нет» и «ошибка», рамка только в режиме разработки;
  - `iconavo-inline`.

  Атрибута `style` компонент не ставит.
- Стили (`src/style.ts`) — правила тега с классами страницы. Лист — `document.adoptedStyleSheets` из `useInsertionEffect`, один на страницу (`Symbol.for("iconavo.react.css.1")`); `display` не трогается. До загрузки скриптов стилей нет (решение владельца 28 октября 2026).
- Режим разработки — `configure({ dev })`, иначе `process.env.NODE_ENV !== "production"`. Неверные пропсы пропускаются; предупреждения — тексты тега с именами пропсов React — печатает эффект браузера.
- Тесты — Vitest в Node, серверная разметка — `react-dom/server` (`src/*.test.ts`); эффекты и гидратацию проверяет `pnpm example --check`. Что сборка `import { loadIcons }` обходится без компонентов, проверяет тест конвейера `src/icon/build.test.ts`.
- Размер: React сверх ядра — 2,19 КБ из 2,5 (бюджет поднят решением владельца 28 октября 2026, ADR-0034).

Пример на Next.js (ADR-0033, ADR-0035, шаг 7 фазы 3): `examples/next` — пакет рабочего пространства `@iconavo-ui/example-next`.
- Next.js 16.4 (Turbopack), React 19.3; типы проверяет `tsc` TypeScript 7 репозитория (Next.js 16.4 вызывает его сам).
- Тексты — по-английски: из него шаг 10 сделает пример для StackBlitz.
- Страницы:
  - `app/layout.tsx` — `await loadIcons(...)` → `IconavoProvider`;
  - `app/page.tsx` — разделы «From the server», «Loaded in the browser», inline и клиентский компонент `app/client.tsx` (переключатель, `addIcons`, тег, иконки, которых нет);
  - `app/more/page.tsx` — вложенная обёртка для перехода по ссылке.

  Имена иконок — `app/icons.json`, его же читает проверка.
- `app/iconavo.ts` — `configure` из `NEXT_PUBLIC_ICONAVO_API` и `…_CDN`, если они заданы (задаёт только проверка). Его импортируют и layout, и клиентский компонент: у серверных и клиентских компонентов Next.js своё ядро.
- `next.config.ts` — в продакшене строгая CSP для стилей (`style-src 'self'`) и хосты иконок в `connect-src`; скрипты Next.js — `'self' 'unsafe-inline'`. `agentRules: false`: иначе `next dev`, заметив ИИ-ассистента, пишет в пример `AGENTS.md`.
- `.next/` и `next-env.d.ts` в git не идут. Next.js сам дописал в пример `@types/node` (та же версия, что у конвейера), а в `tsconfig.json` — `allowJs` и `esModuleInterop`.
- `pnpm example` — `next dev` на 127.0.0.1:4283 с живыми хостами; `--prod` — `next build` и `next start`; `--webpack` — сборщик webpack. Ctrl+C останавливает Next.js со всеми дочерними процессами (на Windows — `taskkill /T /F`). Код — `packages/pipeline/src/example/`, запуск и остановка — `next.ts`.
- `pnpm example --check` — `buildCdn`, превью API, затем для разработки и продакшена — Next.js на свободном порту и Chrome, Firefox, WebKit по очереди (`check.ts`, `check-report.ts`). Что проверяется:
  - серверный HTML без JavaScript;
  - «без мигания» — сторож DOM и одинаковые снимки раздела до и после гидратации;
  - консоль (только два ожидаемых предупреждения) и CSP продакшена;
  - заглушки: сразу после гидратации скрыты, через 0,25 с видны и анимированы; снимок раздела в этот момент;
  - запросы к хостам;
  - клиентский компонент и переход на /more;
  - подпись (Chrome), Trusted Types, рамка, тег;
  - контрольный запуск: заголовок портится до гидратации, засчитывается только сообщение о гидратации.

  Сведения для ADR: какой вход тега выбрал Next.js и работает ли `var()` в атрибуте `color`. Снимки — через `shot()` песочницы: стиль Playwright для снимка строгая CSP WebKit отклоняет. Отчёт — `.cache/reports/example/check.html`; в CI не идёт (шаг 9). На компьютере владельца — несколько минут.
- Результат 28 октября 2026: все проверки «да» в трёх браузерах, в обоих режимах, с Turbopack и (в Chrome) с webpack. Оба сборщика выбирают `development.js` тега в `next dev`; `var()` в атрибуте `color` работает везде; Trusted Types — во всех трёх браузерах.

Песочница пакета: `pnpm sandbox [--port=N]` — страницы на `http://127.0.0.1:4282`: загрузка и сеть (`/`, шаги 2–3), рендер (`/render`, шаг 4), тег (`/tag`) и 5000 иконок (`/many`, шаг 5). Перед запуском собирает скрипт тега. Код — `packages/pipeline/src/sandbox/`.
- Иконки грузит само ядро из `packages/core/dist`: import map страницы, скрипт `client.ts` собирается `tsc` вместе с конвейером.
- Журнал — обёртка над `fetch`: «ушло в сеть» совпадает с числом строк в DevTools → Network (фильтр Fetch/XHR). Колонки «Хост», «Что» (пачка, манифест, иконка), «Итог».
- Условия сети (шаг 3) — имитация в той же обёртке, ядро о ней не знает.
  - Сценарии: «Всё работает», «Основной хост недоступен», «Медленная сеть», «Ничего не отвечает».
  - Состояние каждого хоста: работает, недоступен (ошибка сети сразу), молчит (до отмены ядром), медленный (+2 с, `SLOW_MS`).
  - Флажок «иконки, которых нет» (`MISSING_NAMES`).
  - Что обёртка не пропустила, в сеть не уходит.
- Хост API — `?api=`: живой `https://api.iconavo.dev` (по умолчанию) или превью `http://127.0.0.1:порт` от `pnpm api preview`; другие не принимаются. В режиме превью и статика своя — `/_static/` превью (с CORS).
- Страница «Рендер» (`/render`, шаг 4) — сетка вариантов: размер, поворот, отражение, поворот в данных, цвет, толщина линии, одна иконка дважды, зачем уникальные ID, подпись для скринридеров с инструкцией для Экранного диктора.
  - Сетка и свой набор `sandbox` (широкая стрелка 48×24, луна с маской, две иконки с одним `id="a"`, алиасы с поворотами в данных) — в `render-page.ts`, скрипт — `render-client.ts`: настройки клеток строками в data-атрибутах, разбор — функциями ядра, рисует `renderIcon`.
  - Имена реальных иконок сетки проверяет тест: все есть в `data/`. Главная страница тоже рисует через `renderIcon`.
- Страница «Тег» (`/tag`, шаг 5; `tag-page.ts`, `tag-client.ts`):
  - две копии пакета: скрипт страницы через ядро ставит хосты режима и свой загрузчик `slow` (задержка 1 или 3 с), затем подключает `/icon/iconavo-icon.js` — он регистрирует тег, — и последней копию «как у сборщика» (import map → вывод tsc), которая регистрацию пропускает;
  - разделы: две копии и политика Trusted Types, заглушки на утверждение владельца, иконки нет (рамка, кнопки режима разработки), подпись (две кнопки из README, Экранный диктор), `inline`, цвет и размер от текста, атрибуты и неверные значения.
- Страница «5000 иконок» (`/many`; `many-page.ts`, `many-client.ts`): по 1000 первых видимых имён каждого набора (`MANY_PER_SET`) тегами прямо в HTML, рядом — имя. Подключение — как в README без сборщика, `configure` — из того же адреса через import map. Счётчики раз в секунду: нарисовано, пачки к API и запросы по одной к статике (по ним видно переход на статику, шаг 6), кадры и долгие кадры; кнопки цвета и размера текста. `?slow-script=1` — скрипт тега на 2 с позже: сервер задерживает `/icon/…js?delay=N` (до 10 с).
- Обе страницы — со строгой CSP: свои скрипты и import map по хэшу, стиль только по хэшу, `require-trusted-types-for 'script'; trusted-types iconavo`, пустая иконка вкладки. Атрибутов `style` в разметке и `innerHTML` в скриптах страниц нет; `<select>` тоже нет — у WebKit на Windows он нарушает политику.
- `--browser=webkit|firefox|chrome` — окно Playwright (`browser.ts`) со страницей `/many` для ручной проверки.
- `--check` — `check.ts` и `check-report.ts`. Что делает:
  - собирает раздачу и поднимает превью API и песочницу на свободных портах;
  - по очереди проверяет Chrome (установленный, `channel: "chrome"`), Firefox и WebKit: две копии, стили и Trusted Types при строгой CSP, ошибки и нарушения политики, предупреждения, заглушки (видимость через 150 мс, анимации, без движения), рамку, перекраску, подпись (по дереву доступности — только Chrome), место до загрузки (ответы API задержаны на 800 мс) и ленивую загрузку;
  - нарушения политики во время снимков не в счёт: стиль для снимка вставляет сам Playwright;
  - пишет отчёт со снимками `.cache/reports/sandbox/check.html`, код 1 — есть проблемы. В CI не идёт (шаг 9).

  Браузеры ставит один раз `pnpm exec playwright install webkit firefox` (около 190 МБ, `%LOCALAPPDATA%\ms-playwright`).
- Сервер слушает только 127.0.0.1 и сверяет Host. CSP пускает только свои скрипты и import map по хэшу, сеть — только хосты режима. Свою копию после проверки останавливай.

Проверка файла набора по схеме: `pnpm validate <файл>` (вид по имени `icons|info|metadata|search|changelog.json` или `--kind`). Код выхода 0 — ошибок нет, 1 — есть ошибки, 2 — неверный вызов. Примеры: `packages/schema/examples/{valid,broken}/`.

`size-limit` читает собранные файлы из `dist/`, поэтому перед `pnpm size` запускай `pnpm typecheck` и `pnpm icon build` (скрипт тега меряется готовым файлом).

## Ветка main

Защита `main` включена 20 октября 2026, когда репозиторий стал открытым:
- в `main` — только через pull request; одобрение другим человеком не требуется;
- слить можно только при зелёных проверках «CI» (задача `check`) и «Данные» (задача `data`); «Данные» на PR запускается всегда — обязательная проверка, которая не запустилась, заблокировала бы PR;
- прямые коммиты, перезапись (force push) и удаление `main` запрещены, в том числе администратору;
- ветку перед слиянием догонять до свежего `main` не обязательно;
- безопасные PR робота обновления сливаются сами (автослияние, ADR-0019), ветки после слияния удаляются автоматически.

## Ключи

Имена ключей — в `.env.example`, значения — в локальном `.env` (в git не попадает) и в секретах GitHub Actions. `ANTHROPIC_API_KEY` — обогащение иконок (`pnpm enrich` читает `.env` сам через `--env-file-if-exists`). Вместо ключей OpenAI и Google для эмбеддингов (шаг 12 фазы 0, ADR-0007) временно используется агрегатор Polza AI: `POLZA_API_KEY` (`pnpm embed` и `pnpm nearest` читают `.env` сами). `UPDATE_APP_CLIENT_ID` и `UPDATE_APP_PRIVATE_KEY` — приложение GitHub робота обновления (ADR-0019), только в секретах GitHub Actions. `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID` и `R2_SECRET_ACCESS_KEY` — бакет R2 раздачи (`pnpm cdn upload` и `verify` читают `.env` сами, ADR-0022): токен «Object Read & Write» только на бакет `iconavo-cdn`, в CI — секреты Actions. `BUNNY_STORAGE_PASSWORD` — пароль хранилища Bunny второго хоста (ADR-0025): Password, не Read-only; в CI — секрет Actions, локально нужен только для показа и сверки. У npm локального ключа нет: публикует только CI доверенной публикацией (ADR-0026). `CLOUDFLARE_API_TOKEN` — ключ выкладки функции edge API (ADR-0024): секрет окружения GitHub `api`, право Account · Workers Scripts · Edit; локально не нужен, выкладывает только CI. По силе он равен ключу записи R2: функция привязана к бакету раздачи (ADR-0028). `NPM_TOKEN` — временный секрет окружения GitHub `npm` только на время первой публикации нового пакета; после неё секрет удаляется, токен отзывается. Поисковый сервис (ADR-0049): `MEILISEARCH_URL` и `MEILISEARCH_READ_KEY` (Default Read-Only Admin API Key) — локально для показа, замера и страницы поиска; `MEILISEARCH_ADMIN_KEY` — только секрет окружения GitHub `search`, у робота индекса; `SEARCH_R2_ACCESS_KEY_ID` и `SEARCH_R2_SECRET_ACCESS_KEY` — токен «Object Read & Write» только на закрытый бакет `iconavo-search` (в CI — окружение `search`). Адрес Meilisearch в CI — тоже секрет: логи открыты. Значения ключей читай только из переменных окружения; не открывай `.env` и не выводи его содержимое.
