# Iconavo — платформа иконок

Я продуктовый дизайнер, не разработчик. Объясняй простыми словами.

## Состояние проекта

Монорепозиторий создан (фаза 0, шаг 9): pnpm workspaces, TypeScript, Biome, Vitest, size-limit, CI в `.github/workflows/ci.yml` и `data.yml`. Код пока ранний: заготовка `packages/core` (проверка имени иконки по ADR-0001), `packages/schema` (схемы набора, фаза 1 шаг 1) и `packages/pipeline` (реестр источников и загрузчик, шаг 2; конфиги пяти наборов в `sources/`; санитайзер SVG, шаг 3; нормализация и галерея, шаг 4; SVGO и сборка `data/`, шаг 5; контроль качества, шаг 6; метаданные и лицензии, шаг 7). В `data/{набор}/` — собранные `icons.json`, `info.json`, `metadata.json`, `search.json` и `LICENSE` пяти наборов, `apps/` пуста. Остальной конвейер — в фазе 1.

План и решения — в `docs/`, ADR — в `docs/adr/`. Начинай с `docs/README.md`: там оглавление, а `docs/roadmap.md` даёт фазы и сроки (запуск 1 июня 2027). Фазы 0–3 подробно расписаны в `docs/phase-0.md` … `docs/phase-3.md` вместе с готовыми промптами. Если нужного решения в ADR нет — спроси, не придумывай.

## Что строим

Аналог Iconify: каталог иконок из открытых наборов, который отличается смысловым многоязычным поиском и MCP-сервером для ИИ-ассистентов. Принцип: где Iconify нашёл проверенное решение, берём такое же устройство (формат имён, IconifyJSON, адреса API).

## Архитектура (по ADR)

Конвейер → статика и edge → пакет и сайт:

1. **Конвейер данных** (`packages/pipeline`, фаза 1, ADR-0012…0021): загрузка наборов только из npm и git → очистка SVG своим санитайзером по белому списку → нормализация (сетка 24 или 32, атрибуты корня во внешний `<g>`, цвета в `currentColor`, префиксы ID) → SVGO с закреплённой версией (вывод побайтно детерминирован) → контроль качества рендером через resvg → метаданные и лицензии → отпечатки SHA-256 и журнал изменений → обогащение ИИ (описания, синонимы) и эмбеддинги. Результат кладётся в `data/`, реестр источников — в `sources/`.
2. **Доставка** (фаза 2, ADR-0006, 0022…0025): неизменяемая статика на Cloudflare R2 (`cdn.домен/v/{версия}/{набор}/{иконка}.json|.svg`, манифест `manifest.json` с коротким кэшем) плюс edge API на Workers (`api.домен`: пачки, SVG с параметрами, CSS, поиск). Второй хост статики — Bunny CDN. Выкладка: сначала файлы, потом сверка, манифест последним.
3. **Пакеты** (фаза 3, ADR-0029…0036): общее ядро плюс тонкие адаптеры — веб-компонент `<iconavo-icon>` (Shadow DOM) и React 18/19. Только ESM, бюджеты размера 5, 2 и 2 КБ. Ядро берёт пачки через edge, а при его сбое — поштучно со статики.
4. **Поиск** (ADR-0009, 0021, 0027): гибридный (текст + векторы), Meilisearch Cloud, документ на базовую иконку. Метрика качества — Hit@5 на эталоне из 200 запросов.
5. **Сайт** (Next.js на Vercel) и **MCP-сервер** (Workers, `mcp.домен`, инструменты в т. ч. `pick_icon`).

Ключевые соглашения из ADR, которые легко нарушить:
- Имя иконки — `набор:иконка`, части по `^[a-z0-9]+(-[a-z0-9]+)*$`, префиксы как у Iconify (`lucide`, `tabler`, `material-symbols`, `ph`, `fluent-emoji-flat`). Имя без двоеточия не принимается.
- Иконки никогда не удаляются: пропавшие помечаются `hidden`, переименованные становятся алиасами.
- Файлы данных совместимы с IconifyJSON; данные поиска лежат отдельно в `search.json`.
- Пакеты — semver, до запуска 0.x, публикация в npm только из CI с provenance, тег `next` до запуска.
- Первые наборы: Lucide, Tabler, Material Symbols, Phosphor, Fluent Emoji Flat — только с разрешительными лицензиями.

## Формат набора (ADR-0003)

Схемы — в `packages/schema` (zod 4, сообщения об ошибках по-русски). Набор состоит из четырёх файлов: `icons.json` (формат IconifyJSON, **единственный файл, который идёт в рантайм**), `info.json` (название, автор, лицензия полностью, сетка, признак цветного набора), `metadata.json` (категории и карта суффиксов вариантов) и `search.json` (теги, описания и синонимы ru/en, отпечатки; поля сверх IconifyJSON живут только здесь). В `icons.json` лишние поля допустимы (совместимость), в наших файлах запрещены. Правило имён одно на всё: `^[a-z0-9]+(-[a-z0-9]+)*$`. Ядро `packages/core` не должно зависеть от zod.

## Стек (ADR-0007)

Монорепозиторий на TypeScript с pnpm workspaces; Biome (линтер и форматирование), Vitest, Playwright, size-limit; Next.js; Cloudflare R2/Workers; Meilisearch; эмбеддинги через Polza AI — `openai/text-embedding-3-large`, `google/gemini-embedding-001` или `qwen/qwen3-embedding-8b` (вместо BGE-M3; выбор по замеру в фазе 1). Перед выбором моделей и цен перепроверяй актуальные версии.

## Имена и ресурсы

Бренд Iconavo, организация GitHub `iconavo`, веб-компонент `<iconavo-icon>`. В документации scope npm — `@iconavo-ui`; на npm существует и название `iconavo` (организация/пользователь без публичных пакетов). Адреса `api.домен`, `cdn.домен`, `mcp.домен` — заглушки: подставляется домен проекта.

## Правила работы

- Если меняешь больше двух файлов — сначала план.
- После изменений запускай тесты и показывай результат.
- Всё, что нужно оценить глазами, показывай HTML-страницей.
- Новые зависимости — только после моего согласия.
- Никогда не коммить токены, пароли и файлы `.env`.
- Один шаг — один коммит с понятным описанием на русском.
- Репозиторий закрытый до публичной беты пакетов (ADR-0036).

## Команды

```
pnpm install                 # зависимости
pnpm check                   # всё сразу, как в CI: lint → typecheck → test → size
pnpm lint                    # Biome (линтер и форматирование); pnpm format — исправить форматирование
pnpm typecheck               # tsc -b; заодно собирает dist/ для size-limit
pnpm test                    # Vitest, все тесты
pnpm vitest run packages/core/src/index.test.ts -t "часть названия теста"   # один тест
pnpm size                    # size-limit: бюджеты размера пакетов (ADR-0034); нужен dist/ после typecheck
```

Источники наборов (ADR-0012): конфиг на набор — `sources/{id}.ts` (экспорт по умолчанию, `satisfies SourceConfigInput`, имя файла = префикс набора; папки с SVG и правила имён вариантов — список `svgFolders`; сетка набора `grid` и, если холст источника другой, `sourceGrid` — ADR-0014; автор `author`, лицензия `license`, формат метаданных автора `metadata`, карта вариантов `suffixes`, витрина `samples` — ADR-0017), версии закреплены в `sources.lock.json`, скачанное лежит в `.cache/sources/{id}/{версия}/` (не в git). `pnpm sources fetch [id…]` скачивает по lock (при первом запуске набора закрепляет последнюю версию), повторный запуск без изменений не использует сеть, а при смене правил скачивания (папки, файлы метаданных) набор скачивается заново; git-источники приходят без перевода строк под систему; `pnpm sources pin <id> [версия|коммит]` меняет версию — `sources.lock.json` правь только этой командой. Для git в lock нужен полный хэш коммита, не ветка. Код — `packages/pipeline/src/sources/`.

Эталон поиска (`docs/eval/queries.csv`, описание в `docs/eval/README.md`) генерируется скриптом `node --env-file=.env tools/eval/generate-queries.mjs` через Polza AI; повторный запуск меняет запросы и разбиение work/holdout — не запускай без просьбы.

Очистка SVG (ADR-0013): `pnpm sanitize [id…]` прогоняет скачанные наборы (из `.cache/sources`, сеть не использует) через санитайзер по белому списку, печатает сводку и пишет HTML-отчёт `.cache/reports/sanitize.html`. Код выхода 1 — набор остановлен: исключено больше 1% иконок, найдено опасное (признак подмены источника), потеряны фигуры или атрибуты рисунка. Код — `packages/pipeline/src/sanitize/` (разбор XML — `src/svg/xml.ts`, без зависимостей); «вредные» SVG для тестов — `packages/pipeline/fixtures/harmful-svg/` (исключены из Biome). Санитайзер должен идти раньше SVGO: парсер SVGO читает сущности из DOCTYPE.

Нормализация (ADR-0014): `pnpm normalize [id…]` очищает и нормализует скачанные наборы (сеть не использует, в `data/` ничего не пишет): холст переводится на сетку набора (масштаб — атрибут `transform` на внешнем `<g>`, в координаты его впечатывает SVGO при сборке, `pnpm data`), атрибуты корня уходят во внешний `<g>`, в монохромных наборах цвета → `currentColor` (маски и clipPath не трогаются, фигурам без заливки цвет задаётся явно), ID → `{набор}--{иконка}-{n}`. Печатает сводку и пишет галерею `.cache/reports/normalize/index.html`: «было/стало» на светлом и тёмном фоне и в красном, 48/24/16 px, по 500 иконок на странице, список «Сначала посмотрите»; папка пересоздаётся при каждом запуске. Код выхода 1 — набор остановлен: исключено больше 1%, найдено опасное, больше 1% иконок вне сетки источника, результат не прошёл независимую проверку. Код — `packages/pipeline/src/normalize/`; общие помощники HTML-отчётов — `src/report/html.ts`, ссылки между элементами — `src/svg/refs.ts`.

Сборка (ADR-0015): `pnpm data [id…]` собирает скачанные наборы (сеть не использует): очистка и нормализация как в шаге 4 → SVGO 4.1.0 со своим явным списком плагинов (`packages/pipeline/src/optimize/config.ts`: точность 3 знака, только для сеток 24 и 32; `cleanupIds` выключен; масштаб впечатывается в координаты) → алиасы одинаковых вариантов (поле `variantAliases` в конфиге набора, ADR-0002) → контроль качества (шаг 6, ниже) → метаданные и лицензия (шаг 7, ниже) → `data/{id}/icons.json` (IconifyJSON; ключи по кодам символов, отступ 2 пробела, LF; без `lastModified` до шага 8) и остальные файлы набора. Печатает размеры до и после и пишет галерею `.cache/reports/data/index.html`: «было / до SVGO / SVGO», значки алиасов, «Сначала посмотрите». `data/` хранится в git и руками не правится: повторная сборка без изменений источников даёт побайтно те же файлы, это проверяет `.github/workflows/data.yml` (пересобирает на Linux и падает, если `git status` не пуст). Код выхода 1 — набор остановлен: всё из шага 4, плюс SVGO или проверка после него не прошли, одно имя у нескольких файлов, неподдерживаемая сетка, файл не прошёл схему, «СТОП» контроля качества; файл остановленного набора не перезаписывается. Код — `packages/pipeline/src/build/` и `src/optimize/`. Любое изменение версии SVGO или его конфига — полная пересборка `data/`; попиксельное сравнение с прошлой версией делает контроль качества.

Контроль качества (ADR-0016): идёт внутри `pnpm data`, отдельной команды нет. Каждая иконка рисуется через resvg (`@resvg/resvg-wasm`: сетка = 64 px, прозрачный фон, запас 16 px вокруг холста) и сравнивается через pixelmatch.
- «СТОП» (файл набора не записывается):
  - resvg не нарисовал иконку;
  - иконка пустая: закрашено меньше 0,05% холста;
  - источник тот же, а изменилось или пропало больше 2% имён по сравнению с прошлой версией. Прошлая версия — последний коммит, где менялся `data/{набор}/icons.json`, вместе с `sources.lock.json` того же коммита. Читается через `git show`, git нужен.
- Только отчёт:
  - почти пустые — меньше 0,5% холста;
  - обрезанные — вылет за холст больше 2%;
  - отличия от исходника автора больше 1% пикселей. В монохромных наборах сравнивается только тёмная краска.
- `pnpm data --accept-changes` снимает только правило 2% — для задуманных изменений, проверенных в отчёте. Затем закоммитьте `data/`, иначе следующая сборка снова остановится.
- Отчёт — `.cache/reports/data/qc.html` и раздел в `index.html`. Пороги — `packages/pipeline/src/qc/config.ts`, код — `src/qc/`.

Метаданные и лицензии (ADR-0017): тоже внутри `pnpm data`. Рядом с `icons.json` пишутся:
- `info.json` — автор, лицензия с полным текстом, витрина из шести иконок;
- `metadata.json` — категории автора и карта вариантов `suffixes`;
- `search.json` — отпечаток (ADR-0018) и теги каждой иконки, без алиасов;
- `LICENSE`, а `NOTICE` — только если он есть у автора.

Теги и категории берутся из файлов автора по формату `metadata` в конфиге: `lucide`, `tabler`, `phosphor` (модуль `dist/index.mjs` читается как текст, без запуска), `fluent-emoji`. Где их нет (Material Symbols) — теги из частей имени. Категории — как у автора, строчными только теги. Отчёт — `.cache/reports/data/metadata.html`, таблица — в конце вывода `pnpm data`.
- Лицензию подтверждает только владелец, прочитав текст в `metadata.html`. После его явного «подтверждаю» отпечаток из сообщения «СТОП» вписывается в `license.confirmed` конфига набора. Сам не вписывай.
- «СТОП» (файлы набора не записываются):
  - лицензия не подтверждена или изменилась у автора;
  - лицензия в `package.json` пакета npm не совпадает с конфигом;
  - метаданные автора не читаются;
  - больше 1% иконок без тегов автора;
  - в `samples` неизвестное имя.
- Разрешены только лицензии MIT, ISC и Apache-2.0: другая — ошибка конфига.
- Код — `packages/pipeline/src/metadata/`.

Проверка файла набора по схеме: `pnpm validate <файл>` (вид по имени `icons|info|metadata|search.json` или `--kind`). Код выхода 0 — ошибок нет, 1 — есть ошибки, 2 — неверный вызов. Примеры: `packages/schema/examples/{valid,broken}/`.

`size-limit` читает собранные файлы из `dist/`, поэтому перед `pnpm size` запускай `pnpm typecheck`.

## Ветка main

Защита `main` не включена: на тарифе GitHub Free она недоступна для закрытых репозиториев. Поэтому работаем только через ветки и pull request, а в `main` не коммитим напрямую. Включить защиту (слияние только через PR с зелёными проверками) нужно, когда организация перейдёт на Team или репозиторий станет публичным.

## Ключи

Имена ключей — в `.env.example`, значения — в локальном `.env` (в git не попадает) и в секретах GitHub Actions. `ANTHROPIC_API_KEY` — обогащение иконок. Вместо ключей OpenAI и Google для эмбеддингов (шаг 12 фазы 0, ADR-0007) временно используется агрегатор Polza AI: `POLZA_API_KEY`. Значения ключей читай только из переменных окружения; не открывай `.env` и не выводи его содержимое.
